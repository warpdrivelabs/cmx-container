① 全景：端到端装载链路

一次装载把「单据定义 + 查询指令」变成前端可直接渲染的嵌套主从树。全链路：

前端 loadDocData(host, def) │ def = { domain, application, module, file, filter?, limit?, depth?, query?, dbId?, binary? } ▼ GET|POST /api/doc/data/<驱动>-<内存模式>-<传输> # 6 个组合端点，见 §5 ▼ handler: resolve_doc_meta（读定义 + base 字段集，带缓存）→ DocMetaView ▼ DocQuery::from_json(body) | simple_doc_query(GET query) ▼ dq.validate(meta) # 列名白名单，防注入 ▼ DocLoader::load(mm, db_id, meta, dq) │ 1. 根层查询 build_layer_select → DataSet，收集 rootIds │ 2. 逐层下钻：子层 childKey = ANY($parentIds) + 该层富条件，一条 SQL 取全部子行 │ 3. 按 childKey 分桶挂到父行 _children[childId] ▼ ColumnarCodec::encode(ds) | zmc.encode_columnar_json/binary # 列式包，见 §6 ▼ 前端 _unwrapPkg → CmxDataSet.fromJSON(pkg) # 还原嵌套主从树 ▼ { dsMap: { [datasetId]: rootDs }, pkg } → 绑定 CmxMasterSlave / grid
通用性铁律：所有 SQL 由 sql_builder::build_layer_select 按 LayerView / LayerQuery 元数据生成，装载器本身不含任何单据专属列名/表名。每层查询指令来自 DocQuery（缺省用默认）。

② 元数据模型（DocMetaView）

DocMetaView（meta.rs）是单据定义 DOC 的强类型只读投影，由 DocMetaView::parse(doc, base) 从两份 JSON 解析：doc（含 moduleMeta / voucherSchema / voucherTables）+ base（base 字段集，供 documentFieldSets 展开）。

字段含义
layer_order层序（自顶向下 L1..Ln）的主链路——每 level-group 取首表，装载器据此下钻。
layers各层视图 LayerView（含每层全部表，不止主链路）：id / table_name / level / columns / schema(Arc) / summaries / agg_fields。
layer_groups同 level 下全部并列表（同层多表保真，如 L4 = [cv_aux_line, cv_zycb_line]）。
relations父子关系 RelationView：parent / child / parent_key(默认 id) / child_key(默认 upper_id)。
validation_rules校验规则原始数组（回存时二次校验用，读侧不涉）。
status_flow / versioning状态机 / 版本化开关（原始透传）。

关键方法

  • root_layer() — 层序首个层（根）。
  • layer(id_or_table) — 按 schema id 或表名找层。
  • child_layers(parent_id) — 某父的全部直接子表（同父兄弟；parentTable 声明则精确匹配，否则整组回退）。
  • child_key_for(parent_id) / child_key_for_child(child_id) — 父→子的 childKey（默认 upper_id）。
  • is_primary_in_group(table_id) — 是否层组主表（孙层只从主表下钻）。
逻辑名 vs 物理名：定义里 relations 的 parent/child 用逻辑名（headers/account_lines），而 schema 节点与表用物理名（cv_header/cv_acc_line）。装载器不按 relations 名字匹配层，而是按 layer_groups 相邻推导父子 + child_layers 取兄弟。这是通用性的关键。

③ 富查询模型（DocQuery）

DocQuery（query.rs）是每层独立的富查询指令，推翻了旧「根层单等值」的贫弱设计。

// DocQuery 结构
{
  depth?: number,          // 装载深度：None=全部层；Some(n)=只装前 n 层
  includeSiblings?: bool, // 是否装同父兄弟表（默认 true）
  onlyParents?: any[],    // 懒下钻：只装这些父 id 的子树
  layers: {                // 按层 id 指定该层 LayerQuery（未指定用默认）
    "cv_batch":   { filter, orderBy, limit, offset, cursor },
    "cv_acc_line": { filter: { local_dr: { "$gt": 1000 } } }
  }
}

LayerQuery 的四要素

要素形态说明
filter过滤树（AND/OR 组 + 叶子）算子：$eq $ne $gt $gte $lt $lte $in $notIn $like $ilike $contains $startsWith $endsWith $null。简写等值 {status:"posted"} ≡ {status:{$eq:"posted"}}。显式组 {$or:[...]}。
orderBy字符串或字符串数组"!col"=DESC，"col"=ASC。缺省根层 [id]、子层 [child_key, line_no]。
分页limit/offset 或 cursorkeyset 游标（稳定无漂移，优先游标）。wire 形态 base64(JSON {vals,id})。
安全：所有列名在构建 SQL 前用 layer.schema.get_index(col) 白名单校验（validate_against），值按列 data_type 类型化成 DataValue，全部走 $N 参数绑定——零字符串拼接注入面，且绕开 sea-query 的 decimal/array feature 缺口。

④ 装载算法（广度优先下钻）

DocLoader::load（loader.rs）按层广度优先，父批量驱动子，避免 N+1：

  1. 根层：build_layer_select（该层 filter/orderBy/limit/offset/cursor）→ DataSet，收集 rootIds。
  2. 逐层下钻（descend）：沿 layer_groups 取下一层组全部兄弟表；每张子表一条 SQL childKey = ANY($parentIds) + 该层富条件取全部子行；按 childKey 分桶挂到父行 _children[childId]。孙层只从每组主表继续。
  3. 返回根层嵌套 DataSet（完整主从树）。

两个容错/事务要点

  • 兄弟表容错：非主兄弟表装载失败（元数据定义了但物理表未部署）→ 跳过 + 警告，不中断整单。
  • 事务内装载：load_txn(txn_id: Some(..)) 在指定事务连接上查询（看得到未提交写）——供回存事务内重装载做版本快照用（见 doc save · B1）。此时非主兄弟查询套 SAVEPOINT，失败回滚到 savepoint 再跳过，避免污染整个事务。普通装载用 load（走连接池，txn_id=None）。

⑤ 装载端点（6 通道）

装载端点命名 /api/doc/data/<驱动>-<内存模式>-<传输>，三段一眼可辨。GET（URL query 便捷）与 POST（body = 完整 DocQuery JSON）共用入口 doc_load_entry。路由注册见 handlers/portal/mod.rs:148-175。

端点驱动内存传输用途
/doc/data/sqlx-dataset-jsonsqlx老 DataSet（全物化）JSON 信封默认；兼容老链路
/doc/data/tokio-zmc-msgpacktokio-pgZmcDataSet（零拷贝）msgpack 二进制最快；大结果首选
/doc/data/sqlx-zmc-msgpacksqlxZmcDataSetmsgpack 二进制sqlx 侧零拷贝二进制
/doc/data/tokio-zmc-jsontokio-pgZmcDataSet纯 JSON零拷贝 + JSON 兼容
/doc/data/sqlx-zmc-jsonsqlxZmcDataSet纯 JSON同上，sqlx 侧
/doc/data/tokio-zmc-streamtokio-pgZmcDataSet 流式长度分帧 octet-stream超大扁平结果零内存 chunked（单层，不下钻）
选型指引：常规主从树用默认 sqlx-dataset-json（前端 def.binary 缺省）；追求最优内存/传输用 tokio-zmc-msgpack（def.binary=true）；十万行级单层扁平大结果用 stream 端点（loadDocDataStream）。注：tokio 驱动无老 DataSet 通道，该组合返回业务错误。

GET 便捷参数（URL query）

domain, application, module, file   // 单据坐标（必填）
filter="col:value"                // 根层简单等值
limit=50                            // 根层限行
depth=2                             // 装载深度

⑥ 列式包结构（wire 格式）

三种传输（JSON 信封 / 纯 JSON / msgpack 二进制）承载的都是同一个「列式包」结构——ColumnarCodec::encode（columnar.rs）产出，前端 CmxDataSet.fromJSON 逐字段同构还原。

{
  "datasetId": "cv_batch",               // = 根层 schema id
  "columns": ["id","upper_id","total_dr",...], // 列名，取自 schema.fields 顺序
  "rows": [                            // 每项 = 与 columns 对齐的纯值数组
    ["H1", null, 100],
    ["H2", null, 50]
  ],
  "childRows": {                       // 父行 id → { childKey → 递归列式包 }
    "H1": {
      "cv_line": { datasetId, columns, rows, childRows? }  // 递归同构
    }
  }
}
要点：① rows 是位置数组（非对象），列名只出现一次——比每行重复键的 JSON 省一大截体积。② 子集按父行 id 挂进 childRows[父id][childKey]，递归；父行 id 取自名为 id 的列，无该列或无子集时不产出 childRows。③ 三种传输仅编码不同，结构一致：JSON 信封 = {code,msg,data:<列式包>}；msgpack = 同结构的二进制。

信封（envelope）

JSON/msgpack 端点外层包 ApiResp 信封 { code:0, msg:"success", data:<列式包> }；前端 _unwrapPkg 兼容「带信封」与「门户拦截器已拆信封的裸列式包」两种形态。

⑦ 前端调用（loadDocData）

主入口 loadDocData(host, def)（cmx-doc-source.js:45）——两个位置参数，无第三个 options。

import { loadDocData } from 'cmx-data-comp'

const { dsMap, pkg } = await loadDocData(host, {
  domain: 'fi', application: 'cmxfico', module: 'gl',
  file: 'cmxfico_doc_meta_v2.json',   // 单据定义文件名
  // 便捷参数（走 GET）：
  filter: 'period_code:2026',          // 根层等值
  limit: 50, depth: 2,
  // 通道 / 目标库：
  binary: true,                       // true→msgpack 零拷贝通道；缺省→JSON
  dbId: 'fico',                       // 写入 db_id 请求头（非 query）
  apiPath: '/api/doc/data/...',      // 可选：覆盖默认端点
  // 富查询（存在则改走 POST，body=DocQuery）：
  query: { depth: 2, layers: { cv_batch: { filter: { period_code: '2026' } } } },
  signal: abortController.signal
})

// 返回：{ dsMap: { [datasetId]: rootCmxDataSet }, pkg: 原始列式包 }
const rootDs = dsMap[pkg.datasetId]   // 根层 CmxDataSet（已含 _children 嵌套）
def 字段去向说明
domain/application/module/fileURL query单据坐标，必填
filter/limit/depthURL queryGET 便捷（根层）
queryPOST body存在且非空 → 改走 POST，body = DocQuery JSON
binary端点 + Accept 头true → /tokio-zmc-msgpack + application/x-msgpack；否则 JSON
dbIddb_id 请求头头，不是 query 参数
apiPath端点覆盖字段名是 apiPath（无 loadApiPath）
GET vs POST：由 def.query 是否存在且非空唯一决定。有富查询走 POST（body=DocQuery），否则走 GET（便捷参数）。DocQuery 的构建器见 cmx-doc-query.js（buildDocQuery）。

还原：CmxDataSet.fromJSON

loadDocData 内部 _unwrapPkg 拆信封后调 CmxDataSet.fromJSON(pkg)（cmx-data-set.js:362）——把列式包还原成嵌套主从树：每行 columns[i]→rows[i] 重建 {col:value}（缺 id 自动生成），childRows 按父 id 递归 fromJSON 挂到 row._children[childId]。父 id 查找对 BIGINT 做字符串宽松匹配，避免类型不一致丢子层。

⑧ 懒下钻 loadChildren

grid 展开某父行时按需拉取子树，避免一次装满整棵深树。loadChildren(host, def, opts)（cmx-doc-source.js:105）→ POST /api/doc/data/children。

import { loadChildren } from 'cmx-data-comp'

const { pkg, ds } = await loadChildren(host,
  { domain:'fi', application:'cmxfico', module:'gl', file:'...v2.json', dbId:'fico' },
  {
    layer: 'cv_acc_line',          // 要下钻的层 id（任意层，childKey 由元数据推导）
    parentIds: ['H1', 'H2'],       // 上层选中的父 id 列表
    query: { filter: { local_dr: { '$gt': 1000 } } },  // 该层 LayerQuery（可选）
    depth: 1,                       // 从该层继续下钻几层（None=只装该层）
    exit: 'sqlx-zmc-json'         // 出口通道（缺省 tokio-zmc-json）
  })
// 返回 { pkg, ds }：ds = CmxDataSet.fromJSON(pkg)，回填父行 _children

后端 doc_children 以该层为根、给定父 id 下钻装载子树（ZmcDocLoader::load_subtree），出口纯 JSON 列式包，可直接 fromJSON 回填父行 _children。全部经 build_layer_select，通用无单据专属逻辑。

⑨ 流式装载 loadDocDataStream

超大单层扁平结果（十万行级，不下钻）零内存 chunked 传输。loadDocDataStream(host, def, opts)（cmx-doc-stream.js:29）→ /api/doc/data/tokio-zmc-stream，Accept: application/octet-stream。

长度分帧协议

[u32 大端 len][payload] [u32 len][payload] ... [u32=0]（终止） 帧 1 payload = msgpack { datasetId, columns } # 头 帧 2..N payload = msgpack 行值数组 # 每行一帧 len=0 = 流终止
import { loadDocDataStream } from 'cmx-data-comp/lib/cmx-doc-stream.js'

const pkg = await loadDocDataStream(host, def, {
  onRow: (row, i) => { /* 增量渲染，边收边画 */ },
  onProgress: (n) => updateBar(n)
})
// 组装成扁平列式包 { datasetId, columns, rows }（无 childRows）→ CmxDataSet.fromJSON

FrameStreamParser（cmx-doc-stream.js:94）跨 chunk 边界缓冲字节：push(chunk) 追加、next() 在 len=0 返回 {end:true}、整帧未齐时返回 null、否则 {end:false, payload}。每帧 decodeMsgpack(payload)。

msgpack 解码

decodeMsgpack(buf)（cmx-msgpack-decode.js）现委托官方 @msgpack/msgpack 的 decode（V8 手工优化，比手写 JS 解码器快 2~3 倍）。对字符串键 map 返回普通对象、对 bin 返回 Uint8Array，与旧手写解码器输出一致——两消费方（cmx-doc-source 全量、cmx-doc-stream 逐帧）零改动。

⑩ 定义获取与建表建列

装载数据前需先拿定义（voucherTables/moduleMeta）。定义走独立端点，与数据端点分离：

用途端点方法
单个定义/api/definitions/configGET query kind,id,domain,module,file
批量定义（含 base 字段集，首选）/api/definitions/batchPOST { refs, includeBase }
装载器视角的层/列元数据/api/doc/metaGET（handler doc_meta → project_doc_meta）

前端定义模型 CmxDOCMeta（cmx-doc-meta.js，tableProp:'voucherTables' / metaProp:'moduleMeta'）；baseDocMetaRef.file 推断 base 字段集（默认 base_doc_meta_v1.json），批量端点可一并返回。

定义 → 建表建列（cmx-doc-meta-loader.js）

拿到定义后，四个纯函数把它转成 CmxMasterSlave schema + grid 列：

  • buildMasterSlaveSchema(meta) → 单根 N 层线性父子 schema [{id, children:[...]}]（按 layerOrder 相邻链，忽略 relations 名字）。
  • layerPaths(meta) → 每层 DFS 点分路径 {layerId, path, level, levelName, columns}（如 cv_batch.cv_header），供 bindTable/setColumnModel。
  • buildColumnModel(C, path, columns, opts) → 一层 CmxColumnModel，每列 id/caption/dataType/width/align，主键与系统列 editMode:'readonly'。
  • orderColumns(columns) → 业务列在前、系统列在后。

系统列 SYSTEM_COLS id, upper_id, line_no, create_by, create_time, update_by, update_time, delete_flag, client_code——默认排到显示末尾且只读。

⑪ 常用调用配方

A. 最简：装一棵单据树（默认 JSON 通道）

const { dsMap, pkg } = await loadDocData(host, {
  domain:'fi', application:'cmxfico', module:'gl', file:'...v2.json', dbId:'fico'
})
ms.setDataSet({ [pkg.datasetId]: dsMap[pkg.datasetId] })  // 绑定 CmxMasterSlave

B. 富查询 + 二进制通道（大结果最优）

const { dsMap } = await loadDocData(host, {
  domain:'fi', application:'cmxfico', module:'gl', file:'...v2.json', dbId:'fico',
  binary: true,
  query: {
    depth: 3,
    layers: {
      cv_batch:    { filter: { period_code: '2026' }, orderBy: ['!doc_date'], limit: 100 },
      cv_acc_line: { filter: { local_dr: { '$gte': 1000 } } }
    }
  }
})

C. 懒加载：只装根层，展开时拉子树

// 1) 只装根层
await loadDocData(host, { ...def, depth: 1 })
// 2) grid 展开某父行 → 拉该父的子层
const { ds } = await loadChildren(host, def, { layer:'cv_header', parentIds:[clickedId] })

D. 流式：十万行单层扁平表边收边画

await loadDocDataStream(host, { ...def, apiPath:'/api/doc/data/tokio-zmc-stream' }, {
  onRow: (row) => grid.appendRow(row)
})
