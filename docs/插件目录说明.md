# 插件包结构与配置说明

## 一、目录结构概览

```
plugindemo/
├── manifest.json                  # 插件清单文件（必须）
├── wasmtest.wasm                  # WASM 格式的插件代码（必须）
├── api/
│   └── api.json                   # 插件导出的函数/接口定义
├── metadata/
│   ├── domain_app_module_config.json    # 表定义配置清单
│   └── domain_app_module_tables.json    # 表结构定义（DDL）
├── seeddata/                      # 种子数据（初始化数据）
│   ├── domain_seed.json           # JSON 格式种子数据
│   ├── application_seed.csv       # CSV 格式种子数据
│   └── module_seed.json           # 模块种子数据
├── servicedata/
│   └── sample-flow.json           # 服务编排流程定义
├── wit/
│   └── plugin.wit                 # WASM Interface Type 定义
└── bin/                           # 额外的资源文件（如脚本）
    ├── script1.bas
    └── script2.bas
```

## 二、核心配置文件详解

### 2.1 `manifest.json` — 插件清单（必须）

插件包的根配置文件，定义了插件的基本信息、依赖关系、支持的数据库等。

```json
{
  "manifest_version": "1.0",           // 清单格式版本
  "plugin": {
    "id": "example_plugin",            // 插件唯一标识
    "name": "示例插件",                 // 插件显示名称
    "version": "1.0.2",                // 语义化版本号
    "description": "插件描述",          // 插件功能描述
    "url": "https://...",              // 插件主页/下载地址
    "main_file": "wasmtest.wasm",     // 入口文件路径（相对包根）
    "type": "wasm",                    // 插件类型：wasm / rhai
    "dependencies": [],                // 依赖的其他插件
    "extra_files": [],                 // 额外包含的文件（如脚本）
    "table_config_files": [            // 建表配置 JSON 文件列表
      "metadata/domain_app_module_config.json"
    ],
    "supported_databases": [            // 支持的数据库类型
      "mysql", "postgres", "sqlite", "oracle"
    ],
    "domain_code": "FIN",              // 所属域编码
    "application_code": "FI",          // 所属应用编码
    "module_code": "GL",               // 所属模块编码
    "vendor_name": "供应商名称",         // 供应商名称
    "vendor_url": "https://...",       // 供应商网址
    "development_languages": ["rust"]   // 开发语言
  },
  "entries": [                         // ZIP 包内所有文件列表
    "manifest.json",
    "wasmtest.wasm",
    ...
  ],
  "signature_algorithm": "Ed25519",     // 签名算法
  "signature": "<Base64 签名>",        // 签名数据
  "signer_key_id": "optional-key-id"   // 签名密钥标识
}
```

| 字段 | 必须 | 说明 |
|------|------|------|
| `manifest_version` | 是 | 清单格式版本 |
| `plugin.id` | 是 | 插件唯一标识 |
| `plugin.version` | 是 | 语义化版本 |
| `plugin.main_file` | 是 | 入口文件（.wasm 或 .rhai） |
| `plugin.type` | 是 | 插件类型 |
| `plugin.table_config_files` | 否 | 建表配置文件列表 |
| `entries` | 是 | ZIP 包内文件清单 |
| `signature*` | 否 | 签名相关（生产环境必须） |

### 2.2 `metadata/` — 元数据配置

#### `domain_app_module_config.json` — 表定义配置清单

管理一组表定义的配置文件，支持拓扑排序（`depends_on`）和种子数据（`seed_data`）。

```json
{
  "name": "domain_app_module",              // 配置名称（唯一标识）
  "description": "域-应用-模块三层结构表定义",  // 配置描述
  "depends_on": [],                          // 依赖的其他配置（拓扑排序）
  "priority": 0,                              // 优先级（数值越小越先执行）
  "files": [                                 // 表定义文件列表
    "domain_app_module_tables.json"
  ],
  "seed_data": [                             // 种子数据配置（可选）
    {
      "table_name": "cmx_domain_plugin",     // 目标表名
      "file": "seeddata/domain_seed.json",   // 数据文件路径
      "conflict_columns": ["code"],          // 冲突检测列（UPSERT 用）
      "enabled": true                         // 是否启用
    }
  ]
}
```

**执行顺序**：`depends_on` → `priority` → `files`（表定义）→ `seed_data`（种子数据）

#### `domain_app_module_tables.json` — 表结构定义

定义具体的表结构（列、索引、主键等），用于自动生成 DDL 语句。

```json
{
  "tables": [
    {
      "table_name": "cmx_domain_plugin",     // 表名
      "display_name": "域",                   // 显示名称
      "version": 1,                          // 表定义版本号
      "comment": "企业应用域...",              // 表注释
      "primary_keys": ["id"],                // 主键列
      "i18n": false,                          // 是否启用国际化
      "schema": "public",                     // 数据库 schema
      "columns": [                            // 列定义
        {
          "name": "id",
          "label": "主键",
          "field_type": "Int",                // 字段类型
          "is_primary_key": true,
          "is_nullable": false,
          "db_type": "BIGINT",
          "ordinal": 1                        // 列顺序
        }
      ],
      "indexes": [                           // 索引定义
        { "name": "uk_cmx_domain_code", "columns": ["code"], "kind": "unique" }
      ]
    }
  ]
}
```

**支持的 `field_type`**：

| field_type | 说明 | 对应 DB 类型 |
|------------|------|-------------|
| `Int` | 整数 | BIGINT / INT |
| `Float` | 浮点数 | DOUBLE |
| `Decimal` | 精确小数 | DECIMAL |
| `String` | 字符串 | VARCHAR |
| `Text` | 长文本 | TEXT |
| `Bool` | 布尔值 | BOOLEAN |
| `Date` | 日期 | DATE |
| `DateTime` | 日期时间 | TIMESTAMP |
| `Json` | JSON 数据 | JSONB |

### 2.3 `seeddata/` — 种子数据目录

插件安装时自动执行的初始化数据，支持 JSON 和 CSV 两种格式。

#### JSON 格式（`domain_seed.json`）

```json
[
  {
    "id": 1,
    "code": "FIN",
    "code_version": "1.0",
    "name": "财务域",
    "description": "财务管理相关业务域",
    "type": "business",
    "tags": "财务,会计,资金",
    "sort_order": 1
  }
]
```

#### CSV 格式（`application_seed.csv`）

```csv
id,domain_id,code,name,description,type,sort_order
1,1,FI,会计核算,财务会计核算应用,business,1
2,1,GL,总账管理,总账管理模块,business,2
```

**配置冲突列的选取原则**：
- 通常选择业务上唯一的列（如 `code`）
- 组合唯一键（如 `domain_id + code`）用逗号分隔
- 冲突列用于生成 `INSERT ... ON CONFLICT ... DO UPDATE` 语句

### 2.4 `api/` — 函数接口定义

定义插件导出的 WASM 函数接口，供服务编排调用。

```json
{
  "plugin": {
    "name": "cmx-wasmdemo",
    "version": "0.1.0"
  },
  "functions": [
    {
      "name": "count_vowels",          // 函数名称
      "type": "func",                   // 函数类型：func / branch_fn
      "summary": "统计元音字母数量",      // 函数简述
      "description": "详细描述...",      // 函数详细描述
      "input": {                        // 输入参数定义
        "encoding": "msgpack",
        "type": "FunctionInput",
        "fields": [
          { "name": "input.input", "type": "unknown", "description": "..." }
        ]
      },
      "output": {                       // 输出参数定义
        "encoding": "msgpack",
        "type": "FunctionOutput",
        "fields": [
          { "name": "result", "type": "unknown", "description": "..." }
        ]
      }
    }
  ]
}
```

### 2.5 `servicedata/` — 服务编排流程

定义业务流程的节点编排，支持分支路由、事务处理等。

```json
{
  "name": "服务编排流程名称",
  "code": "bm",
  "description": "流程描述",
  "flow": {
    "nodes": [                          // 节点列表
      {
        "id": "start_1",
        "type": "skylake-start",        // 节点类型
        "data": { "name": "开始节点" }
      },
      {
        "id": "route_check",
        "type": "skylake-switch",       // 分支路由节点
        "data": {
          "name": "路由判断",
          "nodeMeta": {
            "pluginId": "example_plugin",
            "functionName": "route_check"
          },
          "options": ["1", "2", "3"]    // 分支选项
        }
      },
      {
        "id": "branch_1_func",
        "type": "skylake-func",         // 函数执行节点
        "data": {
          "name": "分支1处理",
          "nodeMeta": {
            "pluginId": "example_plugin",
            "functionName": "branch_1_process"
          }
        }
      }
    ],
    "edges": [                          // 连接线列表
      {
        "sourceNodeID": "route_check",
        "sourcePortID": "out_1",
        "targetNodeID": "branch_1_func",
        "targetPortID": "in"
      }
    ]
  }
}
```

**支持的节点类型**：

| 类型 | 说明 |
|------|------|
| `skylake-start` | 开始节点 |
| `skylake-end` | 结束节点 |
| `skylake-func` | 函数执行节点 |
| `skylake-switch` | 分支路由节点（路由函数） |
| `skylake-transaction` | 事务处理框 |

### 2.6 `wit/` — WASM Interface Type

定义 WASM 模块的接口类型规范。

```wit
package my:plugin;

world plugin {
    export hello: func(name: string) -> string;
    export add: func(a: u32, b: u32) -> u32;
}
```

## 三、插件安装流程

```
┌─────────────────────────────────────────────────────────────┐
│                      插件安装流程                              │
├─────────────────────────────────────────────────────────────┤
│  1. 验证清单（manifest.json）                                  │
│     └── 签名验证、完整性校验                                     │
│                                                             │
│  2. 解析插件定义（PluginDefinition）                           │
│     └── 获取 table_config_files 列表                          │
│                                                             │
│  3. 执行建表 DDL（metadata/*.json）                           │
│     └── 加载配置 → 解析表定义 → 生成 DDL → 执行                  │
│     └── 支持增量升级（ALTER TABLE）                             │
│                                                             │
│  4. 执行种子数据（seeddata/*.{json,csv}）                      │
│     └── 加载数据文件 → 生成 UPSERT → 执行 → 校验行数              │
│     └── 错误不阻断安装流程                                      │
│                                                             │
│  5. 保存元数据（cmx_meta_table_define 等）                     │
│     └── 表定义版本化管理                                        │
│                                                             │
│  6. 注册插件（内存 + 数据库）                                    │
│     └── 写入 cmx_plugin、cmx_plugin_versions 等表               │
└─────────────────────────────────────────────────────────────┘
```

## 四、配置优先级与依赖

### 4.1 执行顺序

1. **拓扑排序**：`depends_on` 决定配置间的依赖顺序
2. **优先级**：`priority` 数值越小越先执行（同级按文件顺序）
3. **表定义 → 种子数据**：先建表再插数据

### 4.2 依赖配置示例

```json
// config_a.json
{
  "name": "config_a",
  "depends_on": [],
  "priority": 0
}

// config_b.json（依赖 config_a）
{
  "name": "config_b",
  "depends_on": ["config_a"],
  "priority": 1
}
```

## 五、最佳实践

### 5.1 目录组织建议

```
my-plugin/
├── manifest.json
├── main.wasm
├── api/
│   └── api.json
├── metadata/
│   ├── config_a.json      # 按功能模块拆分配置
│   ├── config_b.json
│   └── tables/
│       ├── table_a.json   # 详细表定义放子目录
│       └── table_b.json
├── seeddata/
│   ├── initial/           # 初始数据
│   └── reference/         # 参考数据
└── servicedata/
    └── flows/
```

### 5.2 种子数据命名规范

```
seeddata/
├── {table_name}_seed.json       # 单表数据（JSON）
├── {table_name}_seed.csv        # 单表数据（CSV）
└── {module}_{table_name}_seed.json  # 带模块前缀
```

### 5.3 版本管理

- `manifest.json` 中 `plugin.version` 采用语义化版本（SemVer）
- `domain_app_module_tables.json` 中每张表有独立 `version` 字段
- DDL 执行支持增量升级，无需全量重建表

## 六、错误处理

### 6.1 建表失败

- DDL 执行不在数据库事务中（PostgreSQL 事务内 DDL 会导致事务 abort）
- 失败立即终止安装流程，记录错误日志

### 6.2 种子数据失败

- **不阻断安装**：错误收集到 `SeedDataSummary`，统一输出日志
- **自动降级**：批量执行失败后降级为逐行执行
- **数据校验**：执行后比对文件行数与数据库行数，不一致输出警告

```
[INFO] 种子数据执行完成: 3 表处理, 29 成功, 0 失败, 耗时 125ms
[WARN] 种子数据条数不一致: 表=cmx_domain_plugin, 文件=4条, 数据库=3条
[ERROR] 种子数据执行失败: 表=cmx_application_plugin, 行=5, 错误=...
```
