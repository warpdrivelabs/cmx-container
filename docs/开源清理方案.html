已确认无需轮换：单机测试库凭据。但仍建议从历史抹除——理由不是密码值钱，而是：① 暴露内网 IP 段（192.168.1.x / 192.168.157.x）与密钥命名规范（cmx_sk_dev_ 前缀、密钥生成器风格）；② 给未来立规矩——开源仓一旦允许「配置带真值提交」，迟早有人把生产凭据也这么提。

2.2 方案 A（推荐）· 止血 + 模板化（不改历史，可逆，先做）

  1. 把真实配置移出跟踪（保留本地文件不删，只从 git 移除）： 
    # cmx-container 仓根
git rm --cached dev.toml dev-local.toml dev-vpn.toml
  2. 加入 .gitignore： 
    # --- 本地配置（含真实凭据，绝不提交）---
/dev.toml
/dev-local.toml
/dev-vpn.toml
/.env
  3. 生成脱敏模板 dev.toml.example（把每个真值替换为占位符 __CHANGE_ME__），入仓。开发者复制为 dev.toml 填真值。此步我会逐键脱敏，保留结构与注释，只抹真值。
  4. 提交：git commit -m "chore: 配置脱敏，真实凭据移出版本控制"
效果：从此刻起不再泄露新凭据；但旧提交里的真值仍在历史中（需方案 B 才能抹除）。因已确认无需轮换，方案 A 已满足「不再恶化 + 开发可用」。

2.3 方案 B（彻底）· 历史抹除（改历史，不可逆，正式开源前做）

用 git filter-repo 从所有历史提交中删除这些文件。见 §6 工具说明。

# 预演（先看会删什么，不落盘）——git filter-repo 无 --dry-run，用 --analyze 或先在副本跑
# 强烈建议先在仓库副本上执行验证：
cp -r cmx-container /tmp/cmx-container-filtertest
cd /tmp/cmx-container-filtertest

git filter-repo --invert-paths \
  --path dev.toml --path dev-local.toml --path dev-vpn.toml --path .env

# 验证：历史里应再无这些文件、无明文密码
git log --all --oneline -- dev.toml        # 应为空
git log --all -p -S "hkO4Mjkg" | head       # 应为空
不可逆：filter-repo 重写所有提交 SHA。执行前确保：① 已在副本验证；② 所有协作者知情（之后须重新 clone，不能 pull）；③ 远程需 force-push（见 §8）。

③ P1 · git 历史膨胀（cmx-container 188M）高

3.1 实测：膨胀源 = 历史里的大二进制

历史 blob体积性质
docker/V2/code-server/code-server-4.121.0-linux-amd64.tar.gz131.6 MB第三方可下载产物
docker/V2/wasmtime/wasmtime-v39.0.1-x86_64-linux.tar.xz10.9 MB第三方可下载产物
docker/V2/code-server-extension/*.vsix（多版本）~5 MB ×5可 release 分发
docker/res/swagger-ui-5.17.14.zip4.2 MB第三方可下载产物
crates/web/web-folder/qq.zip2.7 MB疑似误提交
关键：这些文件工作区当前多已删除（docker/ 现仅 9.4M），但仍留在 git 历史——所以 .git 才 188M。清理 = 从历史移除 blob（改历史）+ 今后走 release/CDN 不入 git。

3.2 方案（改历史，与 P0 方案 B 一次做）

# 在副本验证后执行。按体积阈值一刀切 + 指定路径双保险：
git filter-repo \
  --path docker/V2/code-server --path docker/V2/wasmtime \
  --path docker/V2/code-server-extension --path docker/res/swagger-ui-5.17.14.zip \
  --path crates/web/web-folder/qq.zip \
  --invert-paths

# 或按体积（删所有 >5MB 的历史 blob，更省事但需人工核对不误删源码）：
git filter-repo --strip-blobs-bigger-than 5M

# 完成后回收空间：
git reflog expire --expire=now --all && git gc --prune=now --aggressive
du -sh .git   # 预期从 188M 降到 ~15-25M

3.3 今后如何管理这些二进制（防再膨胀）

  • 第三方产物（code-server / wasmtime / swagger-ui）：写进 docker/ 的构建脚本用 curl 下载 + 校验 sha256，不入 git。
  • 自产 .vsix：走 git release / 制品库，仓里只留构建脚本。
  • gitignore 兜底：
    docker/**/*.tar.gz
docker/**/*.tar.xz
docker/**/*.vsix
docker/**/*.zip
**/qq.zip

4.2 处理策略（三选一，按模块分别定）

策略做法适用

⑥ git filter-repo 前置说明

  • 为何不用 git filter-branch：官方已弃用，慢且易错。git filter-repo 是推荐工具。
  • 安装：
    brew install git-filter-repo    # macOS
# 或 pip3 install git-filter-repo
  • 安全护栏：filter-repo 默认要求「fresh clone」（拒绝在有未提交改动/非镜像仓上跑），这是保护。执行前 git status 应干净。
  • 务必先在副本验证：cp -r 一份到 /tmp 跑，确认结果对了，再对真仓执行。

⑦ 推荐执行顺序

分两阶段，低风险先行、历史重写压后一次做：

阶段一 · 低风险（可逆，随时做，不影响协作者）

  1. 1 P0-A：dev*.toml 移出跟踪 + gitignore + 生成 .example 模板
  2. 2 P1 gitignore 补强（docker 二进制今后不入 git）+ 构建脚本改 curl 下载
  3. 3 P3：落地 LICENSE（先选协议）/README/SECURITY/CONTRIBUTING
  4. 4 P2 盘点：查 @infragistics 真实 import，出「删/换/留」清单

阶段二 · 历史重写（不可逆，正式开源前一次性做，需协作者协调）

  1. 5 副本验证 filter-repo（P0-B + P1 合并一次跑）
  2. 6 真仓执行 + gc 回收（188M → ~20M）
  3. 7 force-push + 通知协作者重新 clone
