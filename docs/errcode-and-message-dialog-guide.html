第一部分 · 错误码定义与管理

每个错误码有两种形态，永远成对出现、一一对应：

形态例用途
整数码 code_num: u321002便于口头 / 工单 / 日志快速引用（"1002 错误"）。
字符串码 code: &'static strVALUE_TOO_LONGSCREAMING_SNAKE，稳定判定 key：前端 if 判定、审计、i18n key、帮助中心定位。永不随文案变化。

对话框明细行末尾统一显示 [整数码-字符串码]，例如：

• [凭证批(cv_batch)] 「凭证批名称」长度超限：最多 50 个字符，实际 116 个  [1002-VALUE_TOO_LONG]
为什么不用 HTTP 状态码当错误码？ HTTP 码是粗分类——十几种校验错都映射到同一个 422，无法区分具体是"超长"还是"必填"。 能精确区分"哪种错"的稳定标识，只有这里的 code_num / code_str。

1.2　在哪里定义

全部集中在一个文件、一个枚举 —— 唯一事实源：

cmx-container/crates/libs/cmx-biz/src/errcode/mod.rs

枚举 CmxErrCode 的每个变体带三段元信息，用 match 一处集中维护：

pub enum CmxErrCode {
    TypeMismatch, ValueTooLong, NotNullViolation, /* … 共 14 个变体 */
}

impl CmxErrCode {
    pub fn code_str(&self) -> &'static str { // 字符串码
        match self { Self::ValueTooLong => "VALUE_TOO_LONG", /* … */ }
    }
    pub fn code_num(&self) -> u32 {       // 整数码（分段：1000/1100/1200/1900）
        match self { Self::ValueTooLong => 1002, /* … */ }
    }
    pub fn http_code(&self) -> ErrCode { /* → 422/400/409/500 粗分类 */ }
    pub fn message_template(&self) -> &'static str { /* 中文 {占位} 模板 */ }
}

校验失败以 Violation 结构承载，整数码 + 字符串码一起下发前端：

pub struct Violation {
    pub row:    Option<usize>,    // 出错行索引（0 基）
    pub table:  String,          // 表名 / 字典 code
    pub column: Option<String>,   // 出错列（DB 列名）
    pub caption:Option<String>,   // 列中文名
    pub code:     &'static str,  // 字符串码 code_str()
    pub code_num: u32,           // 整数码 code_num()  ← 与 code 一一对应
    pub message:  String,        // 渲染后的中文提示
}
唯一构造入口 Violation::new(code, …)：内部同时写 code: code.code_str() 和 code_num: code.code_num()。 没有任何地方用 struct 字面量手工构造，所以两个码永远同步、不会漏填。

1.3　如何保证不重复

两道防线：

防线机制
① 编译期（字符串码 / 枚举） 码值全在 match self { … } 里，一个变体一个分支。Rust 编译器强制 match 穷尽且不可重复分支——写重了同一个变体编译不过。字符串码天然按变体唯一。
② 测试期（整数码不重复） 整数码是人工分配的数字，编译器不管数值是否撞。用单元测试 code_num_stable_and_unique 把 14 个码收进 HashSet，断言 set.len() == 数组长度——撞码即测试失败；并锁定关键码值防误改/重排。 
// cmx-container/crates/libs/cmx-biz/src/errcode/mod.rs（#[cfg(test)]）
#[test]
fn code_num_stable_and_unique() {
    let all = [ /* 全部 14 个变体 */ ];
    let nums: HashSet<u32> = all.iter().map(|c| c.code_num()).collect();
    assert_eq!(nums.len(), all.len(), "code_num 必须互不重复");  // ← 撞码即挂
    assert_eq!(CmxErrCode::ValueTooLong.code_num(), 1002);           // ← 锁定关键值
    assert_eq!(CmxErrCode::OptimisticLockConflict.code_num(), 1201);
}

运行：cargo test -p cmx-biz --lib（errcode 相关随 lib 91 个测试一起跑）。

1.4　如何新增一个错误码

只改 一个文件，四处同步（都在同一 impl 内，改动集中）：

  1. 在 enum CmxErrCode 加变体（放对应语义段）。
  2. code_str() 加 Self::X => "X_SCREAMING_SNAKE"。
  3. code_num() 加一个该语义段未用过的整数（如列校验类取 1008）。
  4. http_code() + message_template() 各加一行。
  5. 把新变体加进 code_num_stable_and_unique 测试的 all[] 数组。
红线：整数码一经分配，永不复用、永不重排（下线的码也不要让给新码）。否则历史日志/工单里的旧号会指向新语义。段内往后取新号即可，段号（1000/1100/…）用完再开新段。

1.5　错误码怎么流到前端

DocSaver::save 校验失败
  └─ Violation::new(CmxErrCode::ValueTooLong, …)     // code + code_num 同时写入
       └─ doc.rs: ApiResp::fail_with_data(422, msg, { violations:[…] })
            └─ 门户 fetch 拦截器（api-client.js）透传 data.violations
                 └─ 页面 saveVoucher: toErr(res, body) → err.violations
                      └─ presentDocError(err) → describeDocError → 对话框
                           └─ formatViolations() 拼出 [1002-VALUE_TOO_LONG]
历史坑（已修）：门户全局 fetch 拦截器 api-client.js 早期把业务错误信封转成 {error, code} 时丢掉了整个 data，导致 violations 全没了、对话框退化成一句"数据校验未通过"。现已透传 data 及 data.violations。

第二部分 · 信息提示对话框使用说明

cmx-message-dialog 是通用、零依赖、自包含的信息提示对话框：纯 DOM + Shadow DOM 隔离样式，不依赖 UI5/外部 CSS，不污染宿主。三个级别、亮/暗主题自适应、居中适中、可访问（alertdialog / ESC / 焦点锁）。

2.1　快速上手

从 cmx-data-comp 导入，或页面里经 globalThis.__cmxDataComp 取用：

// ① ES module 导入
import { showCmxMessage, cmxInfo, cmxWarn, cmxError } from 'cmx-data-comp'

// ② html-pages / native-pages 里（全局对象）
const C = globalThis.__cmxDataComp
C.showCmxMessage({ level:'error', title:'保存失败', message:'字段超长' })

// ③ 便捷别名（第一参就是正文）
C.cmxInfo('已保存')
C.cmxWarn('版本号已存在', { helpCode:'DEF_VERSION_DUP' })
await C.cmxError('服务器 500', { title:'新建失败', helpCode:'DEF_CREATE_FAILED' })

2.2　showCmxMessage(opts) API

参数类型 / 默认说明
level'info'|'warning'|'error' = 'info'级别。非法值回退 info。
titlestring标题。缺省用级别名（信息/警告/错误）。
messagestring正文，支持多行 \n（渲染为换行）。
detailsstring[]明细列表，每项一行（如各条 violation）。渲染成带滚动的明细框。
helpCodestring帮助定位码（如错误码）。warning/error 且有 helpCode/helpUrl 时显示「获取帮助」。
helpUrlstring帮助 URL。门户无监听时回退 window.open 新标签打开。
okTextstring = '确定'主按钮文案。
allowCopyboolean是否显示「复制详情」。缺省：error 且有 details 时为 true。
onClosefunction(how)关闭回调，how = 'ok' 或 'help'。

返回 Promise<'ok'|'help'>：点确定/ESC/点遮罩 → 'ok'；点获取帮助 → 'help'。

关闭方式：确定按钮、ESC 键、点击遮罩，三者都关闭并 resolve 'ok'。

2.3　三个级别

级别用途获取帮助
信息 info成功/中性告知，如"已保存"不显示
警告 warning可恢复/需注意，如"版本已存在""保存冲突"显示
错误 error失败，如"保存失败""校验未通过"显示
选级别的经验法则：能让用户改一下就好的 → 警告（前置校验没填、版本重名、乐观锁冲突）；操作确实失败了 → 错误（列校验失败、500、网络异常）；纯告知/成功 → 信息。

2.4　主题（亮 / 暗自适应）

对话框自动跟随门户 UI5 主题，无需传参。判定顺序：

  1. 读门户主题键 __portal_ui5_theme__——先 sessionStorage、后 localStorage（门户实际写 sessionStorage）。含 dark/hcb → 暗色；亮色/hcw → 亮色。
  2. 读不到 → 回退系统偏好 prefers-color-scheme。

实时跟随：已打开的对话框会监听 cmx-portal-theme-change（门户切主题）与 storage（跨标签页），明暗变化时按新主题重开并保留内容。

历史坑（已修）：门户主题写在 sessionStorage，而对话框早期只读 localStorage——键名相同但存储不同，永远读不到 → 亮色主题下对话框仍是暗的。现已两处都查、且 session 优先。

2.5　获取帮助 → 帮助中心

warning/error 级点「获取帮助」时，对话框派发 cmx-help-request 事件（composed 冒泡到 window）：

detail = { code: opts.helpCode, level, title, url: opts.helpUrl }

门户 portal-app.js 监听此事件 → 打开帮助中心，并把错误码/标题作为上下文传给 AI 助手就地答疑；preventDefault 表示已接管，对话框便不再回退 window.open。门户是常驻根组件，全局生效——任何页面弹的对话框都能跳帮助中心。

2.6　presentDocError —— 存储错误一行接入

调 DCT/DOC 存储服务（saveDocData / /api/doc/save / /api/dict/save）的页面，不用自己判断错误类型，catch 里一行交给 presentDocError：

try {
  await saveDocData(host, def, { saveMode:'merge', changes })
} catch (err) {
  const r = await C.presentDocError(err, {
    action: 'save',                        // save|load|delete|op → 默认标题/帮助码
    tableNames: { cv_batch:'凭证批', cv_acc_line:'科目行' }  // 表名→中文层名（violation 前缀）
  })
  if (r && r.kind === 'conflict') await reload()   // 冲突：确认后刷新到最新版
}

presentDocError 自动把存储层错误分成四类、映射到对话框：

err 形态kind级别对话框
err.conflict（409）conflict警告"他人已修改，请刷新重试"；返回后可 reload()
err.validation + err.violations（422）validation错误标题"数据校验未通过" + 逐行明细 [码] 层[列] 原因
普通 Error（500/网络）generic错误剥掉 [funcName] 技术前缀后展示
AbortError（请求取消）abort—静默不弹（正常中断），返回 null

返回 Promise<{kind, choice}|null>：已弹出 → {kind, choice:'ok'|'help'}；被静默 → null。

另有纯映射函数 describeDocError(err, opts)（不碰 DOM，返回 {kind, level, title, message, details, helpCode}），供单测或自定义渲染。

action 默认标题 / 帮助码

actiongeneric 标题generic 帮助码
save保存失败DOC_SAVE_FAILED
load装载失败DOC_LOAD_FAILED
delete删除失败DOC_DELETE_FAILED
op操作失败DOC_OP_FAILED

2.7　端到端 —— 一次保存失败的完整链路

用户在凭证页把批名称填成 116 字（列限 50），点保存：

1) 后端 DocSaver 校验失败 → Violation::new(ValueTooLong, "cv_batch", "batch_name", "凭证批名称", …)
   下发 { code:422, msg:"数据校验未通过（1 处）",
          data:{ violations:[{ table:"cv_batch", column:"batch_name", caption:"凭证批名称",
                               code:"VALUE_TOO_LONG", code_num:1002,
                               message:"「凭证批名称」长度超限：最多 50 个字符，实际 116 个" }] } }

2) 门户 fetch 拦截器透传 data.violations（不再丢弃）

3) 页面 toErr(res, body) → err.validation=true, err.violations=[…]

4) presentDocError(err, { action:'save', tableNames:{cv_batch:'凭证批'} })

最终对话框：

错误 数据校验未通过

以下字段未通过校验，请修正后重试：
┌─────────────────────────────────────────────────────────────┐
│ • [凭证批(cv_batch)] 「凭证批名称」长度超限：最多 50 个字符，       │
│   实际 116 个  [1002-VALUE_TOO_LONG]                              │
└─────────────────────────────────────────────────────────────┘
        [获取帮助]              [复制详情]  [确定]

「获取帮助」带的定位码是首条 violation 的字符串码 VALUE_TOO_LONG（稳定 key）；明细行同时显示整数码，便于口头引用"1002 错误"。
