# 门户菜单增加指南（LLM 可执行）

> 本文档面向接手「给 cmx 门户增加菜单项」任务的 LLM / Agent。读完即可独立完成加菜单，无需二次探索。
>
> 适用仓库：`cmx-container`（后端 Rust，:8080）+ `cmx-enterprise-portal`（前端 Lit/UI5，仅契约参考，一般不需改）。

---

## 0. 核心结论（先看这个）

**菜单 = 后端 JSON 文件，加菜单 = 改一个 JSON，不动任何代码。**

- 菜单数据由后端 `GET /api/menu-pages?menu=<菜单key>` 动态返回，前端拉取后渲染侧边栏。
- 一个「菜单」对应 `data/menu-pages/` 下的一个 `.json` 文件。
- 菜单 key 用**点分命名空间**映射到分层目录，详见 [§2](#2-找到正确的菜单文件)。
- 点击菜单项后弹出什么界面，由节点里的 `workspace` 字段决定（最常见是嵌入一个 html 页面）。

---

## 1. 菜单树的数据结构

菜单 JSON 根为 `{ "version": 1, "items": [ ... ] }`（也接受顶层数组）。`items` 是分组/节点数组，可任意嵌套。

### 1.1 菜单节点字段

```jsonc
{
  "id": "fi-cmxfico-gl-employee",     // 【必填】全局唯一，也是打开后内容标签的 tabId
  "name": "employee",                  // 内部名，展示文案的回退来源
  "caption": "AI员工信息表单",          // 【建议】显示文字，优先级 caption > name > id
  "type": "workspace-node",            // 节点类型，点击会打开工作区（见下）
  "icon": "tabler-outline/users",      // 图标名（见 §5 图标）
  "permissionId": null,                // 权限ID；null/空 = 不限制。开发态全显
  "expanded": true,                    // 【仅分组】是否默认展开
  "children": [ ... ],                 // 【仅分组】子节点数组；有 children 即为分组
  "workspace": { ... }                 // 点击后打开的工作区配置（见 §3）
}
```

**判定规则（前端自动）**：节点有非空 `children` → 渲染为可展开的**分组**（用 `ui5-side-navigation-item`，带 `expanded`）；否则渲染为**叶子项**（点击触发 `nav-selection` 打开 `workspace`）。

**字段来源与权威定义**：
- 节点契约：`cmx-enterprise-portal/CMXPortalManager/src/lib/explorer-menu.js`（第 20 行 typedef、第 26–29 行 KNOWN_KEYS）
- 其余非已知键会原样收进 `extras` 透传给业务，**不会报错**，但尽量只用已知字段。

### 1.2 分组节点示例

```jsonc
{
  "id": "gl",
  "name": "gl",
  "caption": "基础数据管理",
  "permissionId": null,
  "icon": "tabler-filled/home",
  "expanded": true,
  "children": [
    { "id": "page-home", "name": "home", "caption": "首页", "permissionId": null },
    { ...更多叶子或子分组... }
  ]
}
```

## 2. 找到正确的菜单文件

### 2.1 menu key → 文件路径映射规则

后端 `parse_menu_ref`（`crates/libs/cmx-portal/src/meta/menu_pages.rs:40`）把点分 key 映射为目录：

| menu key | 对应文件 |
|---|---|
| `explorer-menu` | `data/menu-pages/explorer-menu.json` |
| `fi.cmxfico.gl.explorer-menu` | `data/menu-pages/fi/cmxfico/gl/explorer-menu.json` |
| `fi.cmxfico.report.report-menu` | `data/menu-pages/fi/cmxfico/report/report-menu.json` |

**规则**：点分最后一段加 `.json` 作为文件名，前面每段变成一层目录。单段直接当文件名。

### 2.2 命名约束（后端会校验，违规返回 400）

- **整体 menu key**：只允许字母、数字、`.`、`_`、`-`，长度 1–128（`is_safe_id`）。
- **每一段**：不能为空（禁止前导/尾随点、连续点），只允许字母、数字、`_`、`-`（`is_safe_segment`）。
- 即：菜单文件名/目录名必须是 `[a-zA-Z0-9._-]`，不能含中文、空格、斜杠。

### 2.3 怎么知道要改哪个文件

用户通常会说「在 X > Y > Z 后面加」。先定位这条菜单在哪个文件：

```bash
# 在 data/menu-pages 下搜菜单文案
grep -rln "加载服务自检" data/menu-pages/
# → data/menu-pages/fi/cmxfico/gl/explorer-menu.json
```

然后用脚本打印树结构，确认要跟在哪个节点后面：

```bash
python3 -c "
import json
doc = json.load(open('data/menu-pages/fi/cmxfico/gl/explorer-menu.json'))
for i, grp in enumerate(doc.get('items', [])):
    print(f'[{i}] {grp.get(\"caption\")} (id={grp.get(\"id\")}, children={len(grp.get(\"children\",[]))})')
    for j, ch in enumerate(grp.get('children', [])):
        print(f'    ({j}) {ch.get(\"caption\")} (id={ch.get(\"id\")})')
"
```

## 3. `workspace` —— 点击菜单后打开什么

`workspace` 是一个对象，**键 = 区域名，值 = 该区域的视图配置**。

### 3.1 区域键

| 区域 | 含义 | 备注 |
|---|---|---|
| `content` | 主内容区（中间最大） | 最常用，几乎所有菜单只配它 |
| `explorer` | 左下导航/辅助区 | |
| `property` | 右侧属性区 | 即使单视图也有底部 Tab 条 |
| `bottom` | 底部日志/数据区 | |
| `prepare` | 打开主区前先弹的准备对话框 | 包装层可加 `width`/`height` |
| `floatview`(别名`float`) | 浮动窗口 | |
| `model` | 隐藏数据页，仅作 API 提供方 | |
| `inner` | 隐藏，用户脚本可按需挪到对话框 | |
| `embed` | 嵌入页，供其他页 `<cmx-embed-page>` 借出 | |

> 99% 的加菜单场景：**只配 `content` 一个区域**。

### 3.2 区域值的写法（三种等价）

一个区域可填**单个视图对象**、**视图数组**、或 **`{ caption?, icon?, views: [...] }` 包装**。多于一个视图时底部用 Tab 切换：

```jsonc
// 写法A：单视图（最简）
"content": { "type": "html_pages", "html_page": "xxx" }

// 写法B：多视图数组
"content": [ { "type": "..." }, { "type": "..." } ]

// 写法C：包装（推荐，可给区域加标题/图标）——本仓库主流写法
"content": {
  "caption": "AI员工信息表单",
  "icon": "tabler-outline/users",
  "views": [ { "tabLabel": "员工信息", "type": "html_pages", "html_page": "xxx" } ]
}
```

权威定义：`cmx-enterprise-portal/CMXPortalManager/src/lib/workspace-view-config.js`（`WorkspaceRegionViewsInput` typedef，第 12 行；`normalizeWorkspaceRegionViews`，第 80 行）。

### 3.3 视图 `type` 取值（重点）

| `type` | 含义 | 关键字段 | 数据接口 |
|---|---|---|---|
| **`html_pages`** | 嵌入一个 HTML 设计器页面（**最常用**） | `html_page: "<页面id>"` | `POST /api/html-pages/batch`（打开前批量预取） |
| **`native_pages`** | 嵌入手写 JS/HTML 源码页（元数据驱动/大模型生成） | `native_page: "<id>"`, `view`, `props: {...}` | `GET /api/native-pages/:id`（运行时自取） |
| `placeholder` | 占位页 | `data: { "title": "标题" }` | 无 |
| `json` | 展示 JSON 数据 | `data: { "value": {...} }` | 无 |
| `code` / `pre` | 代码文本 | `data: { "code": "..." }` | 无 |
| `markdown` | Markdown 渲染 | `data: { "text": "..." }` | 无 |
| `iframe` | 内嵌网页 | `data: { "src": "url" }` | 无 |
| `link` | 外部链接跳转 | `data: { "href": "url" }` | 无 |
| `split` | 分屏（含子区域） | 见渲染器 | 无 |
| 自定义类型 | 各 portal-* 组件用 `registerWorkspaceViewType` 注册 | — | — |

#### `html_pages` vs `native_pages`（常被问）

- **`html_pages`**：页面由 CMXHTMLDesigner 设计器产出，是编译产物（runnableDoc / Custom Element），侧重「所见即所得的设计器页面」。打开前由 `prepareWorkspaceHtmlPages` **批量预取**所有引用的页面 id 并注入。引用方式：`"html_page": "fi.cmxfico.gl.employee"`。
- **`native_pages`**：**手写 JS/HTML 源码**页，运行时只插入一个空宿主 `<cmx-native-pages-host>`，由宿主自行 `fetch` 源码执行。每个页是独立 CE + shadowRoot，DOM/CSS 天然隔离；内联脚本包进函数作用域执行（顶层变量不泄漏全局）。适合元数据驱动的通用功能页。引用方式：`"native_page": "portal.doc.doc-loader", "view": "content", "props": { ... }`。

权威定义：
- `html_pages`：`cmx-enterprise-portal/CMXPortalManager/src/lib/workspace-html-pages.js`
- `native_pages`：`cmx-enterprise-portal/CMXPortalManager/src/lib/workspace-native-pages.js`

## 4. 标准操作流程（加一个菜单项）

### Step 1 —— 确认要打开的页面 id 及其类型

```bash
# html-pages 页面清单（看 id / name）
python3 -c "
import json
d = json.load(open('data/html-pages/pages-list.json'))
for p in d.get('pages', []):
    print(p.get('id'), '|', p.get('name'), '|', p.get('relPath'))
"

# native-pages 页面清单
python3 -c "
import json
d = json.load(open('data/native-pages/index.json'))
for p in (d.get('pages', d) if isinstance(d, dict) else d):
    print(p.get('id'), '|', p.get('sourceType'), '|', p.get('name'))
"
```

- 页面在 `data/html-pages/` → 用 `type: "html_pages"` + `html_page`。
- 页面在 `data/native-pages/` → 用 `type: "native_pages"` + `native_page`。
- 如果页面还不存在，需要先（让人/用设计器）创建页面，再回来加菜单。**不要假设 id 存在**，务必用上面脚本核对。

### Step 2 —— 定位菜单文件和插入点

见 [§2.3](#23-怎么知道要改哪个文件)，用 `grep` 找文件 + python 打印树结构定位。

### Step 3 —— 编辑 JSON，在目标分组的 `children` 数组追加节点

**重要 JSON 编辑纪律**：
- 必须**先 Read 文件**再编辑（Edit 工具要求）。
- 追加到 `children` 数组**末尾**时：前一个节点对象后补一个逗号，再粘新节点。漏逗号 / 多逗号都会让 JSON 非法。
- **强烈建议沿用同分组现有节点的字段风格**（是否写 `type`、icon 前缀、缩进空格数等），保持一致性。
- 编辑后**必须校验 JSON 合法性**（见 Step 4）。

### Step 4 —— 校验 JSON

```bash
python3 -c "
import json
doc = json.load(open('data/menu-pages/fi/cmxfico/gl/explorer-menu.json'))
grp = doc['items'][0]   # 改成你改的分组
print('OK |', grp['caption'], '| children =', len(grp['children']))
for ch in grp['children'][-3:]:
    print('  -', ch.get('id'), '|', ch.get('caption'))
"
```

校验通过（不抛异常 + 新节点出现在末尾）即成功。JSON 非法会直接 `json.JSONDecodeError`。

### Step 5 —— 生效

菜单是后端动态加载。**重启 `cmx-container` 后端**（或刷新页面 / 点侧栏刷新按钮）即可在侧边栏看到新菜单。

## 5. 图标

图标用 UI5 / Tabler 图标名（字符串），两种都常见：

- **Tabler 系列（本仓库主流）**：`tabler-outline/users`、`tabler-filled/home`、`tabler-outline/checklist`、`tabler-outline/list`、`tabler-outline/select`、`tabler-outline/flame` 等。
- **UI5 原生**：`home`、`documents`、`sys-monitor`、`form`、`table-view`、`value-help`、`edit`、`log`、`detail-view`、`database`、`world`、`puzzle` 等。

**怎么选图标**：在同菜单文件里 `grep` 已有图标的命名风格，沿用同一系列。图标名不对只是不显示图标，不会报错。

```jsonc
{
```

## 7. 常见陷阱

| 陷阱 | 后果 | 对策 |
|---|---|---|
| 漏逗号 / 多逗号 | JSON 非法，**整份菜单加载失败**，侧边栏空白 | Step 4 校验 |
| `id` 重复 | 后打开的覆盖/异常 | 全树唯一，建议 `<domain>-<app>-<page>` 命名 |
| 把页面 id 填错 / 页面不存在 | 该菜单点开显示「未加载 / 页面未返回」 | Step 1 先核对页面 id 真实存在 |
| html_page 用了 native-pages 的 id（或反之） | 页面加载失败 | 分清 `html_pages`↔`data/html-pages/`、`native_pages`↔`data/native-pages/` |
| 文件名/目录含中文或空格 | 后端 400「menu 段非法」 | 仅 `[a-zA-Z0-9._-]` |
| 改了前端代码 | 不必要 | 菜单纯 JSON 驱动，正常情况只改后端数据文件 |
| 没重启后端就以为没生效 | 看不到新菜单 | 重启 cmx-container 或刷新页面 |

## 8. 增加全新顶层活动（最左侧图标，进阶，少见）

如果要加的是**最左侧活动栏的新图标**（而不是某个侧栏菜单项），需改 activities 文件。流程：

1. 找到 activities 文件（由 `CMX_ACTIVITIES_DIR` 决定，前端默认 `name=portal`）。仓库内可 `find data -name 'portal.json'` 或看后端 `crates/libs/cmx-portal/src/meta/activities.rs`。
2. 在 `activities` 数组追加：
   ```jsonc
   {
     "id": "my-module",
     "icon": "tabler-outline/...",
     "label": "我的模块",
     "position": "top",            // top 上半 | bottom 下半
     "sideNav": {
       "type": "menu-pages",        // 或 "module"（等价）/ "built-in" / "html_pages"
       "menu": "my-module-menu",    // 指向 data/menu-pages/my-module-menu.json
       "title": "我的模块"
     }
   }
   ```
3. 新建 `data/menu-pages/my-module-menu.json`，写菜单树（结构同本文 §1）。

> 一般「加菜单」指的是 §1–§7 的侧栏菜单项，本节通常用不到。
