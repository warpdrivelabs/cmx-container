3本轮唯一硬伤：CI test 硬门禁当前即红

失败测试：crates/libs/cmx-infra/cmx-database/src/crud/count_optimizer.rs 的 test_left_join_optimization（断言生成的 COUNT SQL 不含 left join orders，实际含）。

根因：测试 SQL 以 PostgreSQL 保留字 user 作表名（FROM user u LEFT JOIN orders o ...），sqlparser PG 方言解析失败 → try_generate_optimized_count_sql 返回 Err → 走 wrap_count_sql 兜底（原样保留 left join）→ 断言失败。同文件另 3 个测试通过，部分还是兜底路径的「巧合」通过。
定性：既有失败，非本轮回归——该文件最后修改于 2026-07-02（d6965fb3），本轮三个提交均未触碰。此前无 CI 跑 --lib 全量，失败潜伏至今。
影响：CI 中 cargo test --workspace --lib 为 allow_failure: false 硬门禁——首次推送即红。「清零专项」跑了 fmt/clippy 却漏跑 test，门禁上线前缺一次全量自验。

修复建议（任选其一，均为小改）：

  • 测试用例表名改为非保留字（如 users）或加引号 "user"；同时审查优化器对保留字表名的真实生产影响（生产 SQL 若用保留字表名，优化会静默退化为兜底，功能正确但失去 JOIN 优化）；
  • 优化器兜底路径增加可观测性（当前仅 warn! 一次，建议加 metric 计数，便于发现「优化静默失效」）。
