2架构评估 强项

分层干净、依赖方向清晰，新模块沿用了正确范式——这是工程最好的部分。

web-server → cmx-api(26K) → cmx-biz / iam / plugin / portal / model / form → cmx-flow-*(10K) 流程引擎 / cmx-rpt-*(4.3K) 报表 / cmx-ai → cmx-infra/*(45.7K: database / buffer / storage / rpc / auth / audit) → cmx-core / cmx-traits / cmx-utils（零业务基础层）
设计点复核结论评级
Trait 解耦cmx-auth 不依赖 cmx-iam，经 cmx-traits::{UserAuthQuery, PermissionChecker} 在 cmx-biz 注入，抽查验证属实优
集群插件同步单一写入原则（仅 API 节点写 DB）+ Redis Pub/Sub 通知 + 60s 幂等 reconciliation 补偿；只做运行时同步、天然幂等、多节点并发安全，符合根无状态/集群约束优
双数据库层cmx-database（sqlx 多库）+ cmx-database-pg（tokio-postgres PG 专用 + 零拷贝 rowsource），职责分离合理优
全局内存状态OnceCell/LazyLock 全工程仅约 8 处、DashMap 4 处，均为注册表/会话注册等合理用途，未见违规缓存业务数据优
自研能力内核BPMN 2.0 XML 编译器 + 令牌执行内核（等待态即提交点）、报表 DSL 公式引擎——语义中立、无 DB 依赖的内核/壳分离规范优

3规范执行对照（AGENTS.md 18 章）

thiserror 全覆盖、tracing 统一、依赖集中管理、表前缀、迁移命名等基础项执行良好；问题集中在以下 4 项。

🔴 [严重] .env 已被 git 追踪且含敏感键。
.gitignore 中 #.env 规则被注释掉，git ls-files 确认 .env 在库内，含 NACOS_PASSWORD、NACOS_USERNAME、TEST_DATABASE_URL 等键名，最近提交 2026-07-14。直接违反项目 AGENTS.md 4.1 硬规则，凭据已进入 git 历史。处置：git rm --cached .env + 恢复 gitignore + 轮换泄露凭据（必要时清史）。
🟡 handler 手写 SQL 违规仍在生长。
cmx-api/src/handlers/ 下 5 个文件（portal/model_center.rs、dct.rs、doc.rs、auth/api_key_handler.rs、oauth2_client_handler.rs）直接调 execute_sql，违反第 8 章"cmx-api 纯 HTTP 适配层"。model_center.rs 同时是 unwrap 热点（14 处），说明违规代码仍在生长，而非仅存量维护。
🟡 unwrap/panic 在新代码中回潮。
全工程 .unwrap() 1,388 处、panic! 103 处（v2 称生产路径已收敛到 84）。重灾区均为近 3 周新代码：cmx-flow-bpmn/src/lib.rs（unwrap 17 + panic! 10）、cmx-biz/src/doc/{saver,meta}.rs（各 21）、cmx-core/src/model/cell.rs panic! 20 处且在生产模型代码。
🟡 v2 三项冻结待办：两项原样、一项倒退。
插件签名 validator.rs 中 verify_signature: false 仍在（且与 settings.rs 默认 true 两处不一致）；行级数据权限 get_data_scope 仍恒返回 DataScope::All；限流中间件 mw_rate_limit.rs 整体被注释禁用（v2 时是"缺失"，现在是代码留着但不用）。

4其他风险

风险证据等级
无 CI 门禁无 .github/workflows / .gitlab-ci.yml，无 rust-toolchain.toml 锁定工具链；v2 达成的"clippy 零告警"已在新代码中回退高

6建议（按优先级）

1
本周必做：.env 出库。 git rm --cached .env + 恢复 .gitignore 注释 + 轮换 NACOS 等已泄露凭据；如已推送远端，评估历史清理。
2
设 CI 门禁。至少 cargo check --workspace + clippy --workspace --tests -D warnings + cargo test，否则每次冲刺后都要重做一轮 v2 式收尾。
3
对新模块做一轮 v2 式质量收尾。重点：cmx-flow-bpmn、cmx-biz/doc、cmx-core/model/cell.rs 的 panic!/unwrap；model_center.rs 手写 SQL 下沉到业务 crate。

5
依赖治理。cargo-deny 查重；评估 wasmtime/extism 双运行时并存必要性；清理 76 个重复版本包。

刷新 README。crate 数量、版本号、cmx-flow / cmx-rpt / cmx-ai / cmx-portal 模块清单同步。
