一、凭证结构与记账主体
维度SAP FIOracle EBS GL
共性：复式记账业务共性 借贷必相等；凭证 = 头(单据级信息) + 多条分录/行(科目+金额+方向)；过账后更新科目余额、不可改只能冲销。
凭证层级 2 层凭证头 BKPF → 行项目 BSEG。S/4HANA 行项目并入通用日记账 ACDOCA(更宽，含并行分类账)。 3 层凭证批 GL_JE_BATCHES → 凭证头 GL_JE_HEADERS → 凭证行 GL_JE_LINES。批级统一过账、按来源冻结。
记账主体 公司代码 BUKRS(独立出表法律主体)，挂在 Company(合并)下。 账本 Ledger(4C：科目表/日历/币种/会计方法) + 经营单位 OU(MOAC 事务边界)。
凭证主键 复合键 BUKRS + BELNR + GJAHR(公司代码+凭证号+会计年度)，BELNR 来自凭证类型的 FI number range。 JE_HEADER_ID + 行 JE_LINE_NUM；凭证号来自文档序列 Document Sequence。
凭证分类 凭证类型 Document Type BLART(SA/KR/DR/AB…)，控制编号范围与允许账户类型。 双重：来源 Source(Manual/Receivables/Payables…) + 类别 Category(Sales/Adjustment…)。
二、科目与多维核算 ★ 核心差异
维度SAP FIOracle EBS GL
共性：多维分析业务共性 一笔账要能按科目、组织、产品/项目等多个维度分析。两套用截然不同的机制实现。
科目维度 单一科目 + 专列维度行项目用总账科目 HKONT；利润中心 PRCTR、段 SEGMENT、业务范围 GSBER、功能范围 FKBER 各占独立专用字段。 会计弹性域 + CCID科目本身是多段组合(公司-成本中心-自然账户-产品…)，凭证行只存代码组合 CODE_COMBINATION_ID，段在 GL_CODE_COMBINATIONS。
维度扩展性 维度写死为列，加全新分析维度需扩展数据结构(不灵活，但语义最明确、独立可查)。 段数与含义由 Accounting Flexfield 配置决定，加维度=加一个段，不改表结构(最灵活，但分析需 JOIN CCID 解析)。
行项目维度数 16 个专列维度(科目/记账码/利润中心/成本中心/段/业务范围/功能范围/订单/WBS/客商/税码…)。 CCID 1 个(内含 N 段) + 客商/税率等少量直列；多维"长在科目里"。
借贷表达 金额+方向金额列 WRBTR/DMBTR + 借贷标志 SHKZG(S借/H贷)，不分借贷两栏。 借贷分列输入币 ENTERED_DR/CR + 本币 ACCOUNTED_DR/CR，借方贷方各一列。
记账码 有Posting Key BSCHL(40/50/01/31…)决定借贷方向+账户类型+字段状态。 无由 CCID 的自然账户类型 + 借贷列直接体现，无记账码概念。
三、并行会计与多币种
维度SAP FIOracle EBS GL
共性：多准则/多币种业务共性 跨国/集团需按多准则(IFRS/本国/税务)并行出表，按多币种(交易币/本位币/集团币)并行记账。
并行会计 分类账Ledger 0L(主/IFRS)+ 扩展分类账 L1(CAS)/L2(税务)，S/4 在 ACDOCA 行层并行。 从账本主账本 + 报告/从账本(Reporting/Secondary Ledger)，通过 SLA 复制。
多币种金额 行项目 7 个多币种度量：凭证币 WRBTR、本位币 DMBTR、集团币 DMBE2、第二三本位币等。 输入币/本币各借贷分列 ENTERED_*/ACCOUNTED_* + 汇率类型(Corporate/Spot/User)。
凭证拆分 有Document Splitting 可按利润中心/段强制平衡，自动补内部往来行。 无原生凭证拆分；靠 CCID 平衡段(Balancing Segment)与公司间(Intercompany)规则。
四、单据生命周期（状态机）
维度SAP FIOracle EBS GL
共性：草稿→过账→冲销业务共性 凭证经暂存/审批→过账(更新余额)→只能红冲；过账前校验借贷平衡+期间开放。
状态 held 暂存 → parked 预制 → posted 已过账 → reversed 冲销。真实状态在 BSTAT。 unposted(U) → approved → processing(I)/error(E) → posted(P) → reversed。STATUS 单字符码。
过账校验 借贷平衡(公司代码内，启用拆分则按段)、期间开放(记账期间变式)、字段状态组必填。 借贷平衡(账本，非平衡账本除外)、期间开放(O/F)、CCID 启用且允许过账。
来源与日志 来源事务码 TCODE + 参考对象 AWTYP/AWKEY 关联 MM/SD 等。 大量来自 Journal Import + 子分类账 SLA(XLA_AE_HEADERS/LINES)，行 GL_SL_LINK_ID 关联；批动作历史 GL_JE_ACTION_LOG。
五、控制与配置机制
维度SAP FIOracle EBS GL
字段控制 字段状态组 Field Status Group(必填/可选/隐藏) + 记账码字段状态，叠加取严。 弹性域段的校验类型(独立/从属/表校验) + 值集(Value Set)控制取值。
期间控制 会计年度变式(K4，12+4特别期) + 记账期间变式(OB52 开关账)。 会计日历(GL_PERIOD_SETS) + 期间状态 GL_PERIOD_STATUSES(开/关/未来可输)。
税务 税码 Tax Code MWSKZ + 税务过程。 E-Business Tax 税率 ZX_RATES_B(税务体系 Regime 驱动)。
往来主数据 业务伙伴 BP(S/4 统一客商；经典 KNA1 客户/LFA1 供应商)。 供应商 AP_SUPPLIERS + 客户 TCA(HZ_PARTIES/CUST_ACCOUNTS)。
总评
SAP FI：维度专列、并行会计(分类账+多币种)、凭证拆分能力最强，语义最明确；代价是维度写死不灵活、配置最重。适合跨国集团多准则并行出表 + 强分析。
Oracle EBS：弹性域(CCID)扩展性最优雅、三层批结构利于大批量自动化、子分类账(SLA)链路完整；代价是多维"长在科目里"、分析需解析 CCID、弹性域实施门槛高。适合大型集团灵活扩维 + 大批量自动化。
一句话：同一笔账，SAP 用"一个科目 + 一排专用维度列 + 借贷标志"，Oracle 用"一个代码组合 CCID(多段) + 借贷分列"——这是两套凭证模型一切差异的根源。
