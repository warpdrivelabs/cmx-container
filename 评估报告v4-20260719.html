7建议（按优先级）

1

立 CI 门禁（本轮成果的护栏）。 最小集：cargo check --workspace + clippy --workspace --tests -D warnings + cargo test + gitleaks（顺带堵住 .env 类泄露）。没有它，DCT/DOC 这次收尾会像 v2 收尾一样被下轮冲刺稀释。

4
收敛生产 panic! 热点。 优先 cmx-core/model/cell.rs（panic! 20，全工程之最，且在核心数据模型）与 cmx-flow-bpmn/lib.rs——这两处 v3、v4 连续未动。
5
下沉剩余 3 个手写 SQL handler。 model_center.rs（29 SQL 调用 + 14 unwrap）、auth/api_key_handler.rs、oauth2_client_handler.rs——照 DCT/DOC 的 store-pg 范式抽服务层，收口第 8 章「cmx-api 纯 HTTP」违规。
6
提交纪律 + 收尾三项冻结待办 + 刷 README。 避免 git add -A 混提多主题；签名默认值统一开启、数据权限明确「未生效」语义、README 同步 0.1.12/51 crate/新模块清单。

8结语

一句话总结： 本轮是「做对了一件难事」——DCT/DOC 重构在架构判断、破环处理、parity 验证上都达到范式水准，值得作为团队重构模板沉淀。但工程成熟度的天花板不由单次重构决定，而由是否有机制守住成果决定。.env 与 CI 这两件「不写代码」的事没做，分数就只能在 80 出头徘徊。把红线清了、门禁立了，下一版回到 88+ 是顺理成章的。
