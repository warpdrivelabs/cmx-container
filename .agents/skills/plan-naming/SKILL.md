# 方案文档命名规范

当用户使用 `/plan` 或 `/spec` 命令创建方案文档、或编写计划方案时，必须遵循以下命名规范。

---

## 一、命名格式

```
yyyyMMdd_模块名_中文标题.md
```

或（无模块名时）：

```
yyyyMMdd_中文标题.md
```

### 组成部分

| 部分 | 格式 | 必需 | 说明 |
|------|------|------|------|
| 日期 | `yyyyMMdd` | **必需** | 当天日期，6 位或 8 位数字，例如 `20260527` |
| 模块名 | 英文标识 | 可选 | 涉及的 crate 或模块名，如 `cmx-plugin`、`cmx-api`、`cmx-runtime` |
| 中文标题 | 中文描述 | **必需** | 方案的简明中文标题，**禁止使用英文** |

### 分隔符

- 各部分之间使用 **下划线 `_`** 分隔
- 文件扩展名为 `.md`

---

## 二、命名示例

### ✅ 正确示例

| 文件名 | 说明 |
|--------|------|
| `20260527_管控平台插件管理集成方案.md` | 无模块名，纯中文标题 |
| `20260527_cmx-plugin_插件生命周期数据分发方案.md` | 带模块名 |
| `20260527_cmx-api_统一错误码规范.md` | 带模块名 |
| `20260527_数据库迁移优化方案.md` | 无模块名 |

### ❌ 错误示例

| 文件名 | 错误原因 |
|--------|----------|
| `plugin-center-data-integration-plan.md` | 缺少日期前缀，标题为英文 |
| `plan.md` | 缺少日期前缀和中文标题 |
| `20260527_plugin lifecycle.md` | 标题为英文 |
| `plugin-center-plan.md` | 缺少日期前缀，标题为英文 |

---

## 三、执行规则

1. 当用户使用 `/plan` 或 `/spec` 命令、或编写计划方案时，**自动按此规范生成文档名**
2. 从环境信息中获取当天日期作为前缀
3. 根据用户描述的任务内容，判断是否涉及特定模块：
   - 涉及特定 crate -> 加上模块名部分
   - 跨模块或不特定 -> 省略模块名部分
4. 标题部分必须使用中文，从用户的需求描述中提炼简明标题
5. 文档存放路径由调用方或上下文决定，本规范不做约束
