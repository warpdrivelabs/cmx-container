# 配置同步技能

当新增或修改配置项时，必须同步更新对应的文件。配置分为两类：

1. **TOML 配置** — 通过配置文件（`dev.toml` / `config.toml`）管理的配置项
2. **环境变量配置** — 仅通过环境变量注入的配置项（如注册中心、配置中心等敏感信息）

---

## 一、文件结构

| 文件 | 类型 | 说明 |
|------|------|------|
| `config/config_template.toml` | TOML 配置模板 | TOML 配置项的完整模板和默认值 |
| `config/.env.template` | 环境变量参考模板 | 环境变量以 `.env` 格式列出 |
| `config/CONFIG_MANUAL.md` | TOML 配置手册 | TOML 配置项的详细文档 |
| `config/ENV_MANUAL.md` | 环境变量手册 | 环境变量的详细文档 |

### 分离原则

- **TOML 配置**: 可以在 `.toml` 配置文件中设置的项 → 放入 `config/config_template.toml` + `config/CONFIG_MANUAL.md`
- **环境变量配置**: 仅通过环境变量注入、不在 TOML 文件中配置的项 → 放入 `.env.template` + `config/ENV_MANUAL.md`
- **TOML 配置的环境变量覆盖**: TOML 配置项支持的环境变量覆盖方式，在 `config/CONFIG_MANUAL.md` 对应章节末尾说明

---

## 二、触发条件

当用户执行以下操作时，**必须**触发此技能：

- 新增或修改 TOML 配置项 → 更新 `config/config_template.toml` + `config/CONFIG_MANUAL.md`
- 新增或修改环境变量 → 更新 `config/.env.template` + `config/ENV_MANUAL.md`
- 删除配置项或环境变量 → 同步更新对应文件
- 用户明确要求"更新配置文档"、"同步配置"等

---

## 三、注释层级约定

模板文件（`config_template.toml` / `.env.template`）中存在三类注释行，**必须**严格区分层级：

| 层级 | 前缀     | 含义           | 取消注释时           |
|----|--------|--------------|-----------------|
| L1 | `#`    | 结构性注释（分节标题、字段用途、永久说明） | **不应**被批量取消     |
| L2 | `##`   | 示例/可选配置项的描述注释 | 降级为 `#`，**仍为注释** |
| L3 | `#`    | 被注释的配置项本身    | 激活为有效配置         |

**配对规则**：

- 每一组「示例/可选配置项」由 **1 行 L2 + N 行 L3** 组成，结构如：

  ```toml
  ## <配置项用途说明>（默认值 <x>，可选/不推荐...）
  # key1 = "default1"
  # key2 = "default2"
  ```

- L2 行**仅出现在**其紧邻下方的 L3 之前，不可单独存在。
- L2 行**不应用于**结构性注释（如分节标题 `# ============================================`）。
- L2 行**必须**用 `##` 开头，**不要**使用三个或更多 `#`（避免视觉混乱）。
- L2 行的内容应清晰标注「默认值」和「可选/必需/不推荐」属性。

**编辑体验**：

- 用户在 IDE 中选中整块（L2 + L3）执行"取消注释"（VS Code / IntelliJ / Sublime 默认去除每行首部一个 `#`；Vim `gcc` 切换行注释）后：
  - L2 降级为 `# <描述>` → 仍是合法注释，描述不丢失
  - L3 激活为有效配置
- 用户单独取消 L3 不会影响 L2（因为 L2 不属于"被注释的配置项"）。
- 重新注释操作（再加一个 `#`）会得到 `###`，仍是合法注释，可由用户自行简化。

> 背景：当用户**全选并取消注释**时，整组会被一次性激活；引入 L2 `##` 是为了确保
> "激活配置项"与"保留描述注释"在同一动作下同时正确完成。

## 四、操作步骤

### 步骤 1：确定配置类型

判断新增/修改的配置属于哪一类：
- 如果配置可以在 `.toml` 文件中设置 → **TOML 配置**
- 如果配置仅通过环境变量注入 → **环境变量配置**

### 步骤 2：更新模板文件

#### TOML 配置模板 (`config/config_template.toml`)

```toml
# ============================================
# <配置节中文名称>
# ============================================
[<section_name>]
# 配置项说明（可选/必需，默认 <默认值>）   ← L1 结构性注释
key = "default_value"

## 可选配置项说明（默认值 <x>，可选）     ← L2 示例描述注释
# optional_key = "default"              ← L3 被注释配置项
# another_optional = ["a", "b"]
```

- 每个配置节上方添加分隔注释 `# ============================================`（L1 结构性注释）
- 每个**激活**配置项上方添加中文注释说明（L1 结构性注释），标注：是否可选、默认值、用途说明
- **可选 / 示例性**配置项按「L2 + L3」配对呈现：
  - L2 行以 `##` 开头描述该组用途、默认值、是否可选
  - L3 行为 `# config = default` 形式，可被用户全选取消注释后激活
- 必需配置项直接写值（无注释）

#### 环境变量参考模板 (`config/.env.template`)

```bash
# ============================================
# <分类中文名称>（通过环境变量注入）
# ============================================
# 说明文字                                          ← L1 结构性注释

# 变量说明（默认值、用途）                            ← L1 结构性注释
VARIABLE_NAME=default_value
# 变量说明（留空使用内置默认）                          ← L1 结构性注释
OPTIONAL_VAR=

## 不推荐使用的旧变量（已废弃，建议迁移到 NEW_VARIABLE）  ← L2 示例描述注释
# OLD_VARIABLE=                                     ← L3 被注释变量
# ANOTHER_OLD=
```

- `.env` 文件格式，`#` 开头为注释
- **每个激活变量上方必须有 L1 注释说明**：标注默认值、用途、是否可选
- 变量名用大写，`=` 后跟默认值
- 留空表示使用代码内置默认值
- **不推荐 / 废弃的旧变量**按「L2 + L3」配对呈现：
  - L2 行以 `##` 开头，描述废弃原因与对应新变量
  - L3 行为 `# OLD_VAR=` 形式，保留供历史迁移参考
- 严禁使用「单 `#` 描述 + 单 `#` 旧变量」混排形式（取消注释时会把描述也激活）

### 步骤 3：更新手册文件

#### TOML 配置手册 (`config/CONFIG_MANUAL.md`)

```markdown
## <配置节中文名称>

### `[<section_name>]`

#### `<key>`

- **类型**: <类型>
- **必需**: 是/否
- **默认值**: `<默认值>`
- **说明**: <详细说明>
- **示例**: `<示例值>`
```

- 同时更新目录中的条目
- 保持与现有文档风格一致
- 如支持环境变量覆盖，在章节末尾说明格式

#### 环境变量手册 (`config/ENV_MANUAL.md`)

```markdown
## <分类中文名称>

### VARIABLE_NAME

- **类型**: <类型>
- **默认值**: `<默认值>`
- **说明**: <详细说明>
- **示例**: `<示例值>`
```

- 同时更新目录中的条目
- 包含优先级说明和兼容旧变量映射
- 旧变量标注"不推荐"

---

## 五、注意事项

1. **分类准确**: TOML 配置和环境变量配置不要混放
2. **同时更新模板和手册**: 模板文件和手册文件必须同步更新
3. **保持目录完整**: 两个手册文件的目录中需同步添加/修改条目
4. **注释风格一致**: 遵循现有文件的注释风格
5. **不要删除已有内容**: 只追加或修改对应部分
6. **交叉引用**: 如果 TOML 配置项支持环境变量覆盖，在 `config/CONFIG_MANUAL.md` 中注明"详见 [ENV_MANUAL.md](config/ENV_MANUAL.md)"
7. **注释层级一致**: 模板中所有「示例 / 可选 / 废弃」配置项的描述注释**必须**使用 `##`（L2）前缀，
   不允许使用单 `#`（L1）与被注释配置项（L3）混排。code review 与 CI 应检查此项；
   详见 [## 三、注释层级约定](#三注释层级约定)。

---

## 六、验证

更新完成后，检查：

- [ ] TOML 配置项 → `config_template.toml` 和 `config/CONFIG_MANUAL.md` 已同步
- [ ] 环境变量 → `.env.template` 和 `config/ENV_MANUAL.md` 已同步
- [ ] 两个手册文件的目录已更新
- [ ] 所有字段类型、默认值、说明准确无误
- [ ] 不推荐使用的旧变量已标注
- [ ] `.env.template` 中每个激活变量上方都有 L1 注释说明
- [ ] 模板中所有「示例 / 可选 / 废弃」配置项的描述注释均使用 `##`（L2）前缀，与被注释项（L3）严格配对
