# `data/` 目录结构与内容总结

> 本文件汇总 `cmx-container/data/` 下每个子目录存放的文件类型、加载/写入路径、相关 Rust 模块及典型使用场景。
>
> 适用版本：cmx-container（Rust 后端门户 / 设计器业务层），数据根 `data/` 是 CMXPortalManager Node 时代沿用至今的 JSON 文件持久层。
> 数据根由 `cmx-portal-base/src/config.rs` 解析，来源优先级：
> 1. 配置项 `portal.data_root`（`config.toml`）
> 2. 环境变量 `CMX_PORTAL_DATA_ROOT`
> 3. 回退默认 `./data`（相对进程工作目录）

---

## 二、目录详解

### 2.1 `dam-registry/`

**作用**：DAM（Domain / Application / Module）主数据的旧 JSON 持久层。**写路径已废弃**，主数据迁入 `cmx_domain` / `cmx_application` / `cmx_module` 三张表，写操作走 `cmx-biz` 的 Service；此处仅作历史备份。

```
dam-registry/
└── registry.json.bak    # 备份文件，含 version + domains/applications/modules 三类
```

- 加载入口：[cmx-portal/src/dam/mod.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-portal/src/dam/mod.rs) / [store.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-portal/src/dam/store.rs)
- 现存只读 API：`get_dam_registry()` / `list_domains()` / `list_applications()` / `list_modules()`，全部从 DB 查并反向映射回原 `registry.json` 形状
- 旧文件 `registry.json.bak` 字段结构：`{ version, domains:[{id,name,title,icon,status,description}], applications:[…], modules:[{…resourceRoot,manifestPath,aliases,theme,themeColor,…}] }`
- 典型域：`fi` / `hr` / `cr` / `dr` / `sc`；应用：`portal` 等

### 2.4 `form-pages/`

**作用**：CMX 表单设计器（拖拽式 UI 设计器）的版本化存储。**写路径已废弃**，AGENTS 第十八章标记为「禁止参考」。

```
form-pages/
├── pages-list.json                    # 索引：{version, pages:[{id,name,details,latestFormFile}]}
└── sources/
    ├── .gitkeep
    ├── myform_20260504_152820279.json  # 版本源文件：{ "form": "<CMX 表单 JSON 字符串>" }
    └── myform1_20260504_153457002.json
```

- 加载入口：[cmx-form/src/pages/form.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-form/src/pages/form.rs)
- 路径规则：
  - 索引：`form-pages/pages-list.json`
  - 版本源：`form-pages/sources/<id>_<yyyyMMdd>_<HHmmssSSS>.json`
- API：`list_form_pages_paged`（分页列表）/ `save_form_page`（写带时间戳的新版本 + 索引 upsert）/ `get_form_page_by_id`（按 id 找 latestFormFile 再读源）
- 写时序：取全局写锁 → 写新版本源 → 加载列表 → 找到旧行则替换，否则追加 → 持久化列表
- 表单 JSON 是**字符串字段**内嵌（避免重写 `cmx-form` 组件树结构），由前端 JSON.parse 解析

### 2.5 `help/` & `help-src/`

**作用**：门户帮助中心文档。
- `help/` 是**运行时读取的产物**（Rust 直接读 JSON）。
- `help-src/` 是**手写源**（Markdown + YAML frontmatter），由 `scripts/build-help.mjs` 编译为 `help/*.json`。

> 详细格式见 [help-src/README.md](file:///media/yqs/工作/rustspace/cmx/cmx-container/data/help-src/README.md)

```
help/                                  # 运行时读取（由 help-src 编译产出）
├── fi/cmxfico/gl/
│   ├── gl-overview.json
│   ├── master-account.json
│   ├── voucher-entry.json
│   └── voucher-post.json
├── hr/recruit/candidate/
│   └── candidate-intro.json
└── portal/portal/overview/
    ├── getting-started.json
    └── launch-demo.json

help-src/                              # 手写源（Markdown）
├── README.md
├── fi/cmxfico/gl/{gl-overview,master-account,voucher-entry,voucher-post}.md
├── hr/recruit/candidate/candidate-intro.md
└── portal/portal/overview/{getting-started,launch-demo}.md
```

- 加载入口：[cmx-portal/src/help/store.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-portal/src/help/store.rs)
- 路径规则：`help/<domain>/<app>/<module>/<file>.json`，3 段 DAM + 文件
- 源→产物映射：`help-src/<d>/<a>/<m>/<id>.md → help/<d>/<a>/<m>/<id>.json`（目录自动创建）
- 文档结构（HelpDoc）：`{ domain, app, module, file, id, path, title, summary, keywords, order, content, examples:[{title,lang,note,code}], actions, updatedAt }`
  - `path` 是模块内分级目录（斜杠分级）
  - `actions` 是内联可执行动作映射（`wsnode:#key` 链接用）
  - `content` 是 Markdown 正文
  - `examples` 是 property 区样例数组
- API：
  - `get_doc`（按 DAM+file 读完整文档）
  - `list_catalog`（遍历整棵树，投影出轻量目录项，排序 domain/app/module→order→path→id）
  - `save_doc`（原子写，`file` 缺省时由 `id` 推导为 `<id>.json`）
  - `delete_doc`（物理删除）
- 构建脚本：`node scripts/build-help.mjs [--check | --clean]`

- 字段详见《17-元数据 JSON 文件字段详解》

## 三、数据根与路径拼接

- 数据根来源（`cmx-portal-base/src/config.rs::data_root`）：
  1. `ConfigManager::try_global().get_string("portal.data_root")`
  2. `std::env::var("CMX_PORTAL_DATA_ROOT")`
  3. `./data`（相对进程工作目录）
- 路径拼接工具：`data_path(segments)`（`data_root()` + 段数组）
- 全局写锁：`crate::util::write_lock()` 返回 `OnceLock<Mutex<()>>`，所有 store 的写操作（save/delete）均 `let _guard = write_lock().lock().await;` 串行化
- 原子写：`fsutil::write_json_atomic` / `write_text_atomic`（临时文件 + rename 模式）

## 四、典型业务流（举例）

1. **前端打开门户欢迎页** → 读 `html-pages/index.json` → 拿到 `domains=["_legacy","cr","fi"]` → 进入 `fi` 域 → 读 `html-pages/index/fi.pages.json` → 列出该域页面 → 用户点开某页 → 读 `html-pages/sources/<relPath>` 的 HTML
2. **AI 助手「我要录入凭证」** → `cmx-portal::launcher::resolve` → 扫描 `menu-pages/fi/cmxfico/gl/explorer-menu.json` 收集 `workspace-node` 项 → AI/规则匹配 → 命中项取完整 `workspace` 返回 → 前端 `openWorkspaceNode`
3. **凭证录入页加载** → 读 `fact/fi/cmxfico/gl/cmxfico_vouchers.json` 拉数据 + `dict/entries/fi/cmxfico/gl/cf_*.json` 取科目等下拉 + `meta/flexible-combination/fi/cmxfico/gl/account.json` 决定辅助核算列
4. **门户资源解析** → `cmx-portal::meta::modules::list_module_manifests` → DAM 优先（`cmx_module` 表）→ 回退 `modules/**/module.json` → `resolve_module_resource(d,a,m,res_type)` 标注 exists/kind
5. **帮助中心打开** → 读 `help/<d>/<a>/<m>/<id>.json` 完整文档（正文 Markdown + examples）→ `help/**/.../gl-overview.json` 链接 `help:master-account` 站内跳转

## 五、注意事项

1. **旧实现红线**（AGENTS 第十八章）：
   - `data/dict/`、`data/fact/`、`data/form-pages/` 标记为「禁止参考」；写路径已废弃，主数据/凭证/表单页统一走数据库新接口（`/api/dict/*`、`/api/doc/*` 等）
   - 仅做维护兼容，新增功能不得沿用
2. **JSON 文件存储 = 单实例**（[cmx-portal/src/lib.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-portal/src/lib.rs) 顶部注释）：
   - 写安全依赖进程内 `write_lock` 全局锁，**不支持多实例水平扩展**
   - 部署须保证「同一 data root 同一时刻只被一个本服务进程持有」
3. **DAM 已迁库**（`cmx_domain` / `cmx_application` / `cmx_module` 三表），`dam-registry/registry.json.bak` 只读备份
4. **路径安全**：所有 store 入口均校验 DAM 段 `[a-zA-Z0-9_-]+` + file 须 `*.json`；html/native 的 relPath 防 `..` / 绝对 / 反斜杠
5. **帮助中心源 / 产物分离**：`help-src/**/*.md` 是手写源，**不要直接改 `help/**/*.json`**，改完 .md 跑 `scripts/build-help.mjs` 重新生成
6. **HTML 页面双写**：`save_page` 同时写分片 + v1 列表，保证 list 立即可见；读取优先分片，回退 v1
7. **菜单解析**：`menuRef` 点分 → 文件路径（最后一段补 `.json`）；`dam:<d>/<a>[/<m>]` 形式从 DAM + manifest 派生
8. **工作区节点**：`menu-pages` 里的 `type:"workspace-node"` 是「菜单内联配置」（launcher 数据源），`node/nodes.json` 是「用户实际保存过的工作台」（updatedAt 倒序列表）
9. **服务目录**：Bruno 调试集合是辅助开发资源，路径按 DAM 树（domain/app/module）组织，可用 `Bruno CLI` 打开整个目录直接调接口
