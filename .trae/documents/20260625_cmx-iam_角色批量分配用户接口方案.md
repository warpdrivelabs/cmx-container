# 角色批量分配用户接口方案

## 一、背景与目标

当前 cmx-iam / cmx-api 中**不存在「角色 → 用户」方向的批量分配接口**。现有能力仅有：

| 接口                                                     | 方向                 | 语义          |
| ------------------------------------------------------ | ------------------ | ----------- |
| `assign_roles` (`/iam/users/assign-roles`)             | user → roles       | 单用户多角色，全量替换 |
| `assign_permissions` (`/iam/roles/assign-permissions`) | role → permissions | 单角色多权限，全量替换 |

缺失：在角色管理页面选中一个角色，批量勾选用户保存为其最终用户集合的能力。

本方案新增**单接口「角色批量分配用户」**，采用**全量替换**语义（先删后增，事务内处理），并支持**分块批量插入**以应对大数据量。

## 二、设计决策

| 决策点  | 选择                                       | 理由                                                                                       |
| ---- | ---------------------------------------- | ---------------------------------------------------------------------------------------- |
| 接口数  | 单接口                                      | 与现有 `assign-permissions` 对称，语义为「设置该角色的用户集合」                                              |
| 语义   | 全量替换（先 DELETE 后 INSERT）                  | 与 `assign_permissions` / `assign_roles` 完全一致；`user_ids` 空数组表示清空该角色的所有用户                  |
| 用户标识 | `user_id`                                | 与临时角色授权接口一致，无需 username→id 查询转换                                                          |
| 事务   | 全程单事务（删除 + 插入 + 原用户集合查询）                 | 保证原子性，参考 `assign_permissions`(role/service.rs:448) 与 `assign_roles`(user/service.rs:563) |
| 大数据量 | 分块批量插入（`chunks(BATCH_SIZE)` + 多值 INSERT） | 避免 SQL 参数超限（PG 单语句参数上限 65535），提升写入性能；`BATCH_SIZE = 500`                                  |
| 响应体  | `ApiResp<()>`                            | 与 `assign_permissions` 一致（全量替换无需返回 affected）                                             |
| 数据表  | 复用 `cmx_user_role`                       | 已有 `uk_cmx_user_role(user_id, role_id)` 唯一约束与双向索引                                        |
| 缓存失效 | 对「原用户集合 ∪ 新用户集合」失效 user\_cache           | 全量替换会改变多用户的角色归属，需失效受影响用户缓存                                                               |

## 三、接口定义

### 批量给角色分配用户（全量替换）

```
POST /api/iam/roles/assign-users
```

请求体：

```json
{
  "role_id": "角色ID",
  "user_ids": ["user_id_1", "user_id_2", "user_id_3"]
}
```

响应：

```json
{ "code": 0, "data": null }
```

**语义**：

* 将该角色的用户集合**全量设置**为 `user_ids`。

* 事务内：① 查询该角色当前的原用户集合（用于缓存失效）→ ② `DELETE FROM cmx_user_role WHERE role_id = $1` → ③ 按 `BATCH_SIZE` 分块批量 `INSERT` → ④ 提交事务。

* `user_ids` 为空数组 ⇒ 删除该角色全部用户关联（等同清空），合法。

* `ON CONFLICT (user_id, role_id) DO NOTHING` 兜底唯一约束冲突。

### 第 3 层：Service 实现（cmx-iam）

**文件**: `crates/libs/cmx-iam/src/role/service.rs`

* 在 `assign_permissions` 实现（行 448-520）之后新增实现。`RoleServiceImpl` 已具备所需字段（`mm`、`db_id`、`audit`、`rule_enforcer`、`permission_checker`）。

**实现伪代码**（参考 `assign_permissions` 行 448-520 + `assign_roles` 行 563-651）：

```rust
const ROLE_USERS_INSERT_BATCH: usize = 500;

async fn assign_role_users(
    &self,
    svr_ctx: &SVRContext,
    role_id: &str,
    user_ids: &[String],
) -> Result<(), TraitError> {
    debug!("...assign_role_users role: {}, user_count: {}", role_id, user_ids.len());

    // 1. 开启事务
    let txn_ctx = self.mm.get_transaction_context();
    let guard = txn_ctx.begin_with_guard(&self.db_id).await
        .map_err(|e| TraitError::from(IamError::Business(format!("事务开始失败: {e}"))))?;
    let txn_id = guard.txn_id();

    // 2.（可选）SoD 校验：若 rule_enforcer 存在，对每个 user 调用
    //    check_user_roles(user_id, &[role_id]) —— 参考 user/service.rs:598-603

    // 3. 【事务内】先查询「原用户集合」，供提交后缓存失效使用
    //    必须在 DELETE 之前查，否则提交后查到的是新集合，会漏掉被移除的旧用户。
    //    注意：不能用 invalidate_role_cache(role_id)，它内部也是查当前表，同样漏旧用户。
    let select_sql = "SELECT user_id FROM cmx_user_role WHERE role_id = $1";
    let ds = self.mm.query_sql_with_datavalues(
        &self.db_id, Some(txn_id), select_sql,
        vec![DataValue::String(role_id.to_string())], "old_role_users",
    ).await.map_err(|e| TraitError::from(IamError::Business(format!("查询原用户集合失败: {e}"))))?;
    let schema = ds.schema.as_ref();
    let mut old_user_ids: Vec<String> = Vec::new();
    for row in ds.iter() {                       // 多行遍历模式，参考 iam_checker.rs:236-241
        if let Some(uid) = row.get_by_name_as::<String>(schema, "user_id") {
            old_user_ids.push(uid);
        }
    }

    // 4. 物理删除旧关联（全量替换）
    let delete_sql = "DELETE FROM cmx_user_role WHERE role_id = $1";
    self.mm.execute_sql_with_datavalues(&self.db_id, Some(txn_id), delete_sql, vec![DataValue::String(role_id.into())])
        .await.map_err(|e| TraitError::from(IamError::Business(format!("删除旧用户关联失败: {e}"))))?;

    // 5. 分块批量插入新关联（ON CONFLICT 兜底）—— 多值 INSERT 方案
    for chunk in user_ids.chunks(ROLE_USERS_INSERT_BATCH) {
        let n = chunk.len();
        // 动态拼装占位符："($1,$2,$3,0),($4,$5,$6,0),..."
        let values_clause = (0..n).map(|i| {
            let b = i * 3;
            format!("(${},${},${},0)", b + 1, b + 2, b + 3)
        }).collect::<Vec<_>>().join(",");
        let insert_sql = format!(
            "INSERT INTO cmx_user_role (id,user_id,role_id,archived) VALUES {} \
             ON CONFLICT (user_id, role_id) DO NOTHING",
            values_clause
        );
        // 参数列表：每行 [id, uid, role_id]
        let mut params: Vec<DataValue> = Vec::with_capacity(n * 3);
        for uid in chunk {
            params.push(DataValue::String(snowflake_id_str()));  // id
            params.push(DataValue::String(uid.clone()));          // user_id
            params.push(DataValue::String(role_id.to_string()));  // role_id
        }
        self.mm.execute_sql_with_datavalues(&self.db_id, Some(txn_id), &insert_sql, params)
            .await.map_err(|e| TraitError::from(IamError::Business(format!("批量插入用户角色关联失败: {e}"))))?;
    }

    // 6. 提交事务
    guard.commit().await
        .map_err(|e| TraitError::from(IamError::Business(format!("事务提交失败: {e}"))))?;

    // 7. 审计日志
    let audit_detail = serde_json::json!({ "role_id": role_id, "user_ids": user_ids });
    self.audit_write(svr_ctx, "assign_role_users", "role", role_id, &audit_detail).await;

    // 8. 批量失效缓存：对 old_user_ids ∪ new user_ids 逐个失效
    //    （被移除的旧用户角色集已变，必须失效；参考 revoke_temp_roles_batch:1010-1015）
    if let Some(checker) = &self.permission_checker {
        let mut done: std::collections::HashSet<&str> = std::collections::HashSet::new();
        for uid in old_user_ids.iter().chain(user_ids.iter()) {
            if done.insert(uid.as_str()) {   // 去重，避免对保留用户重复失效
                checker.invalidate_user_cache(uid).await;
            }
        }
    }

    info!(role_id = role_id, user_count = user_ids.len(), "角色用户分配成功");
    Ok(())
}
```

**分块多值 INSERT 实现说明**：

* 每个 chunk 有 `n` 个用户，每行 3 个参数 ⇒ 共 `3n` 个占位符（`$1..$3n`），由 `format!` 动态拼出。

* `execute_sql_with_datavalues` 的 sql 参数接受 `&str`，故用 `&insert_sql`（`String` 的引用）传入，非必须字面量。

* PG 参数上限 65535，每行 3 参数 ⇒ 单 chunk 理论上限 21845 行；取 `500` 远低于上限，安全。

* `snowflake_id_str()` 已在 service.rs 顶部引入（行 15），直接复用。

/// 批量给角色分配用户（全量替换）
#[utoipa::path(
    post,
    path = "/api/iam/roles/assign-users",
    request_body = AssignRoleUsersRequest,
    responses(
        (status = 200, description = "分配成功", body = ApiResp<serde_json::Value>)
    ),
    tag = "IAM-Role"
)]
pub async fn assign_role_users(
    State(cmx_state): State<CmxAppState>,
    CmxSvrContext(svr_ctx): CmxSvrContext,
    Json(req): Json<AssignRoleUsersRequest>,
) -> Result<Json<ApiResp<()>>> {
    debug!(
        "{:<12} - handler::assign_role_users - role: {}, user_count: {}",
        "HANDLER", req.role_id, req.user_ids.len()

    iam.role_service
        .assign_role_users(&svr_ctx, &req.role_id, &req.user_ids)
        .await
        .map_err(|e| Error::business_error(e.to_string()))?;
    Ok(Json(ApiResp::ok(())))
}

## 六、假设与边界

* 不新增数据库表/索引，复用现有 `cmx_user_role`。

* 全量替换语义：调用后该角色的用户集合 == 请求 `user_ids`；空数组 = 清空。

* 不做强校验「user\_id 是否存在」（与 `assign_permissions` 不强校验权限存在性一致）。

* SoD 校验为可选增强，仅当 `rule_enforcer` 注入时对每个用户生效。

* 分块插入采用多值 INSERT（`BATCH_SIZE = 500`），`execute_sql_with_datavalues` 接受动态 `&str` SQL，参数由 `format!` 拼装。

* `DataValue`、`snowflake_id_str` 均已在 role/service.rs 顶部引入（行 12、15），无需新增 import。

* `audit_write` 来自 `AuditHelper` trait，RoleServiceImpl 已实现该 trait（assign\_permissions 已调用），可直接复用。
