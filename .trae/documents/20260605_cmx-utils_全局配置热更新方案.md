# 全局配置热更新方案

## 一、概述

当 Nacos 配置中心发生配置变更时，当前系统仅通过 `GlobalChangeNotifier` 打印日志，无法将新配置实际应用到运行中的 `ConfigManager`。本方案设计一套企业级配置热更新机制，使配置变更能够覆盖全局配置并通知业务模块刷新。

---

## 二、现状分析

### 2.1 核心瓶颈

| 问题 | 位置 | 说明 |
|------|------|------|
| `ConfigManager` 不可变 | `cmx-utils/src/config/config_impl.rs:665` | `OnceLock<Config>` 初始化后无法更新 |
| 通知器只传原始字符串 | `cmx-registry-config/src/notifier.rs` | 回调签名 `Fn(&str)` 无法提供结构化变更信息 |
| 业务模块各自缓存 | `web-server/src/config/mod.rs:32` 等 | 各模块用 `OnceLock` 缓存配置子集，即使全局刷新也不会更新 |
| 无变更比对能力 | - | 无法知道哪些 key 发生了变化 |

### 2.2 当前配置流转链路

```
Nacos Server 变更
  -> nacos-sdk ConfigChangeListener
    -> ConfigChangeCallback (Fn(&str))
      -> GlobalChangeNotifier::notify(content: &str)
        -> "default" handler: 仅打印日志 ✅
        -> 无其他处理器 ❌
        -> ConfigManager 未更新 ❌
        -> 业务模块未感知 ❌
```

### 2.3 影响范围

共 21 个文件使用 `ConfigManager::global()`，4 个文件使用 `ConfigManager::try_global()`。

---

## 三、方案设计

### 3.1 目标架构

```
Nacos Server 变更
  -> nacos-sdk ConfigChangeListener
    -> GlobalChangeNotifier::notify(content)
      -> "config_reloader" handler: 解析 + 构建 + 刷新 ConfigManager ✅
      -> "default" handler: 打印日志 ✅
      -> 业务 handler (各模块注册): 收到 ConfigChangeEvent，按需刷新 ✅
```

### 3.2 分层设计

```
┌──────────────────────────────────────────────────┐
│  Layer 3: 业务模块 (各 crate config 模块)          │
│  - 实现 ConfigChangeListener trait                │
│  - 按需刷新 OnceLock 缓存                         │
├──────────────────────────────────────────────────┤
│  Layer 2: 配置变更通知 (cmx-registry-config)       │
│  - ConfigChangeEvent (结构化变更事件)               │
│  - ConfigChangeListener trait                     │
│  - EnhancedChangeNotifier (增强版通知器)            │
├──────────────────────────────────────────────────┤
│  Layer 1: 配置存储 (cmx-utils)                     │
│  - ConfigManager: 支持原子替换的配置存储             │
│  - ConfigReloader: 解析 + 合并 + 刷新              │
└──────────────────────────────────────────────────┘
```

## 四、详细设计

### 4.1 Layer 1: ConfigManager 可重载化

**文件**: `crates/libs/cmx-utils/src/config/config_impl.rs`

**改动**: 将 `OnceLock<Config>` 替换为 `OnceLock<RwLock<Arc<Config>>>`，支持原子替换。

```rust
// 之前
static GLOBAL_CONFIG: OnceLock<Config> = OnceLock::new();

// 之后
static GLOBAL_CONFIG: OnceLock<RwLock<Arc<Config>>> = OnceLock::new();
```

**ConfigManager API 变更**:

| 方法 | 之前返回 | 之后返回 | 说明 |
|------|---------|---------|------|
| `initialize()` | `Result<(), ConfigError>` | 不变 | 初始化逻辑调整，存入 `Arc::new(config)` |
| `global()` | `&'static Config` | `Arc<Config>` | 读取通过 `RwLock` + `Arc` clone，开销极低 |
| `try_global()` | `Option<&'static Config>` | `Option<Arc<Config>>` | 同上 |
| `reload(config)` | 不存在 | `Result<(), ConfigError>` | **新增**，原子替换全局配置 |
| `is_initialized()` | `bool` | 不变 | - |

**关键实现**:

```rust
impl ConfigManager {
    /// 原子替换全局配置
    ///
    /// 用于配置热更新场景，将新的配置实例替换全局配置。
    /// 旧的 Arc 引用在所有持有者释放后自动回收。
    pub fn reload(config: Config) -> Result<(), ConfigError> {
        let guard = GLOBAL_CONFIG.get().ok_or(ConfigError::BuildError {
            message: "配置管理器未初始化".to_string(),
        })?;
        let mut lock = guard.write().map_err(|_| ConfigError::BuildError {
            message: "配置管理器锁获取失败".to_string(),
        })?;
        *lock = Arc::new(config);
        Ok(())
    }

    /// 获取全局配置实例（Arc 引用，开销极低）
    pub fn global() -> Arc<Config> {
        let guard = GLOBAL_CONFIG.get()
            .expect("配置管理器未初始化，请先调用 ConfigManager::initialize()");
        lock.read().unwrap().clone()
    }
}
```

**消费端适配**:

`Arc<Config>` 实现了 `Deref<Target = Config>`，所以绝大多数调用点只需改类型声明，方法调用不变：

```rust
// 之前
let config = ConfigManager::global();
let port = config.get_string("server.port")?;

// 之后（完全相同，Arc<Config> 自动 deref）
let config = ConfigManager::global();
let port = config.get_string("server.port")?;
```

需要显式改类型的场景（约 5 处）：
- 函数参数声明 `&'static Config` → `Arc<Config>`
- `OnceLock` 缓存中存储 `&'static Config` 的地方

### 4.2 Layer 2: 结构化配置变更通知

**文件**: `crates/libs/cmx-infra/cmx-registry-config/src/notifier.rs`

**改动**: 扩展通知器，支持结构化变更事件。

#### 4.2.1 ConfigChangeEvent

```rust
/// 配置变更事件
pub struct ConfigChangeEvent {
    /// 变更的配置键列表
    pub changed_keys: Vec<String>,
    /// 新的配置内容（原始 TOML 字符串）
    pub raw_content: String,
}
```

#### 4.2.2 ConfigChangeListener trait

```rust
/// 配置变更监听器
///
/// 业务模块实现此 trait 以接收结构化的配置变更通知。
pub trait ConfigChangeListener: Send + Sync {
    /// 监听器名称（用于日志和调试）
    fn name(&self) -> &str;

    /// 感兴趣的配置键前缀（空表示监听所有变更）
    fn interested_keys(&self) -> &[String] {
        &[]
    }

    /// 配置变更回调
    fn on_change(&self, event: &ConfigChangeEvent);
}
```

#### 4.2.3 ChangeNotifier 扩展

在现有 `ChangeNotifier` 基础上增加 typed listener 支持：

```rust
pub struct ChangeNotifier {
    // 原有：原始字符串回调
    handlers: RwLock<HashMap<String, ConfigChangeCallback>>,
    // 新增：结构化监听器
    listeners: RwLock<Vec<Arc<dyn ConfigChangeListener>>>,
}

impl ChangeNotifier {
    /// 注册结构化配置变更监听器
    pub fn add_listener(&self, listener: Arc<dyn ConfigChangeListener>) {
        let mut listeners = self.listeners.write().unwrap();
        info!("注册配置变更监听器: {}", listener.name());
        listeners.push(listener);
    }

    /// 通知所有处理器和监听器
    pub fn notify_with_event(&self, event: &ConfigChangeEvent) {
        // 先通知原始回调（向后兼容）
        self.notify(&event.raw_content);

        // 再通知结构化监听器
        let listeners = self.listeners.read().unwrap();
        for listener in listeners.iter() {
            let interested = listener.interested_keys();
            let should_notify = interested.is_empty()
                || event.changed_keys.iter().any(|k| {
                    interested.iter().any(|prefix| k.starts_with(prefix))
                });

            if should_notify {
                match std::panic::catch_unwind(AssertUnwindSafe(|| {
                    listener.on_change(event)
                })) {
                    Ok(_) => {}
                    Err(e) => {
                        warn!("配置变更监听器 [{}] 执行异常: {:?}", listener.name(), e);
                    }
                }
            }
        }
    }
}
```

### 4.3 Layer 1+2: ConfigReloader 配置重载器

**文件**: `crates/libs/cmx-infra/cmx-registry-config/src/reloader.rs`（新增）

**职责**: 接收远程配置变更，解析并构建新 Config，调用 `ConfigManager::reload()` 刷新全局配置。

```rust
/// 配置重载器
///
/// 注册到 GlobalChangeNotifier，当远程配置变更时：
/// 1. 解析新 TOML 内容
/// 2. 与本地配置合并（保留本地文件和环境变量优先级）
/// 3. 调用 ConfigManager::reload() 原子替换全局配置
/// 4. 通过 ChangeNotifier 通知业务监听器
pub struct ConfigReloader {
    /// 本地配置文件路径（用于合并）
    config_file_path: Option<String>,
}
```

**核心 reload 流程**:

```rust
impl ConfigReloader {
    pub async fn reload(&self, new_content: &str) -> Result<Vec<String>, ConfigCenterError> {
        // 1. 记录旧配置的 key 集合
        let old_config = ConfigManager::global();
        let old_keys: HashSet<String> = old_config.keys().collect();

        // 2. 构建新配置：本地 TOML + 新远程配置 + 环境变量
        let mut builder = ConfigBuilder::new();

        // 2a. 本地 TOML 文件（不变）
        if let Some(path) = &self.config_file_path {
            builder = builder.add_toml_file(path);
        }

        // 2b. 新的远程配置内容（替换）
        let source = RemoteConfigSource::from_toml_str(new_content)?;
        builder = builder.add_source(source);

        // 2c. 环境变量（不变，保持最高优先级）
        builder = builder.add_env();

        // 3. 构建并验证新配置
        let new_config = builder.build()
            .map_err(|e| ConfigCenterError::ParseFailed(
                format!("配置重载构建失败: {}", e)
            ))?;

        // 4. 计算变更 key 列表
        let new_keys: HashSet<String> = new_config.keys().collect();
        let changed_keys: Vec<String> = old_keys
            .symmetric_difference(&new_keys)
            .chain(
                old_keys.intersection(&new_keys).filter(|k| {
                    old_config.get(k) != new_config.get(k)
                })
            )
            .cloned()
            .collect();

        // 5. 原子替换全局配置
        ConfigManager::reload(new_config)?;

        Ok(changed_keys)
    }
}
```

### 4.4 Layer 3: infra_init.rs 集成

**文件**: `crates/web/web-server/src/config/infra_init.rs`

**改动**: 在 `setup_config_listener()` 中注册 ConfigReloader。

```rust
async fn setup_config_listener(
    config_center: &Arc<dyn ConfigCenter>,
    cc_config: &ConfigCenterFullConfig,
) {
    if !config_center.is_enabled() {
        info!("配置中心未启用，跳过配置监听注册");
        return;
    }

    GlobalChangeNotifier::initialize();

    // 注册配置重载器（优先级最高，先于其他 handler 执行）
    let config_file_path = std::env::var("CONFIG_FILE").ok();
    let reloader = Arc::new(ConfigReloader::new(config_file_path));
    GlobalChangeNotifier::register("config_reloader", {
        let reloader = reloader.clone();
        Arc::new(move |content: &str| {
            let reloader = reloader.clone();
            let content = content.to_string();
            tokio::spawn(async move {
                match reloader.reload(&content).await {
                    Ok(changed_keys) => {
                        info!("配置热更新成功，变更 key: {:?}", changed_keys);
                        // 通知结构化监听器
                        let event = ConfigChangeEvent {
                            changed_keys,
                            raw_content: content,
                        };
                        GlobalChangeNotifier::notify_with_event(&event);
                    }
                    Err(e) => {
                        warn!("配置热更新失败: {}，保留当前配置", e);
                    }
                }
            });
        })
    });

    // 注册默认日志处理器
    GlobalChangeNotifier::register("default", Arc::new(|content: &str| {
        info!("检测到远程配置变更，内容长度: {} 字节", content.len());
    }));

    // ... 后续监听注册不变
}
```

### 4.5 业务模块适配示例

以 `WebConfig` 为例，展示业务模块如何支持热更新：

```rust
// web-server/src/config/mod.rs

use cmx_registry_config::{ConfigChangeEvent, ConfigChangeListener};

pub struct WebConfigListener;

impl ConfigChangeListener for WebConfigListener {
    fn name(&self) -> &str { "web_config" }

    fn interested_keys(&self) -> &[String] {
        static KEYS: &[String] = &[];
        KEYS // 监听所有变更
    }

    fn on_change(&self, event: &ConfigChangeEvent) {
        if event.changed_keys.iter().any(|k| k.starts_with("web_")) {
            info!("Web 配置已变更，下次请求将使用新配置");
            // 如果 WebConfig 也需要支持刷新，可替换 OnceLock 为 RwLock
        }
    }
}
```

## 六、设计决策与假设

### 6.1 设计决策

| 决策 | 选项 | 选择理由 |
|------|------|---------|
| 全局配置存储方式 | `RwLock<Arc<Config>>` vs `arc-swap` crate | 避免引入新依赖，`RwLock<Arc<Config>>` 足以满足需求，读开销仅一次 Arc clone（原子计数器 +1） |
| reload 失败策略 | 保留旧配置 vs panic | 保留旧配置，仅 warn 日志，确保服务可用性 |
| 环境变量优先级 | reload 时重新读取 vs 固定启动时值 | 重新读取，保持"环境变量 > 远程配置 > 本地文件"的优先级不变 |
| 通知模式 | 同步通知 vs 异步通知 | ConfigReloader 使用 `tokio::spawn` 异步执行，避免阻塞 Nacos 监听线程 |
| 向后兼容 | 保留 `Fn(&str)` 回调 vs 全部改为 typed | 保留原始回调机制，新增 typed listener，渐进式迁移 |

### 6.2 假设

1. 配置变更频率较低（秒级以上），`RwLock` 写锁竞争可忽略
2. 业务模块的 `OnceLock` 缓存不需要全部改为可刷新（仅关键模块按需改造）
3. 配置变更时不需要重启服务，但部分配置（如数据库连接池）可能需要模块自行重建连接
