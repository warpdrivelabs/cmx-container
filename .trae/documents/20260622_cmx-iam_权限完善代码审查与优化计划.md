## 二、审查报告

### 2.1 严重问题（Critical）

#### C1: `has_permission` 缓存逻辑存在严重缺陷

- **文件**: [iam_checker.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-iam/src/iam_checker.rs#L310-L316)
- **问题**: 缓存未命中时，DB 查询到目标权限后仅缓存单个权限码 `&[permission_code.to_string()]`，而非用户完整权限列表。下次检查不同权限码时缓存命中但返回 false（因缓存中只有第一个权限码），导致**有效权限被错误拒绝**。
- **方案要求**: 3.4.2 节"读流程：先查 Redis，命中则反序列化返回；未命中查 DB 并回填 Redis"——应查询用户完整权限列表并缓存。
- **影响**: 缓存命中率极低且产生假阴性，权限校验不正确。

#### C2: `assign_temp_role` 缺少 SoD 规则校验

- **文件**: [user/service.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-iam/src/user/service.rs#L693-L777)
- **问题**: 分配临时角色时未调用 `RuleEnforcer::check_user_roles`。
- **方案要求**: 3.1.3 节"校验时机"明确指出"临时角色分配 `assign_temp_role`：同样调用 `check_user_roles`"。
- **影响**: 临时角色分配可绕过 SoD 规则，安全漏洞。

### 2.2 高优先级问题（High）

#### H1: `revoke_temp_roles_batch` 缺少缓存失效

- **文件**: [user/service.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-iam/src/user/service.rs#L852-L908)
- **问题**: 单个 `revoke_temp_role` 会失效用户缓存，但批量版本不会。批量撤销后缓存中仍是旧权限，最长 300 秒后才过期。
- **修复**: 循环中收集受影响的 `user_id`，循环结束后批量失效缓存。

#### H2: `revoke_temp_roles_batch` 缺少事务

- **文件**: [user/service.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-iam/src/user/service.rs#L852-L908)
- **问题**: 循环执行 UPDATE 无事务保护，中途失败导致部分撤销部分未撤销。
- **修复**: 用事务包裹批量操作。

#### H3: `handle_circuit_open` FailOpen SQL 缺少角色状态检查

- **文件**: [iam_checker.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-iam/src/iam_checker.rs#L191-L206)
- **问题**: FailOpen 降级查询 `system:all` 的 SQL 未 JOIN `cmx_role` 表，缺少 `r.archived = 0 AND r.status = 1` 检查，与正常路径（L250-L269）不一致。
- **影响**: 熔断降级时可能通过已禁用/归档的角色放行 `system:all`。

#### H4: 缺少 `page` 和 `validate` 两个规则 API

- **文件**: [rule/mod.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-api/src/handlers/iam/rule/mod.rs)
- **问题**: 方案 6.1.2 节定义 9 个规则 API，实际仅实现 7 个。缺少：
  - `POST /iam/permission-rules/page`（分页查询规则）
  - `POST /iam/permission-rules/validate`（规则校验测试）

### 2.3 中优先级问题（Medium）

#### M1: `SodCheckScope::Incremental` 未实际实现

- **文件**: [enforcer.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-iam/src/rule/enforcer.rs#L329-L333)
- **问题**: `All` 和 `Incremental` 两个分支执行完全相同的逻辑（校验合并后完整集合），`Incremental` 选项无效。
- **修复**: `Incremental` 应仅校验本次新增权限（role_ids 展开后的权限）是否违反规则，不校验已有权限。

#### M2: `get_user_role_codes` 和 `has_role` 未使用缓存

- **文件**: [iam_checker.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-iam/src/iam_checker.rs#L326-L442)
- **问题**: 方案 3.4.2 节定义了 `iam:role:{user_id}` 缓存 key，但 `has_role` 和 `get_user_role_codes` 从未读写缓存。
- **修复**: 增加 `get_user_role_codes_cached` 方法，在 `has_role` 中使用。

#### M3: 临时角色操作审计日志 `target_id` 不正确

- **文件**: [user/service.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-iam/src/user/service.rs#L825-L902)
- **问题**: 方案 3.2.6 节指定 `target_id` 应为 `user_id`，但：
  - `revoke_temp_role`（L825）: 用 `assignment_id` 作 target_id
  - `revoke_temp_roles_batch`（L902）: 用 `"batch"` 作 target_id
  - `extend_temp_role`（L979）: 用 `assignment_id` 作 target_id
- **修复**: 查询 assignment 对应的 user_id，用作 target_id。

#### M4: `scheduler.rs` 缺少过期审计日志

- **文件**: [scheduler.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-iam/src/scheduler.rs#L52-L73)
- **问题**: 方案 3.2.4 节要求"每批失效记录需写入审计日志（action=`temp_role_expired`）"，实现仅记录 info 日志。
- **修复**: 清理后查询失效记录，按 `audit_batch_size` 聚合写入审计日志。

#### M5: `get_role_permission_ids` 使用 N+1 查询

- **文件**: [enforcer.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-iam/src/rule/enforcer.rs#L148-L172)
- **问题**: 对每个 `role_id` 执行单独 SQL 查询，N 个角色 N 次查询。
- **修复**: 改为单次查询 `WHERE role_id = ANY($1)`。

### 2.4 低优先级问题（Low）

#### L1: `EffectivePermissionsResponse` 缺少 `upcoming_expirations` 字段

- **文件**: [service_traits.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-iam/src/service_traits.rs#L49-L56)
- **问题**: 方案 3.3.3 节定义 `AssignmentSummary` 含 `upcoming_expirations`（7天内将过期），实际缺少此字段。也缺少 `AssignmentSummary` 嵌套结构。
- **修复**: 添加 `upcoming_expirations: u32` 字段及对应查询逻辑。

#### L2: `PermissionUsageStat` 缺少 `last_assigned_at` 字段

- **文件**: [service_traits.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-iam/src/service_traits.rs#L90-L96)
- **问题**: 方案 3.3.3 节定义含 `last_assigned_at: Option<DateTime<Utc>>`，实际缺少。
- **修复**: 添加字段并在查询中返回。

#### L3: `create_rule` 规则项插入缺少事务

- **文件**: [rule/service.rs](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-iam/src/rule/service.rs#L210-L259)
- **问题**: 先插入规则，再循环插入规则项，无事务保护。规则项插入失败则规则已创建但不完整。
- **修复**: 用事务包裹规则 + 规则项的插入。

## 三、优化实施计划

### 3.1 第一轮修复（严重 + 高优先级）
