## 二、新发现的问题

### 2.1 IAM 服务的 db_id 来源未说明 — P1 实现级矛盾

**问题**：方案 5.4 决策"用户/角色/权限表放在共享认证数据库中"。但当前所有 handler 通过 `get_db_id_from_header(&headers)` 从请求头获取 db_id 来操作对应业务库（见 [rest/handler.rs:46](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-api/src/rest/handler.rs#L46)）：

```rust
let mm = get_default_db_manager();
let db_id = get_db_id_from_header(&headers).await;  // 从 header 取业务库 db_id
GenericCrudService::<MC>::create(mm, &db_id, None, data).await?;
```

这意味着 IAM handler（用户/角色/菜单/组织 CRUD）面临矛盾：
- 如果 IAM handler 也用 `get_db_id_from_header` → 操作的是 header 指定的**业务库**，而非共享认证库
- 如果 IAM handler 用固定的认证库 db_id → 需要一套不同的 db_id 获取逻辑

方案没有说明认证库的 db_id 如何确定。可能的选项：
1. 认证库就是 default 数据源（`DatabaseManager` 的 default_db_id），IAM 操作固定使用它
2. 认证库是独立的数据源，需要配置专用的 db_id（如 `"auth"`）
3. IAM 表和业务表在同一个数据库中（共享 default 数据源）

**建议**：方案 5.4 应补充认证库 db_id 的确定方式，以及 IAM handler 如何获取它（而非从 header 获取业务 db_id）。

### 2.2 ServiceResult<T> 的定义位置未明确 — P2

**问题**：方案 6.2 定义了 `ServiceResult<T>` 作为协议无关的统一响应模型，但未说明它定义在哪个 crate。

- 如果定义在 `cmx-biz` → cmx-auth、cmx-iam 也需要返回 ServiceResult，但它们不依赖 cmx-biz
- 如果定义在 `cmx-api-types` → 所有业务 crate 都能访问（cmx-api-types 依赖少，位置合适）
- 如果定义在 `cmx-core` → 同样所有 crate 可访问，但 cmx-core 当前不包含响应模型概念

**建议**：明确 `ServiceResult<T>` 定义在 `cmx-api-types` 中（与 `ApiResp<T>` 同级），业务 crate 通过依赖 cmx-api-types 使用它。或者定义在 `cmx-core` 中，作为更基础的协议无关类型。

### 2.3 execute_service 签名与当前 Orchestrator 实现不匹配 — P2

**问题**：方案 9.2.C 给出的 `execute_service` 签名：

```rust
pub async fn execute_service(
    runtime, plugin_query, service_query, service_storage,
    svr_ctx, service_key, flow: &FlowJson,  // ← flow 参数
) -> Result<Value, BizError>
```

但当前 [Orchestrator](file:///media/yqs/工作/rustspace/cmx/cmx-container/crates/libs/cmx-service/src/orchestrator) 的实际执行逻辑是：传入 `service_key` → 通过 `ServiceQuery` 内部获取编排定义（Flow JSON），**不需要外部传入 flow**。同时 Orchestrator 构造还需要 `default_db_id` 参数，签名中缺失。

**建议**：
1. 移除 `flow: &FlowJson` 参数（编排定义由内部通过 service_key 查询获取）
2. 补充 `default_db_id: &str` 参数（Orchestrator 构造需要）

### 2.4 配置同步流程未提及 — P3 流程遗漏

**问题**：方案新增 `cmx-auth`、`cmx-iam`、`cmx-audit` 三个 crate，各自包含 `config.rs`（JWT secret、token 过期时间、密码策略等）。根据项目 [config-sync 规范](file:///media/yqs/工作/rustspace/cmx/cmx-container/.trae/skills/config-sync/SKILL.md)，新增配置项必须同步到：
- `config/config_template.toml`
- `config/.env.template`
- `config/CONFIG_MANUAL.md`
- `config/ENV_MANUAL.md`

方案的实施阶段（第十一章）未提及配置同步步骤。

**建议**：在实施阶段 4（认证系统）和 5（IAM 核心）中增加"配置项同步到模板文件"的产出项。
