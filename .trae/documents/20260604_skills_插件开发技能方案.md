# 插件开发技能方案

## 概述

创建两个新的 AI 技能（Skill），以渐进式披露方式指导 AI 开发 WASM 插件：

1. **wasm-plugin-developer** — 插件工程结构指南（技能1）
2. **plugin-metadata-generator** — 元数据和种子数据生成器（技能3）

技能2（service-orchestration-generator）已存在，无需创建。

***

## 一、当前状态分析

### 1.1 现有技能结构

* 路径：`.trae/skills/{skill-name}/SKILL.md`

* 格式：YAML frontmatter（name + description）+ Markdown 正文

* 命名：kebab-case 目录名，固定 `SKILL.md` 文件名

* 现有 12 个技能

### 1.2 关键发现

**表结构文件位置**：cmx-account 实际结构中，`account_tables.json` 位于 `metadata/` 目录（非 `config/`）。`config/account_config.json` 中的 `files` 字段仅引用文件名，加载器自动从 `metadata/` 目录查找。

**FieldType 完整列表**（来自 cmx-metadata/src/ddl/postgres.rs）：

| field\_type | PostgreSQL 类型             | 说明             |
| ----------- | ------------------------- | -------------- |
| String      | VARCHAR(length) 或 TEXT    | 字符串，需指定 length |
| Int         | BIGINT                    | 整数             |
| Float       | DOUBLE PRECISION          | 浮点数            |
| Decimal     | NUMERIC(precision, scale) | 精确小数           |
| DateTime    | TIMESTAMP WITH TIME ZONE  | 日期时间           |
| Date        | DATE                      | 日期             |
| Bool        | BOOLEAN                   | 布尔值            |
| Text        | TEXT                      | 长文本            |
| Binary      | BYTEA                     | 二进制数据          |
| Array       | JSONB                     | 数组             |
| Json        | JSONB                     | JSON 数据        |
| Uuid        | UUID                      | UUID 标识符       |
| Unknown     | TEXT                      | 未知类型           |

**ColumnDefine 完整字段**（来自 cmx-core model）：

```json
{
  "name": "列名",
  "label": "显示名称",
  "field_type": "FieldType枚举值",
  "is_primary_key": false,
  "is_nullable": true,
  "default_value": null,
  "i18n": false,
  "length": 64,           // 仅 String 类型需要
  "db_type": "VARCHAR(64)", // PostgreSQL 类型声明
  "ordinal": 1,           // 列顺序
  "is_foreign_key": false,
  "foreign_key_table": null,
  "foreign_key_column": null,
  "extensions": {}
}
```

## 二、技能设计方案

### 2.1 技能1：wasm-plugin-developer

**路径**：`.trae/skills/wasm-plugin-developer/SKILL.md`

**定位**：插件开发的总入口指南，采用渐进式披露方式：

* 第一层：工程目录结构全景

* 第二层：每个目录的详细规范

* 第三层：代码架构和 manifest.json 规范

* 第四层：指引使用其他技能生成具体内容

**内容大纲**：

```
# WASM 插件开发指南

## 一、工程目录结构全景
  - 完整目录树（参照 cmx-account）
  - 各目录用途速查表

## 二、目录详细规范
  ### 2.1 config/ — 表定义配置
    - account_config.json 格式规范
    - files 字段引用 metadata/ 下的文件名
    - seed_data 配置规范
  ### 2.2 metadata/ — 表结构定义
    - account_tables.json 格式规范（概述，详细规范引用技能3）
  ### 2.3 seeddata/ — 种子数据
    - JSON/CSV 格式说明（概述，详细规范引用技能3）
  ### 2.4 servicedata/ — 服务编排
    - 每个文件对应一个接口
    - code 字段为服务唯一标识
    - 引用 service-orchestration-generator 技能
  ### 2.5 预留目录
    - formdata/ — 表单配置
    - menudata/ — 菜单配置
    - permdata/ — 权限数据（预留）
    - flowdata/ — 流程定义数据（预留）

## 三、manifest.json 规范
  - 完整字段说明表
  - 必填/选填标注
  - 域/应用/模块编码约定

## 四、代码架构
  ### 4.1 文件职责
    - lib.rs / models.rs / host_traits.rs / core.rs / extism_layer.rs / tests.rs
  ### 4.2 三层分离模式
    - core.rs（纯逻辑）→ host_traits.rs（抽象）→ extism_layer.rs（适配）
  ### 4.3 HostFunctions trait（11个宿主能力）
  ### 4.4 函数注释规范（必须使用 plugin-fn-doc 技能）
    - **重要**：所有带 #[plugin_fn] 属性的函数的文档注释必须使用 plugin-fn-doc 技能生成（无论定义在哪个文件中）
    - 确保注释格式正确，cmx-cli 能正确解析生成 api.json
    - func — 普通函数
    - branch_fn — 分支路由函数（#[doc_type = "branch_fn"]）

## 五、技能使用指引
  - **编写函数文档注释（extism_layer.rs）→ 必须使用 plugin-fn-doc 技能**（必须）
  - 生成服务编排 → 使用 service-orchestration-generator 技能（推荐）
  - 生成表结构和种子数据 → 使用 plugin-metadata-generator 技能（推荐）
```

### 2.2 技能3：plugin-metadata-generator

**路径**：`.trae/skills/plugin-metadata-generator/SKILL.md`

**定位**：表结构元数据和种子数据的详细生成规范，AI 可据此自动生成完整的 metadata 和 seeddata 文件。

**内容大纲**：

```
# 插件元数据和种子数据生成器

## 一、文件关系概览
  - config/{name}_config.json → metadata/{name}_tables.json → seeddata/{name}_seed.json
  - 依赖关系和加载流程

## 二、config 配置文件规范
  ### 2.1 {name}_config.json 完整格式
    - name / description / depends_on / priority / files / seed_data
  ### 2.2 拓扑排序规则
    - depends_on 和 priority 的使用
  ### 2.3 seed_data 配置
    - table_name / file / conflict_columns / enabled
  ### 2.4 多配置文件场景

## 三、metadata 表结构定义规范
  ### 3.1 顶层结构
    - { "tables": [ TableDefine, ... ] }
  ### 3.2 TableDefine 完整字段
    - table_name / display_name / version / comment / primary_keys / i18n / schema / columns / indexes / ...
  ### 3.3 ColumnDefine 完整字段（逐一说明）
    - 每个字段的类型、必填性、取值范围
  ### 3.4 FieldType 枚举及对应 DB 类型
    - 13 种字段类型完整映射表
  ### 3.5 db_type 生成规则
    - 根据 field_type 自动生成
    - String 需指定 length → VARCHAR(length)
    - Int 可选 BIGINT 或 INT
  ### 3.6 索引定义规范
    - name / columns / kind（unique / normal）
  ### 3.7 外键定义规范
    - is_foreign_key / foreign_key_table / foreign_key_column
  ### 3.8 完整列模板
    - 提供每种 field_type 的列定义 JSON 模板

## 四、seeddata 种子数据规范
  ### 4.1 JSON 格式
    - 顶层是数组，每个元素是一个对象
    - 键名必须与 columns 中的 name 一致
    - null 表示 NULL，省略字段使用默认值
  ### 4.2 字段类型值格式
    - 每种 field_type 在 JSON 中的值表示方式
  ### 4.3 conflict_columns 选取原则
    - 选择业务唯一列
    - 组合唯一键用数组
  ### 4.4 种子数据命名规范
    - {table_name}_seed.json / {table_name}_seed.csv

## 五、生成流程
  ### 5.1 操作步骤
    1. 根据业务需求设计表结构
    2. 生成 metadata/{name}_tables.json
    3. 生成 seeddata/{name}_seed.json
    4. 创建或更新 config/{name}_config.json（注册表定义和种子数据）
  ### 5.2 校验清单
    - columns 中 ordinal 连续递增
    - primary_keys 中的列标记了 is_primary_key=true
    - foreign_key 列标记了 is_foreign_key=true 并填写关联信息
    - seed_data 中的 field 值类型与 field_type 一致
    - conflict_columns 中的列在表中存在且有唯一索引
```
