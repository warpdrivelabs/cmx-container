# 插件函数获取接口实现计划

## 任务目标

在 cmx-api 的 plugin handler 下新增一个接口，根据插件ID获取插件函数列表。

## 核心逻辑

1. 接收 `plugin_id` 查询参数
2. 通过 `GlobalPluginManager::get().get_plugin(&plugin_id)` 获取插件信息（包含 `install_path` 和 `version`）
3. 读取 `{install_path}/api/api.json` 文件
4. 以 `ApiResp<serde_json::Value>` 方式返回 api.json 的 JSON 内容

## 实现步骤

### 1. 在 `plugin/request.rs` 中添加查询参数结构体

文件路径：`e:\rustspace\cmx\cmx-container\crates\libs\cmx-api\src\handlers\plugin\request.rs`

添加新的查询参数结构体：

```rust
/// 插件函数查询参数
#[derive(Debug, Deserialize, IntoParams)]
pub struct PluginFunctionsQuery {
    /// 插件ID
    pub plugin_id: String,
}
```

### 2. 在 `plugin/handler.rs` 中添加 handler

文件路径：`e:\rustspace\cmx\cmx-container\crates\libs\cmx-api\src\handlers\plugin\handler.rs`

添加新的 handler 函数：

```rust
/// 获取插件函数列表
///
/// 处理 GET /api/plugin/functions 请求，根据 plugin_id 获取插件的 api.json 文件内容。
///
/// # 参数
/// - `query`: 查询参数（PluginFunctionsQuery），包含 plugin_id
///
/// # 响应
/// - 成功：返回 api.json 的 JSON 内容
/// - 失败：插件不存在或 api.json 文件读取失败
#[utoipa::path(
    get,
    path = "/api/plugin/functions",
    params(PluginFunctionsQuery),
    responses(
        (status = 200, description = "查询成功", body = ApiResp<serde_json::Value>)
    ),
    tag = "Plugin"
)]
pub async fn plugin_functions(
    Query(query): Query<PluginFunctionsQuery>,
) -> Result<Json<ApiResp<serde_json::Value>>> {
    let manager = cmx_plugin::GlobalPluginManager::get();

    let plugin = manager.get_plugin(&query.plugin_id).await
        .map_err(|e| crate::error::Error::internal_error(format!("获取插件信息失败: {}", e)))?;

    let plugin_info = plugin.ok_or_else(|| crate::error::Error::NotFound(format!("插件 {} 不存在", query.plugin_id)))?;

    let api_json_path = plugin_info.install_path.join("api").join("api.json");

    let content = tokio::fs::read_to_string(&api_json_path).await
        .map_err(|e| crate::error::Error::internal_error(format!("读取 api.json 失败: {}", e)))?;

    let json_value: serde_json::Value = serde_json::from_str(&content)
        .map_err(|e| crate::error::Error::internal_error(format!("解析 api.json 失败: {}", e)))?;

    Ok(Json(ApiResp::ok(json_value)))
}
```

注意：需要确保 `request.rs` 中导出了 `PluginFunctionsQuery`，handler.rs 中的 `super::request::*` 会包含它。

### 3. 在 `plugin/mod.rs` 中添加路由导出

文件路径：`e:\rustspace\cmx\cmx-container\crates\libs\cmx-api\src\handlers\plugin\mod.rs`

修改内容：

1. 在 `pub use handler::...` 中添加 `plugin_functions` 导出
2. 在 `inner_routes()` 中添加路由：`.route("/functions", get(plugin_functions))`

### 4. 在 `openapi.rs` 中添加 handler 到 paths

文件路径：`e:\rustspace\cmx\cmx-container\crates\libs\cmx-api\src\openapi.rs`

在 Plugin handlers 区域添加：

```rust
crate::handlers::plugin::handler::plugin_functions,
```

## 关键依赖

- `GlobalPluginManager::get()` - 获取全局插件管理器
- `manager.get_plugin(&plugin_id)` - 获取插件信息（包含 install_path）
- `tokio::fs::read_to_string()` - 异步读取文件
- `serde_json::Value` - 动态 JSON 类型
- `serde_json::from_str()` - 解析 JSON 字符串

## 错误处理

| 场景 | 错误处理 |
|------|----------|
| 插件不存在 | 返回 NotFound 错误 |
| 获取插件信息失败 | 返回 InternalError |
| api.json 文件读取失败 | 返回 InternalError |
| api.json 解析失败 | 返回 InternalError |

## 验证方式

1. 编译检查：`cargo build -p cmx-api`
2. 启动服务后访问：`GET /api/plugin/functions?plugin_id=xxx`
3. 检查返回的 JSON 结构是否符合 api.json 格式
