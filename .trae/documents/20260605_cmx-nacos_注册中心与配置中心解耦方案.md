# 注册中心与配置中心解耦方案

> **模块**: `cmx-registry-config` | **日期**: 2026-06-05 | **状态**: 已实现

---

## 一、概述

新建 `cmx-registry-config` crate，通过 **trait 抽象 + 适配器实现** 的可扩展架构，将注册中心与配置中心从 Nacos 硬编码中解耦。定义 `ServiceRegistry` 和 `ConfigCenter` 两个核心 trait，使用 `dyn trait` 动态派发，支持后续低成本扩展 Consul、Etcd、Apollo 等实现。

**策略**: 新建独立 crate 开发，`cmx-nacos` 保持不动，开发完成后在 `web-server` 中切换到新 crate，旧代码注释保留。

---

## 二、现状分析

### 2.1 当前架构

```
web-server
  └── config/nacos.rs  (硬编码 NacosClient)
        ├── NacosClient::new(nacos_config)
        ├── client.register_service(ip, port)
        ├── client.get_config_source(data_id, group)
        ├── client.listen_config(data_id, group, listener)
        └── client.deregister_service(ip, port)

cmx-nacos (crate)
  ├── client.rs          -- NacosClient 统一入口（硬耦合 nacos-sdk，实际使用的逻辑）
  ├── naming.rs          -- NamingClient（死代码，未被 client.rs 使用）
  ├── config_service.rs  -- ConfigClient（死代码，未被 client.rs 使用）
  ├── config.rs          -- NacosConfig（环境变量加载）
  ├── config_source.rs   -- NacosConfigSource（实现 config::Source）
  ├── listener.rs        -- RemoteConfigChangeListener
  ├── notifier.rs        -- ConfigChangeNotifier / GlobalConfigChangeNotifier
  └── error.rs           -- NacosError
```

### 2.2 问题

1. **Nacos 硬编码**: `web-server` 直接依赖 `NacosClient` 具体类型，无法替换
2. **注册与配置耦合**: 服务注册和配置中心绑定在同一个 `NacosClient` 中
3. **不可测试**: 无法注入 Mock 实现进行单元测试
4. **不可扩展**: 添加 Consul/Etcd 需要大量改动调用方代码
5. **环境变量泄露**: `NACOS_NAMING_SERVICE_NAME` 被 `cmx-api/app_state.rs` 和 `web-server/config/services.rs` 直接读取作为 `app_id`，绕过了配置系统

### 2.3 现有 trait 模式参考

项目已有成熟的 trait + dyn 分发模式（`cmx-traits`）：

- `RuntimeInvoker` → `cmx-runtime::ExtismEngine` 实现
- `PluginQuery` → `cmx-plugin::PluginManager` 实现
- `ServiceQuery` → `cmx-service::ServiceQueryImpl` 实现
- 全部使用 `async_trait` + `Arc<dyn Trait>` + `OnceLock` 全局单例

本方案严格遵循相同模式。

## 三、设计方案

### 3.1 新 crate 结构

```
cmx-registry-config/
├── Cargo.toml
└── src/
    ├── lib.rs                    # 模块入口，re-export 公共 API
    ├── error.rs                  # RegistryError + ConfigCenterError
    ├── config.rs                 # 配置模型（RegistryConfig、ConfigCenterFullConfig、NacosNamingConfig）
    │
    ├── global_registry.rs        # GlobalRegistry 全局单例（OnceLock + 空结构体）
    ├── global_config_center.rs   # GlobalConfigCenter 全局单例（OnceLock + 空结构体）
    │
    ├── registry/                 # 注册中心 trait + 实现
    │   ├── mod.rs                # 导出 trait + 工厂函数 + ServiceInstance
    │   ├── trait_rs.rs           # ServiceRegistry trait 定义
    │   ├── nacos.rs              # NacosRegistry 实现
    │   └── mock.rs               # MockRegistry 实现
    │
    ├── config_center/            # 配置中心 trait + 实现
    │   ├── mod.rs                # 导出 trait + 工厂函数 + ConfigChangeCallback
    │   ├── trait_rs.rs           # ConfigCenter trait 定义
    │   ├── nacos.rs              # NacosConfigCenter 实现 + NacosListenerAdapter
    │   └── mock.rs               # MockConfigCenter 实现
    │
    ├── config_source.rs          # RemoteConfigSource（实现 config::Source）
    └── notifier.rs               # ChangeNotifier + GlobalChangeNotifier
```

**与 `cmx-nacos` 的关系**:
- `cmx-nacos` 保持不动，不做任何修改
- `cmx-registry-config` 中的 Nacos 适配器实现参考 `cmx-nacos/src/client.rs` 中的逻辑
- `notifier.rs` 从 `cmx-nacos` 复制并去掉 Nacos 前缀（`GlobalConfigChangeNotifier` → `GlobalChangeNotifier`）
- 开发完成后，`web-server` 切换依赖到 `cmx-registry-config`，`cmx-nacos` 的依赖注释保留

### 3.2 核心 Trait 定义

#### 3.2.1 ServiceRegistry Trait

```rust
// cmx-registry-config/src/registry/trait_rs.rs

use async_trait::async_trait;
use std::collections::HashMap;

/// 服务实例信息
pub struct ServiceInstance {
    pub ip: String,
    pub port: u16,
    pub service_name: String,
    pub group_name: Option<String>,
    pub cluster_name: Option<String>,
    pub weight: f64,
    pub metadata: HashMap<String, String>,
    pub healthy: bool,
    pub ephemeral: bool,
}

/// 服务注册中心 trait
#[async_trait]
pub trait ServiceRegistry: Send + Sync {
    async fn register(&self, instance: &ServiceInstance) -> Result<(), RegistryError>;
    async fn deregister(&self, instance: &ServiceInstance) -> Result<(), RegistryError>;
    async fn query_instances(
        &self, service_name: &str, group_name: Option<&str>, clusters: Vec<String>,
    ) -> Result<Vec<ServiceInstance>, RegistryError>;
    fn is_enabled(&self) -> bool;
}
```

#### 3.2.2 ConfigCenter Trait

```rust
// cmx-registry-config/src/config_center/trait_rs.rs

use async_trait::async_trait;
use std::sync::Arc;

pub type ConfigChangeCallback = Arc<dyn Fn(&str) + Send + Sync>;

/// 配置中心 trait
#[async_trait]
pub trait ConfigCenter: Send + Sync {
    async fn get_config(&self, data_id: &str, group: &str) -> Result<String, ConfigCenterError>;
    async fn listen(
        &self, data_id: &str, group: &str, callback: ConfigChangeCallback,
    ) -> Result<(), ConfigCenterError>;
    fn is_enabled(&self) -> bool;
}
```

### 3.3 配置模型（三层分离）

配置模型分为三层：**通用参数**（对所有注册中心类型生效）、**连接配置**（特定注册中心的连接参数）、**环境变量映射**（兼容旧变量）。

#### 3.3.1 RegistryConfig（通用层）

```rust
pub struct RegistryConfig {
    pub registry_type: String,      // mock | nacos | consul | etcd
    pub enabled: bool,
    // 通用注册参数（对所有注册中心类型生效）
    pub service_name: String,       // 注册的服务名称
    pub group_name: String,         // 分组名称
    pub cluster_name: String,       // 集群名称
    pub weight: f64,                // 实例权重
    pub metadata: HashMap<String, String>,
    // 具体注册中心连接配置
    pub nacos: NacosNamingConfig,   // type = "nacos" 时生效
}
```

#### 3.3.2 NacosNamingConfig（连接层）

```rust
pub struct NacosNamingConfig {
    pub server_addr: String,        // Nacos 服务器地址
    pub namespace: String,          // 命名空间
    pub app_name: String,           // 应用名称
    pub username: Option<String>,   // 认证用户名
    pub password: Option<String>,   // 认证密码
}
```

> **设计说明**: `service_name`、`group_name`、`cluster_name`、`weight` 等服务实例参数提升到 `RegistryConfig` 通用层，`NacosNamingConfig` 仅保留 Nacos 连接相关配置。这样切换到 Consul 等其他注册中心时，调用方代码无需修改。

#### 3.3.3 环境变量映射

| 新变量 | 旧变量回退 | 说明 |
|--------|-----------|------|
| `SERVICE_REGISTRY_TYPE` | - | 注册中心类型 |
| `SERVICE_REGISTRY_ENABLED` | `NACOS_ENABLED` + `NACOS_NAMING_ENABLED` | 是否启用 |
| `SERVICE_REGISTRY_NAME` | `NACOS_NAMING_SERVICE_NAME` | 注册的服务名称 |
| `SERVICE_REGISTRY_GROUP` | `NACOS_NAMING_GROUP_NAME` | 分组名称 |
| `SERVICE_REGISTRY_CLUSTER` | - | 集群名称 |
| `SERVICE_REGISTRY_WEIGHT` | - | 实例权重 |
| `SERVICE_REGISTRY_IP` | `NACOS_REGISTER_SERVER_IP` | 注册 IP |
| `SERVICE_REGISTRY_PORT` | `NACOS_REGISTER_SERVER_PORT` | 注册端口 |
| `CONFIG_CENTER_TYPE` | - | 配置中心类型 |
| `CONFIG_CENTER_ENABLED` | `NACOS_ENABLED` + `NACOS_CONFIG_ENABLED` | 是否启用 |
| `APP_ID` | `SERVICE_REGISTRY_NAME` → `NACOS_NAMING_SERVICE_NAME` | 应用标识 |

> **配置方式**: 当前仅支持环境变量，所有配置通过 `XxxConfig::from_env()` 加载。

### 3.4 build_instance 便捷方法

`RegistryConfig` 提供 `build_instance(ip, port)` 方法，将通用注册参数组装为 `ServiceInstance`，调用方无需关心字段映射：

```rust
let registry_config = RegistryConfig::from_env();
let instance = registry_config.build_instance(ip, port);
registry.register(&instance).await?;
```

### 3.5 全局单例（跨 crate 可访问）

`GlobalRegistry` 和 `GlobalConfigCenter` 定义在 `cmx-registry-config` crate 中，使用 `OnceLock` + 空结构体模式（与 `cmx-traits::GlobalRuntime` 一致），任何依赖了该 crate 的模块都可以直接访问：

```rust
pub struct GlobalRegistry;
static INSTANCE: OnceLock<Arc<dyn ServiceRegistry>> = OnceLock::new();

impl GlobalRegistry {
    pub fn set(registry: Arc<dyn ServiceRegistry>) { ... }
    pub fn get() -> Arc<dyn ServiceRegistry> { ... }
    pub fn is_initialized() -> bool { ... }
}
```

### 3.6 工厂函数

```rust
pub fn create_registry(config: &RegistryConfig) -> Result<Arc<dyn ServiceRegistry>, RegistryError> {
    match config.registry_type.as_str() {
        "nacos" => Ok(Arc::new(NacosRegistry::new(&config.nacos)?)),
        "mock" => Ok(Arc::new(MockRegistry::new())),
        other => Err(RegistryError::UnsupportedType(other.to_string())),
    }
}
```

### 3.7 IP/端口解析逻辑

`resolve_register_ip()` 和 `resolve_register_port()` 保留在 `web-server/src/config/infra_init.rs`，优先级：

```
SERVICE_REGISTRY_IP    > NACOS_REGISTER_SERVER_IP > server.ip 配置 > 自动检测 > 127.0.0.1
SERVICE_REGISTRY_PORT  > NACOS_REGISTER_SERVER_PORT > server.port 配置 > 8080
```

### 3.8 app_id 获取优先级

`app_state.rs` 和 `services.rs` 中 `app_id` 的获取优先级：

```
app.id 配置 > APP_ID 环境变量 > SERVICE_REGISTRY_NAME > NACOS_NAMING_SERVICE_NAME > "default"
```

## 六、扩展新实现指南（以 Consul 为例）

1. 在 `cmx-registry-config/src/registry/` 下新增 `consul.rs`，实现 `ServiceRegistry` trait
2. 在 `config.rs` 中新增 `ConsulConfig` 连接配置结构体，加到 `RegistryConfig` 中
3. 在工厂函数 `create_registry` 中添加 `"consul"` 分支
4. **无需修改任何调用方代码**（通用参数已在 `RegistryConfig` 通用层，`build_instance()` 自动适配）

## 八、决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 模块位置 | 新建 `cmx-registry-config` crate | 不影响现有 `cmx-nacos`，独立开发 |
| 旧代码处理 | 注释保留，不删除 | 安全迁移，保留回退能力 |
| 派发策略 | dyn trait (`Arc<dyn Trait>`) | 配置驱动、运行时灵活切换，与项目 `cmx-traits` 模式一致 |
| async 方式 | async_trait | 项目已有 24 处使用 async_trait，保持一致 |
| Mock 范围 | 完整实现 | 方便单元测试，且 Mock 实现本身简单 |
| 配置来源 | 仅环境变量 | 当前实现仅支持环境变量加载，通过 `XxxConfig::from_env()` |
| 服务实例参数 | 提升到 RegistryConfig 通用层 | 切换注册中心类型时调用方无需修改 |
| 全局单例 | 定义在 cmx-registry-config crate 中 | 任何依赖该 crate 的模块都可访问 |
| IP/端口解析归属 | 保留在 web-server | 涉及 ConfigManager，与具体注册中心无关 |
| app_id 获取 | 统一优先级链 | `app.id` > `APP_ID` > `SERVICE_REGISTRY_NAME` > `NACOS_NAMING_SERVICE_NAME` |
