# 用户权限角色管理方案（cmx-iam）

> 日期：2026-06-15 | 模块：cmx-iam | 状态：方案设计
>
> 依赖文档：`20260612_平台级基础设施与双协议架构重构方案.md`（Phase 5：IAM 核心）

## 一、目标

基于 `20260612_平台级基础设施与双协议架构重构方案.md` 的 crate 划分，详细设计 **cmx-iam** 中用户、角色、权限三个核心模块的：

1. **数据库表结构**（DDL，遵循 pg-table-generator 规范）
2. **Entity / BMC / Filter 定义**（遵循 cmx-biz 模式）
3. **Service 层业务逻辑**
4. **cmx-traits trait 定义**（含数据权限扩展预留接口）
5. **API handler / route 规划**

### 设计原则

| 原则 | 说明 |
|------|------|
| 标准 RBAC 模型 | User → Role → Permission，多对多关系 |
| 企业级粒度 | 权限采用 `resource:action` 编码（如 `user:create`） |
| 数据权限预留 | 角色 data_scope 字段 + PermissionChecker trait 扩展方法，本次不实现具体数据过滤逻辑 |
| 遵循现有模式 | Entity/BMC/Filter/Service 四文件结构，GenericCrudService 复用 |
| 协议无关 | Service 层不依赖 axum，handler 为薄层适配 |
| **WASM 可达性** | **基础数据结构体放 cmx-core，业务逻辑（BMC/Filter/Service）放 cmx-iam** |

### 类型分层设计

> cmx-core 已有 `DomainEntity`、`TableDefine` 等纯数据结构先例，且 WASM SDK 直接 re-export cmx-core 类型。

| 层级 | 位置 | 包含内容 | WASM 可见 |
|------|------|----------|----------|
| **基础数据模型** | `cmx-core/src/model/iam/` | `User`、`Role`、`Permission`、`AuthContext`（纯 Serialize/Deserialize，无 sqlx 依赖） | ✅ 是 |
| **业务操作层** | `cmx-iam/src/{user,role}/` | `UserForCreate`、`UserForUpdate`、`UserBmc`、`UserFilter`、`UserService`、`AssignRolesRequest` | ❌ 否（服务端专用） |

**分层理由**：
- WASM 插件需要感知调用者身份（User/Role）和权限信息（Permission），这些类型必须在 cmx-core 中
- WASM 插件不需要 ForCreate/ForUpdate/Filter/BMC（这些是服务端 CRUD 关注点）
- cmx-core 无 sqlx 依赖，基础结构体为纯 `Serialize/Deserialize`；cmx-iam 拥有 sqlx + modql + database 等完整能力

## 二、RBAC 权限模型设计

### 2.1 模型关系图

```
┌──────────┐     ┌──────────────┐     ┌──────────┐
│  cmx_user │─────│ cmx_user_role│─────│ cmx_role │
│  用户表   │  N:N│  用户角色关联 │  N:N│  角色表   │
└──────────┘     └──────────────┘     └────┬─────┘
                                            │
                                    ┌───────┴────────┐
                                    │cmx_role_permission│
                                    │  角色权限关联     │
                                    └───────┬────────┘
                                            │
                                    ┌───────┴─────┐
                                    │cmx_permission│
                                    │  权限表      │
                                    └─────────────┘
```

### 2.2 权限编码规范

权限 `code` 采用 `resource:action` 格式：

| 资源 | 操作 | 权限码 | 说明 |
|------|------|--------|------|
| user | create / read / update / delete | `user:create` 等 | 用户管理 |
| role | create / read / update / delete | `role:create` 等 | 角色管理 |
| permission | read / assign | `permission:read` 等 | 权限管理 |
| menu | create / read / update / delete | `menu:create` 等 | 菜单管理 |
| org | create / read / update / delete | `org:create` 等 | 组织管理 |
| system | config / all | `system:all` | 系统管理 |

### 2.3 数据权限扩展设计（预留，本次不实现）

**DataScope 枚举**（定义在 cmx-traits，供 PermissionChecker 使用）：

```rust
/// 数据权限范围 — 本次仅定义枚举和接口，不实现过滤逻辑
#[derive(Debug, Clone, Serialize, Deserialize, Default)]
pub enum DataScope {
    #[default]
    All,                  // 全部数据
    Custom(Vec<String>),  // 自定义部门范围（部门ID列表）
    Dept,                 // 本部门
    DeptAndSub,           // 本部门及子部门
    SelfData,             // 仅本人数据
}
```

**预留机制**：
- `cmx_role` 表包含 `data_scope` 字段（int4，默认 1=All）
- `PermissionChecker` trait 包含 `get_data_scope()` 方法（带默认实现返回 `All`）
- 未来实现数据权限时，只需：① 实现 `get_data_scope` 具体逻辑 ② 在 BMC/Service 层注入数据过滤条件

### 4.2 DataScope 定义

```rust
// crates/libs/cmx-traits/src/iam/data_scope.rs

use serde::{Deserialize, Serialize};

/// 数据权限范围 — 本次仅定义枚举，不实现过滤逻辑
///
/// 未来实现数据权限时，BMC/Service 层根据此枚举注入 WHERE 条件
#[derive(Debug, Clone, Serialize, Deserialize, Default, PartialEq)]
pub enum DataScope {
    /// 全部数据（默认）
    #[default]
    All,
    /// 自定义数据范围（部门ID列表）
    Custom(Vec<String>),
    /// 本部门数据
    Dept,
    /// 本部门及子部门数据
    DeptAndSub,
    /// 仅本人数据
    SelfData,
}

/// 从 int4 数据库值转换（cmx_role.data_scope 字段）
impl From<i64> for DataScope {
    fn from(v: i64) -> Self {
        match v {
            2 => DataScope::Custom(vec![]),
            3 => DataScope::Dept,
            4 => DataScope::DeptAndSub,
            5 => DataScope::SelfData,
            _ => DataScope::All,
        }
    }
}

impl From<&DataScope> for i64 {
    fn from(ds: &DataScope) -> Self {
        match ds {
            DataScope::All => 1,
            DataScope::Custom(_) => 2,
            DataScope::Dept => 3,
            DataScope::DeptAndSub => 4,
            DataScope::SelfData => 5,
        }
    }
}
```

### 6.2 Handler 文件结构

> 遵循 `20260612_平台级基础设施与双协议架构重构方案.md` 的架构规划：cmx-api 为**薄层 HTTP 适配**，IAM handler 模块**仅包含 `handler.rs + mod.rs`**，不单独定义 request.rs/response.rs。Entity/Filter 类型直接从 cmx-iam 导入。

```
cmx-api/src/rest/handlers/iam/
  ├── mod.rs                       # 路由聚合 + 汇总导出
  │
  ├── user/                        # 用户管理
  │   ├── mod.rs                   # 模块导出 + routes() 注册
  │   └── handler.rs               # 自定义 handler（assign_roles / get_roles / create 含密码哈希）
  │                                 #   导入 cmx_iam::user::{UserBmc, UserForCreate, UserFilter, ...}
  │
  ├── role/                        # 角色管理
  │   ├── mod.rs
  │   └── handler.rs               # 自定义 handler（assign_permissions / get_permissions）
  │                                 #   导入 cmx_iam::role::{RoleBmc, RoleForCreate, RoleFilter, ...}
  │
  └── permission/                  # 权限管理
      ├── mod.rs
      └── handler.rs               # 自定义 handler（get_permission_tree）
                                      #   导入 cmx_iam::role::{PermissionBmc, PermissionFilter, ...}
```

**关键区别（vs 旧模式）**：
- **不建 request.rs**：`AssignRolesRequest` / `AssignPermissionsRequest` 等 IAM 专用请求体定义在 **cmx-iam 的 entity.rs** 中
- **不建 response.rs**：直接使用 cmx-iam 的 Entity（如 `User`、`Role`）作为响应类型
- handler.rs 仅做：请求解析 → 调用 `cmx_state.iam` 中的 trait 方法 → 包装 `ApiResp` 返回

```rust
// handlers/iam/user/handler.rs
use axum::extract::{State, Query};
use axum::Json;
use crate::api_response::ApiResp;
use crate::app_state::CmxAppState;
use crate::error::Result;
use crate::middleware::CmxSvrContext;
// 直接从 cmx-iam 导入请求/响应类型
use cmx_iam::user::AssignRolesRequest;
use cmx_iam::role::Role;

/// 为用户分配角色（全量替换）
#[utoipa::path(
    post,
    path = "/iam/user/assign-roles",
    request_body = AssignRolesRequest,
    responses(
        (status = 200, description = "分配成功", body = ApiResp<()>)
    ),
    tag = "IAM-User"
)]
pub async fn assign_roles(
    State(cmx_state): State<CmxAppState>,
    CmxSvrContext(svr_ctx): CmxSvrContext,
    Json(req): Json<AssignRolesRequest>,
) -> Result<Json<ApiResp<()>>> {
    let iam = cmx_state.iam.as_ref()
        .ok_or_else(|| Error::internal_error("IAM service not initialized"))?;
    iam.user_service.assign_roles(
        &db_id, &svr_ctx, &req.user_id, &req.role_ids
    ).await?;
    Ok(Json(ApiResp::ok_no_data()))
}

/// 查询用户的角色列表（返回 cmx-iam 的 Role Entity）
#[utoipa::path(
    get,
    path = "/iam/user/get-roles",
    params(
        ("id" = String, Query, description = "用户ID")
    ),
    responses(
        (status = 200, description = "查询成功", body = ApiResp<Vec<Role>>)
    ),
    tag = "IAM-User"
)]
pub async fn get_user_roles(
    State(cmx_state): State<CmxAppState>,
    Query(params): Query<cmx_core::GetParams>,
) -> Result<Json<ApiResp<Vec<Role>>>> {
    let iam = cmx_state.iam.as_ref()
        .ok_or_else(|| Error::internal_error("IAM service not initialized"))?;
    let roles = iam.user_service.get_user_roles(&db_id, &params.id).await?;
    Ok(Json(ApiResp::ok(roles)))
}
```

```markdown
## 十一、新架构薄层 Handler 模式（cmx-iam / cmx-auth 等）

> 适用于遵循 `20260612_平台级基础设施与双协议架构重构方案.md` 架构的业务 crate。

### 11.1 与旧模式的区别

| 维度 | 旧模式（如 plugin handler） | 新架构薄层模式（如 iam handler） |
|------|---------------------------|-------------------------------|

| 请求/响应类型 | request.rs / response.rs 独立定义 | **直接复用业务 crate 的 Entity** |
| handler 职责 | 请求解析 + 业务逻辑 + 响应构造 | **仅请求解析 → 调用 trait → 包装 ApiResp** |

  ├── user/

  ├── role/

  └── permission/
```

## 十、假设与决策

| 决策 | 理由 |
|------|------|
| 权限采用 `resource:action` 编码 | 企业级标准，清晰可扩展 |
| User Entity 不包含 password_hash | 防止 API 泄漏敏感数据 |
| 角色-权限为全量替换模式 | 简化前端操作，避免增量同步复杂性 |
| DataScope 定义在 cmx-traits 而非 cmx-iam | 未来 BMC 层（cmx-database）也需要感知 |
| PermissionChecker 有默认实现 | 按需启用，不影响现有无认证接口 |
| 本次不建 cmx_role_data_scope 表 | 避免过度设计，待组织机构模块就绪后再建 |
| 用户表无 dept_id 字段 | 组织机构在 Phase 6 实现，届时通过 cmx_user_org 关联表处理 |
| **基础数据模型放 cmx-core** | WASM 插件需感知调用者身份（User/Role/Permission），cmx-core 是 WASM 可达的共享类型层。cmx-core 已有 DomainEntity 等纯数据结构先例，无 sqlx 依赖 |
| **ForCreate/ForUpdate/BMC/Filter 放 cmx-iam** | 这些是服务端 CRUD 关注点，WASM 不需要，cmx-iam 拥有 sqlx+modql+database 完整能力 |
| **cmx-core 结构体无 Fields/FromRow derive** | cmx-core 不依赖 sqlx，基础模型为纯 Serialize/Deserialize；Fields/FromRow 在 cmx-iam 的 ForCreate/ForUpdate 上 |
