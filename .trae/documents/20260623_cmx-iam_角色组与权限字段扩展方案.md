# 角色组与权限字段扩展方案

> 日期：2026-06-23 | 模块：cmx-iam | 类型：功能扩展方案
>
> 关联文档：[20260622\_认证与权限整体架构方案.md](file:///media/yqs/工作/rustspace/cmx/cmx-container/.trae/documents/20260622_认证与权限整体架构方案.md)

***

## 一、需求概述

### 需求1：角色组（Role Group）

1. 新增 `cmx_role_group` 表，支持**树形结构**（通过 `parent_id` 自引用）
2. `cmx_role` 表新增 `role_group_id` 字段，关联所属角色组
3. 新增角色组的**增删改查**接口 + **树形查询**接口

### 需求2：权限字段扩展

1. `cmx_permission` 表新增三个分类字段：`domain_code`（所属域）、`app_code`（所属应用）、`module_code`（所属模块）
2. `cmx_permission` 表新增 `extension`（text 类型）扩展字段，供用户自定义配置
3. 权限树接口支持按 `domain_code` / `app_code` / `module_code` 进行过滤查询

**核心方法**：

| 方法                    | 说明                                                      |
| --------------------- | ------------------------------------------------------- |
| `create_role_group`   | 创建角色组，可选校验 parent\_id 存在性                               |
| `get_role_group`      | 查询单个角色组                                                 |
| `update_role_group`   | 更新角色组                                                   |
| `delete_role_group`   | 批量删除角色组（软删除），**防止循环引用**校验                               |
| `page_role_groups`    | 分页查询                                                    |
| `list_role_groups`    | 列表查询                                                    |
| `get_role_group_tree` | 一次性加载全部有效角色组 → 内存递归组装树（复用 permission 的 `build_tree` 模式） |

**删除校验逻辑**：

* 检查待删除角色组下是否有子角色组（`SELECT id FROM cmx_role_group WHERE parent_id = ANY($1) AND archived = 0`）

* 检查待删除角色组下是否有关联角色（`SELECT id FROM cmx_role WHERE role_group_id = ANY($1) AND archived = 0`）

* 如有关联数据，返回 `IamError::RoleGroupInUse`

**修改 Service 实现**（`crates/libs/cmx-iam/src/permission/service.rs`）：

```rust
// 构建带过滤条件的 SQL
let mut sql = String::from(
    "SELECT * FROM cmx_permission WHERE archived = 0 AND status = 1"
);
if domain_code.is_some() { sql.push_str(" AND domain_code = $1"); }
if app_code.is_some() { /* 追加参数化条件 */ }
if module_code.is_some() { /* 追加参数化条件 */ }
sql.push_str(" ORDER BY sort_order ASC NULLS LAST, code ASC");
```

查询结果仍通过 `build_tree` 内存组装树。

## 五、假设与决策

| 决策                                         | 理由                               |
| ------------------------------------------ | -------------------------------- |
| 角色组不包含 code 和 status 字段 | 角色组为组织管理用，以 name 为主标识，通过 archived 控制归档 |
| 角色组使用 `parent_id` 自引用实现树形结构                | 与权限树保持一致的实现模式，复用 `build_tree` 算法 |
| `cmx_role.role_group_id` 可为 NULL           | 兼容已有角色数据，不强制绑定角色组                |
| 角色组删除前校验子组和关联角色                            | 避免孤儿数据，保证引用完整性                   |
| 权限的 domain_code/app_code/module_code 为 varchar(100) 可空字符串 | 灵活分类，不强制外键约束，支持渐进迁移              |
| `extension` 字段为 text 类型                    | 用户可存 JSON 或任意文本，无长度限制            |
| 权限树过滤使用参数化 SQL 动态拼接 WHERE                  | 避免全量加载后再过滤，提升查询效率                |
| 不修改内置种子权限的 domain_code/app_code/module_code 值 | 保持兼容，新增字段默认 NULL                 |
| 同步修改 init_ddl.sql 和迁移脚本                  | 保持全量 DDL 与增量迁移一致                    |
| 迁移文件编号为 007                                | 继承现有 001-006 序号                  |
