# 权限自动注册与统一检查方案

> 借鉴 `PERMISSION_DESIGN.md`(cmx-server-demo 设计)与 `example/cmxold` 的认证实现,
> 为 cmx-container 补齐**编译期权限自动注册**和**统一权限检查**能力。
>
> 决策:① inventory+宏为主注册机制,与现有 TOML 配置**并存增强**(TOML 作为可选覆盖);
> ② 新建 `cmx-macros` proc-macro crate 实现 `#[permission]` 属性宏。

***

## 一、概述

当前项目已实现 RBAC + 中间件管线(`mw_auth`→`mw_permission`),但路由→权限映射依赖
**TOML 配置驱动**(`[iam_permissions]` section + 最长前缀匹配),存在以下缺口:

1. **无编译期注册**:新增受保护路由需手动在 TOML 添加映射,易遗漏,无启动校验。
2. **无过程宏注解**:handler 函数体不感知权限,无法在函数级精确声明所需权限。
3. **无 DB 同步**:代码中权限声明与 DB `cmx_permission` 表无自动同步机制。
4. **无启动校验**:无法发现"漏写权限注解的路由处理器"。

本方案新增以下能力(对标 PERMISSION\_DESIGN.md §3、§4):

| 能力                                    | 对应设计章节   | 说明                      |
| ------------------------------------- | -------- | ----------------------- |
| `RegisteredPermission` + inventory 收集 | §3.1     | 编译期全局收集权限定义             |
| `#[permission]` / `#[public]` 属性宏     | §3.2 方式一 | 注解式声明权限,自动注册 + 注入检查     |
| `register_crud_permissions!` 宏        | §3.2 方式三 | 一键注册 CRUD 五权限           |
| `RegisteredRouteHandler` + 启动校验       | §3.3     | 防止漏写权限注解                |
| `require_permission` 统一检查 API         | §4.3     | AuthContext 级统一检查(短路规则) |
| 路由→权限映射自动生成                           | §4.1     | inventory 驱动,与 TOML 并存  |
| `sync_from_registry` DB 同步            | §6       | 启动期代码→DB 权限同步           |

***

```toml

**src/lib.rs** 实现三个属性宏:

#### `#[permission]` — 受保护 handler 权限注解

````rust
use proc_macro::TokenStream;
use quote::quote;
use syn::{parse_macro_input, ItemFn, Meta, Expr, Lit};

/// 受保护路由处理器权限注解
///
/// 同时完成:
/// 1. inventory::submit! 注册 RegisteredPermission(权限元数据)
/// 2. inventory::submit! 注册 RegisteredRouteHandler(路由处理器登记,has_check=true)
/// 3. 在函数体首行注入权限检查代码
///
/// # 用法
/// ```ignore
/// #[cmx_macros::permission(
///     key = "user:create",
///     group = "用户管理",
///     display = "创建用户",
///     description = "创建新用户账户"
/// )]
/// pub async fn create_user(...) -> ... { ... }
/// ```
#[proc_macro_attribute]
pub fn permission(args: TokenStream, input: TokenStream) -> TokenStream {
    // 解析 key/group/display/description 参数
    // 生成:
    //   - inventory::submit! { RegisteredPermission { ... } }
    //   - inventory::submit! { RegisteredRouteHandler { kind: Protected, has_check: true, .. } }
    //   - 原函数体首行注入: svr_ctx.require_permission("key")?;
    // ...
}
````

**注入逻辑**:宏解析函数参数,找到 `CmxSvrContext(svr_ctx)` 类型的参数,
在函数体首行注入:

```rust
svr_ctx.require_permission("user:create")?;
```

> 注:`require_permission` 是 `SVRContext` 新增方法(见 3.3),内部委托 `AuthContext::require_permission`。

#### `#[public]` — 公开路由标记

```rust
/// 标记为公开路由(无需认证/权限),但仍登记到 RegisteredRouteHandler 用于启动校验
#[proc_macro_attribute]
pub fn public(_args: TokenStream, input: TokenStream) -> TokenStream {
    // 仅 inventory::submit! { RegisteredRouteHandler { kind: Public, has_check: false, .. } }
    // 不注入检查代码
}
```

#### `register_crud_permissions!` — CRUD 权限批量注册声明式宏

放在 `cmx-core` 中(非 proc-macro),一次注册 create/read/update/delete/list 五个权限:

```rust
#[macro_export]
macro_rules! register_crud_permissions {
    ($resource:expr, $display:expr, $group:expr, $desc:expr) => {
        $crate::inventory::submit! {
            $crate::model::iam::registry::RegisteredPermission {
                key: concat!($resource, ":create"),
                group: $group, display: concat!($display, "创建"),
                description: $desc, source: module_path!(),
            }
        }
        // ... read/update/delete/list 同理
    };
}
```

### 3.2 cmx-core 注册表结构与 inventory 收集

**新增文件**: `crates/libs/cmx-core/src/model/iam/registry.rs`

```rust
//! 权限注册表 - 编译期 inventory 收集
//!
//! 通过 inventory crate 在编译期将所有权限定义和路由处理器登记到全局集合,
//! 启动期用于:① 路由→权限映射自动生成 ② DB 同步 ③ 漏写校验。

/// 编译期注册的权限定义
pub struct RegisteredPermission {
    pub key: &'static str,
    pub group: &'static str,
    pub display: &'static str,
    pub description: &'static str,
    pub source: &'static str,
}
inventory::collect!(RegisteredPermission);

/// 路由处理器种类
pub enum HandlerKind {
    Public,
    Protected,
}

/// 编译期注册的路由处理器登记
pub struct RegisteredRouteHandler {
    pub handler_name: &'static str,
    pub kind: HandlerKind,
    pub permission_key: Option<&'static str>,
    pub has_check: bool,
    pub source: &'static str,
}
inventory::collect!(RegisteredRouteHandler);

/// 获取所有已注册权限
pub fn all_registered_permissions() -> Vec<&'static RegisteredPermission> {
    inventory::iter::<RegisteredPermission>().collect()
}

/// 获取所有已注册路由处理器
pub fn all_registered_handlers() -> Vec<&'static RegisteredRouteHandler> {
    inventory::iter::<RegisteredRouteHandler>().collect()
}
```

### 3.3 AuthContext / SVRContext 增加 require\_permission 统一检查 API

对标 PERMISSION\_DESIGN.md §4.3 的短路规则。

**修改文件**: `crates/libs/cmx-core/src/model/service/context.rs`

为 `AuthContext` 新增:

```rust
impl AuthContext {
    /// 统一权限检查(短路规则)
    ///
    /// 1. system:all 超级权限 → 放行
    /// 2. admin 角色 → 放行
    /// 3. 拥有指定权限 → 放行
    /// 4. 否则 → 返回 PermissionDenied
    pub fn require_permission(&self, key: &str) -> Result<(), PermissionDeniedError> {
        // 1. system:all 短路
        if self.has_permission("system:all") { return Ok(()); }
        // 2. admin 角色短路
        if self.has_role("admin") { return Ok(()); }
        // 3. 业务权限检查
        if self.has_permission(key) { Ok(()) }
        else { Err(PermissionDeniedError { user_id: self.user_id.clone(), permission: key.to_string() }) }
    }
}
```

为 `SVRContext` 新增委托方法(供宏注入代码使用):

```rust
impl SVRContext {
    /// 权限检查(委托 AuthContext)
    pub fn require_permission(&self, key: &str) -> Result<(), PermissionDeniedError> {
        let auth = self.auth_context.as_ref()
            .ok_or(PermissionDeniedError::unauthenticated())?;
        auth.require_permission(key)
    }
}
```

**新增错误类型**: `crates/libs/cmx-api-types/src/error.rs` 增加 `PermissionDenied` 变体
(或复用现有错误类型),确保 `?` 传播到 handler 返回值。

> 根用户短路:当前 `AuthContext` 无 `user_id == 0` 概念(user\_id 为 String),
> 根用户短路通过 `system:all` 权限实现(由 IamChecker 在加载权限时注入)。

### 3.4 启动期路由→权限映射自动生成(并存增强)

**修改文件**: `crates/web/web-server/src/config/iam.rs` 的 `load_permission_map()`

**策略**: inventory 自动生成 + TOML 覆盖

```rust
fn load_permission_map() -> HashMap<String, String> {
    // 1. 从 inventory 自动生成的 RegisteredRouteHandler 收集
    //    (需在路由注册时关联 handler_name → route_path,见 3.4.1)
    let mut map = build_permission_map_from_registry();

    // 2. TOML [iam_permissions] 作为覆盖(优先级更高)
    let config = cmx_utils::ConfigManager::global();
    if let Ok(table) = config.inner().get_table("iam_permissions") {
        for (k, v) in table {
            if let Ok(s) = v.clone().into_string() {
                map.insert(k, s);  // 覆盖
            }
        }
    }
    map
}
```

#### 3.4.1 handler\_name → route\_path 关联

`#[permission]` 宏注册的 `RegisteredRouteHandler` 含 `handler_name` 但无 route\_path。
路由路径在 `ModuleRoutes::routes()` 注册时才确定。

**方案**: 扩展 `ModuleRoutes` trait,各模块在 `routes()` 中调用辅助函数登记路径:

```rust
// cmx-api/src/routes/traits.rs 扩展
pub trait ModuleRoutes {
    fn routes(&self) -> Router<CmxAppState>;
    /// 返回模块声明的路由→处理器名映射,用于启动校验
    fn route_handler_names(&self) -> Vec<(&'static str, &'static str)> { vec![] }
}
```

> 简化版:启动时遍历 `inventory::iter::<RegisteredRouteHandler>` 获取所有已注解 handler,
> 与各模块 `route_handler_names()` 比对,未登记的告警(可配置 panic)。

### 3.6 CRUD handler 权限集成(扩展 declare\_crud\_handlers!)

**修改文件**: `crates/libs/cmx-api/src/routes/macros.rs`

扩展 `declare_crud_handlers!` 和 `setup_crud_api!` 增加权限参数:

```rust
#[macro_export]
macro_rules! declare_crud_handlers {
    (
        $module_name:ident, $entity:ty, $bmc:ty,
        $entity_create:ty, $entity_update:ty, $filter:ty,
        $tag:expr, $prefix:expr,
        // 新增:权限资源名(如 "user"),为空则不注入权限检查
        $perm_resource:expr
    ) => {
        pub mod $module_name {
            // ... 原有代码 ...

            pub async fn create(
                State(cmx_state): State<CmxAppState>,
                CmxSvrContext(svr_ctx): CmxSvrContext,
                headers: HeaderMap,
                Json(data): Json<$entity_create>,
            ) -> Result<Json<ApiResp<DataSet>>> {
                // 新增:权限检查注入(仅当 perm_resource 非空)
                if !$perm_resource.is_empty() {
                    svr_ctx.require_permission(concat!($perm_resource, ":create"))
                        .map_err(crate::error::Error::from)?;
                }
                $crate::rest::handler::create::<$bmc, $entity_create>(/* ... */).await
            }
            // ... read/update/delete/list 同理 ...
        }

        // 新增:注册 CRUD 权限到 inventory
        if !$perm_resource.is_empty() {
            $crate::register_crud_permissions_inline!($perm_resource);
        }
    };
}
```

> 注:`register_crud_permissions_inline!` 在 cmx-core 定义,展开为 `inventory::submit!`。
> 因 `macro_rules!` 内不能直接调用 `#[proc_macro_attribute]`,CRUD 路由的权限检查
> 通过在 `macro_rules!` 内手写 `svr_ctx.require_permission(...)` 注入,
> 权限元数据注册通过 `inventory::submit!` 在模块初始化时完成。

## 七、假设与决策

### 决策

1. **并存增强**:inventory+宏自动生成映射为主,TOML 作为可选覆盖(优先级更高),支持热更新。现有配置不破坏。
2. **新建 cmx-macros crate**:proc-macro crate,实现 `#[permission]`/`#[public]` 属性宏。
3. **双保险检查**:宏注入的 `require_permission()`(handler 级精确) + 现有 `mw_permission` 中间件(路由级安全网)并存。
4. **根用户短路**:通过 `system:all` 权限实现(由 IamChecker 加载时注入),不引入 `user_id == 0` 特判。
5. **CRUD 权限**:通过扩展 `declare_crud_handlers!` 宏注入,不依赖 proc-macro(macro\_rules! 内手写注入)。
6. **启动校验可配置**:`handler_validation_mode` 支持 panic/warn/off,默认 warn(渐进迁移)。

### 假设

1. `inventory` 0.3 版本与 edition 2024 兼容(需验证,若有问题降级 0.2)。
2. `cmx-api-types::Error` 可扩展新变体且现有 `From` 转换链路可支持 `PermissionDeniedError`。
3. 现有 CRUD 路由调用点(`setup_crud_api!`)数量可控,可逐一补充权限资源参数。
4. `ModuleRoutes` trait 扩展 `route_handler_names()` 为可选默认实现,不强制所有模块立即实现。

### 风险

* **inventory 版本兼容**:edition 2024 较新,inventory 0.3 需实测。备选:改用 `linkme` crate 或手动 `lazy_static` 收集。

* **宏注入参数定位**:`#[permission]` 需在函数参数中找到 `CmxSvrContext` 类型参数,依赖命名约定。若参数名不固定,需通过类型路径匹配(`cmx_api::middleware::CmxSvrContext`)。

* **CRUD 宏迁移量**:现有 `setup_crud_api!` 调用点需逐一添加权限参数,工作量与模块数成正比。
