# 权限自动注册与统一检查方案

> 借鉴 `PERMISSION_DESIGN.md`(cmx-server-demo 设计)、`example/cmxold` 认证实现、
> 以及 **Spring Security** 注解体系,为 cmx-container 补齐**编译期权限/角色自动注册**
> 和**统一检查**能力。
>
> 决策:① inventory+宏为主注册机制,与现有 TOML 配置**并存增强**;
> ② 新建 `cmx-macros` proc-macro crate,实现 Spring Security 风格的权限+角色注解宏;
> ③ **不自动写 DB**,启动时仅校验代码声明权限与 DB 一致性(缺失时 panic/warn);
> ④ **不做路由→权限映射自动生成**(职责分离:handler 级用宏注入检查,路由级用 TOML 中间件)。

---

## 一、概述

当前项目已实现 RBAC + 中间件管线(`mw_auth`→`mw_permission`),但权限检查能力存在缺口:

1. **无编译期注册**:新增受保护路由需手动在 TOML 添加映射,易遗漏,无启动校验。
2. **无过程宏注解**:handler 函数体不感知权限/角色,无法在函数级精确声明所需权限。
3. **无统一检查 API**:AuthContext 仅有 `has_permission()`/`has_role()` 查询方法,无 `require_*` 检查方法。
4. **无角色注解**:只有权限检查,缺少类似 Spring Security `hasRole()` 的角色检查能力。
5. **无启动校验**:无法发现"代码声明权限与 DB 不一致"。

本方案新增以下能力(对标 PERMISSION\_DESIGN.md §3、§4 + Spring Security 注解体系):

| 能力                                    | 对应设计章节   | 说明                      |
| ------------------------------------- | -------- | ----------------------- |
| `RegisteredPermission` + inventory 收集 | §3.1     | 编译期全局收集权限定义             |
| 权限注解宏(`#[has_permission]` 等)           | §3.2     | Spring Security `hasAuthority` 等价 |
| 角色注解宏(`#[has_role]` 等)             | §3.2     | Spring Security `hasRole` 等价     |
| `#[permit_all]` 公开标记                    | §3.2     | 标记无需认证的路由               |
| `register_crud_permissions!` 宏        | §3.2     | 一键注册 CRUD 四权限            |
| `RegisteredRouteHandler` + 漏写告警       | §3.3     | 防止漏写权限注解(辅助)            |
| `require_*` 统一检查 API(权限+角色)         | §4.3     | AuthContext 级统一检查(短路规则) |
| **启动一致性校验(不写 DB)**                  | §6(简化)  | 代码声明权限 vs DB 存在性比对,缺失时告警 |

> **范围声明**:本方案仅覆盖**功能权限**(操作级)和**角色检查**。
> 数据权限(DataScope)不在本方案范围内,后续单独设计。
> 插件动态权限注册(WASM 运行时)为未来扩展项,本方案仅预留 `PermissionRegistry` 运行时 API 接口。

### Spring Security 注解对照表

宏命名采用 Spring Security 风格的 `has_*` 前缀,术语保留项目的 `permission`
(对齐 DB 表 `cmx_permission` 与 trait `PermissionChecker`)。

| Spring Security 表达式 | 本方案宏 | 语义 |
|---|---|---|
| `hasAuthority('user:read')` | `#[has_permission(...)]` | 必须拥有指定权限(含元数据注册) |
| `hasAnyAuthority('a', 'b')` | `#[has_any_permission("a", "b")]` | 拥有任一权限 |
| (无,用 `and` 连接) | `#[has_permissions("a", "b")]` | 必须拥有所有权限 |
| `hasRole('ADMIN')` | `#[has_role("admin")]` | 必须拥有指定角色 |
| `hasAnyRole('ADMIN', 'MANAGER')` | `#[has_any_role("admin", "manager")]` | 拥有任一角色 |
| (无,用 `and` 连接) | `#[has_roles("admin", "manager")]` | 必须拥有所有角色 |
| `permitAll()` | `#[permit_all]` | 公开访问 |

> 命名约定:
> - `has_permission`(单数)— 对应 `hasAuthority`,**唯一**带元数据注册的宏(key/group/display/description)
> - `has_permissions`(复数)— 对应多权限 AND 语义(Spring Security 用 `and` 连接多个 hasAuthority)
> - `has_any_permission`— 对应 `hasAnyAuthority`(OR 语义)
> - `has_role`/`has_roles`/`has_any_role`— 对应 `hasRole`/`hasAnyRole`
> - `permit_all`— 对应 `permitAll`

### 3.1 新建 cmx-macros proc-macro crate

**路径**: `crates/libs/cmx-macros/`

**依赖约束**(评审 v2-4.5):proc-macro crate 只能用 host target,**不依赖任何业务 crate**
(cmx-core/cmx-api 等)。仅依赖 syn/quote/proc-macro2(workspace 已有)。
宏生成的 `inventory::submit!` 代码在**调用方 crate**(如 cmx-api)中展开,
因此宏生成代码中的类型路径需用**绝对路径** `::inventory::submit!`。

```toml
[dependencies]

# AST 解析 - 代码生成
quote = { workspace = true }
# AST 解析 - 底层支持
proc-macro2 = { workspace = true }
```

**workspace Cargo.toml** 新增:


#### 3.1.4 CRUD 权限批量注册声明式宏

放在 `cmx-core` 中(非 proc-macro),注册 **4 个权限**(8 handler → 4 权限码):

```
create / create_many  → {resource}:create
get / list / page     → {resource}:read
update / update_many  → {resource}:update
delete                → {resource}:delete
```

```rust
#[macro_export]
macro_rules! register_crud_permissions {
    ($resource:expr, $display:expr, $group:expr, $desc:expr) => {
        ::inventory::submit! {
            $crate::model::iam::registry::RegisteredPermission {
                key: concat!($resource, ":create"),
                group: $group, display: concat!($display, "创建"),
                description: $desc, source: module_path!(),
            }
        }
        ::inventory::submit! {
            $crate::model::iam::registry::RegisteredPermission {
                key: concat!($resource, ":read"),
                group: $group, display: concat!($display, "查询"),
                description: $desc, source: module_path!(),
            }
        }
        // :update / :delete 同理(共 4 个权限码)
    };
}
```

> 使用 `::inventory` 绝对路径(评审 v2-P2-15)。

### 3.2 cmx-core 注册表结构与 inventory 收集

```rust
//! 权限注册表 - 编译期 inventory 收集
//!
//! 通过 inventory crate 在编译期将所有权限定义和路由处理器登记到全局集合,
//! 启动期用于:① 漏写告警 ② DB 一致性校验 ③ 权限元数据查询。

/// 编译期注册的权限定义
pub struct RegisteredPermission {
    pub key: &'static str,
    pub group: &'static str,
    pub display: &'static str,
    pub description: &'static str,
    pub source: &'static str,
}
inventory::collect!(RegisteredPermission);

/// 编译期注册的路由处理器登记(漏写告警用)
///
/// 注:不做路由→权限自动映射(职责分离),
/// 此结构仅用于统计已注解 handler 数量,与路由总数粗略比对。
pub struct RegisteredRouteHandler {
    pub handler_name: &'static str,
    pub is_public: bool,
    pub source: &'static str,
}
inventory::collect!(RegisteredRouteHandler);

/// 获取所有已注册权限
pub fn all_registered_permissions() -> Vec<&'static RegisteredPermission> {
    inventory::iter::<RegisteredPermission>().collect()
}

/// 获取所有已注册路由处理器
pub fn all_registered_handlers() -> Vec<&'static RegisteredRouteHandler> {
    inventory::iter::<RegisteredRouteHandler>().collect()
}
```

### 3.3 AuthContext / SVRContext 增加统一检查 API(权限 + 角色)

对标 PERMISSION\_DESIGN.md §4.3 的三种检查方式 + Spring Security 的 hasRole/hasAnyRole。

**统一短路规则**(所有检查方法共用):
1. `system:all` 超级权限 → 放行
2. `admin` 角色 → 放行

#### 3.3.1 PermissionDeniedError 定义

**新增文件**: `crates/libs/cmx-core/src/model/iam/error.rs`(评审 v3-P1-5 明确定义位置)

```rust
//! 权限/角色检查错误类型

use thiserror::Error;

/// 角色需求语义(AND/OR)
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum RoleRequirement {
    /// 必须拥有所有角色(AND)
    All,
    /// 拥有任一角色即可(OR)
    Any,
}

impl std::fmt::Display for RoleRequirement {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        match self {
            Self::All => write!(f, "全部"),
            Self::Any => write!(f, "任一"),
        }
    }
}

/// 访问拒绝错误(权限检查 + 角色检查统一错误类型)
#[derive(Debug, Clone, Error)]
pub enum PermissionDeniedError {
    /// 未认证(auth_context 缺失)
    #[error("未认证:缺少认证上下文")]
    Unauthenticated,

    /// 权限不足
    #[error("用户 {user_id} 缺少权限: {permission}")]
    Permission {
        user_id: String,
        permission: String,
    },

    /// 角色不足(单角色)
    #[error("用户 {user_id} 缺少角色: {role}")]
    Role {
        user_id: String,
        role: String,
    },

    /// 角色不足(多角色,AND/OR 语义)
    #[error("用户 {user_id} 缺少角色(需{requirement}): {roles}")]
    Roles {
        user_id: String,
        requirement: RoleRequirement,
        roles: String,           // 缺失的角色列表
    },
}

impl PermissionDeniedError {
    /// 是否为未认证错误
    pub fn is_unauthenticated(&self) -> bool {
        matches!(self, Self::Unauthenticated)
    }
}
```

> `RoleRequirement` 枚举替代字符串魔法值 `"all"`/`"any"`(评审 v4-P1-4),提供编译期类型安全。

> 定义在 `cmx-core/src/model/iam/error.rs`,通过 `cmx-core/src/model/iam/mod.rs` 导出,
> cmx-core 根 `lib.rs` re-export 为 `cmx_core::PermissionDeniedError`。

#### 3.3.2 AuthContext 检查方法(6 个)

**修改文件**: `crates/libs/cmx-core/src/model/service/context.rs`

**权限检查(3 个)**:

```rust
impl AuthContext {
    /// 统一短路规则(私有辅助方法)
    fn is_short_circuited(&self) -> bool {
        self.has_permission("system:all") || self.has_role("admin")
    }

    /// 必须拥有指定权限
    /// Spring Security: hasAuthority(key)
    pub fn require_permission(&self, key: &str) -> Result<(), PermissionDeniedError> {
        if self.is_short_circuited() { return Ok(()); }
        if self.has_permission(key) { Ok(()) }
        else { Err(PermissionDeniedError::Permission {
            user_id: self.user_id.clone(), permission: key.to_string(),
        })}
    }

    /// 必须拥有所有指定权限(AND 语义)
    /// 一次性收集全部缺失权限后返回(评审 v4-P1-5)
    pub fn require_all_permissions(&self, keys: &[&str]) -> Result<(), PermissionDeniedError> {
        if self.is_short_circuited() { return Ok(()); }
        let missing: Vec<&str> = keys.iter()
            .filter(|k| !self.has_permission(k))
            .copied()
            .collect();
        if missing.is_empty() { Ok(()) }
        else { Err(PermissionDeniedError::Permission {
            user_id: self.user_id.clone(),
            permission: missing.join(", "),
        })}
    }

    /// 拥有任一权限即可(OR 语义)
    pub fn require_any_permission(&self, keys: &[&str]) -> Result<(), PermissionDeniedError> {
        if self.is_short_circuited() { return Ok(()); }
        if keys.iter().any(|k| self.has_permission(k)) { Ok(()) }
        else { Err(PermissionDeniedError::Permission {
            user_id: self.user_id.clone(),
            permission: keys.join("|"),
        })}
    }
```

```rust
    /// 一次性收集全部缺失角色后返回(评审 v4-P1-5)
    pub fn require_all_roles(&self, roles: &[&str]) -> Result<(), PermissionDeniedError> {
        if self.is_short_circuited() { return Ok(()); }
        let missing: Vec<&str> = roles.iter()
            .filter(|r| !self.has_role(r))
            .copied()
            .collect();
        if missing.is_empty() { Ok(()) }
        else { Err(PermissionDeniedError::Roles {
            user_id: self.user_id.clone(),
            requirement: RoleRequirement::All,
            roles: missing.join(", "),
        })}
    }

    /// 拥有任一角色即可(OR 语义)
    /// Spring Security: hasAnyRole(roles...)
    pub fn require_any_role(&self, roles: &[&str]) -> Result<(), PermissionDeniedError> {
        if self.is_short_circuited() { return Ok(()); }
        if roles.iter().any(|r| self.has_role(r)) { Ok(()) }
        else { Err(PermissionDeniedError::Roles {
            user_id: self.user_id.clone(),
            requirement: RoleRequirement::Any,
            roles: roles.join("|"),
        })}
    }
}
```

### 3.4 权限检查职责分离(不做路由自动映射)

**评审 v3-P0-1 决策:方案 C(务实) — 删除路由→权限映射自动生成**

经评估,编译期无法可靠地将 `handler_name` 关联到 `route_path`(路径在运行时 axum 注册时确定)。
为避免"自动生成形同虚设"的问题,采用**职责分离**:

| 层级 | 机制 | 数据源 | 配置方式 |
|---|---|---|---|
| **handler 级(精确)** | 宏注入的 `require_permission()` / `require_role()` | AuthContext 内存快照 | `#[has_permission]` / `#[has_role]` 等注解 |
| **路由级(安全网)** | `mw_permission` 中间件(最长前缀匹配) | AuthContext 内存快照 | TOML `[iam_permissions]` |

**两层职责清晰分离**:
- handler 级检查:开发者通过注解精确声明每个 handler 所需权限/角色
- 路由级中间件:运维通过 TOML 配置路由前缀→权限码映射,作为兜底安全网
- 不做"自动生成"(避免编译期 route_path 不可得的逻辑断裂)

> 现有 `load_permission_map()`(从 TOML 加载)**保持不变**,不集成 inventory 自动生成。

#### 三种权限配置模式

为支持"部分接口需要权限、部分不需要"的常见场景,宏支持三种参数模式,

**模式二:无权限参数(保持现状兼容,全部不鉴权)**

**模式三:精细化配置(部分鉴权、部分不鉴权)★ 关键**

```rust
declare_crud_handlers!(
    module_crud, Module, ModuleBmc,
    ModuleForCreate, ModuleForUpdate, ModuleFilter,
    "Module", "/module",
    perms(
        create = "module",   // create/create_many → require_permission("module:create")
        read = "",           // get/list/page → 不鉴权(任何人可查)
        update = "module",   // update/update_many → require_permission("module:update")
        delete = "module",   // delete → require_permission("module:delete")
    )
);
```

> `perms(...)` 块中:
> - 值为资源名(如 `"module"`)→ 该类操作注入 `require_permission("{资源}:{操作}")`
> - 值为空字符串 `""` → 该类操作不鉴权

#### 宏实现:多条 arms + 内部代理宏

```rust
#[macro_export]
macro_rules! declare_crud_handlers {
    // 模式三:精细化配置(优先匹配,最具体)
    (
        $module_name:ident, $entity:ty, $bmc:ty,
        $entity_create:ty, $entity_update:ty, $filter:ty,
        $tag:expr, $prefix:expr,
        perms(
            create = $p_create:expr,
            read = $p_read:expr,
            update = $p_update:expr,
            delete = $p_delete:expr $(,)?
        )
    ) => {
        $crate::__declare_crud_handlers_inner!(
            $module_name, $entity, $bmc,
            $entity_create, $entity_update, $filter,
            $tag, $prefix,
            $p_create, $p_read, $p_update, $p_delete
        )
    };

    // 模式一:统一资源名(全部鉴权,4 类操作复用同一资源名)
    (
        $module_name:ident, $entity:ty, $bmc:ty,
        $entity_create:ty, $entity_update:ty, $filter:ty,
        $tag:expr, $prefix:expr,
        $perm_resource:expr  // 单个字符串
    ) => {
        $crate::__declare_crud_handlers_inner!(
            $module_name, $entity, $bmc,
            $entity_create, $entity_update, $filter,
            $tag, $prefix,
            $perm_resource, $perm_resource, $perm_resource, $perm_resource
        )
    };

    // 模式二:无权限参数(向后兼容,全部不鉴权)
    (
        $module_name:ident, $entity:ty, $bmc:ty,
        $entity_create:ty, $entity_update:ty, $filter:ty,

        $crate::__declare_crud_handlers_inner!(
            $module_name, $entity, $bmc,

        $tag:expr, $prefix:expr,
        $p_create:expr, $p_read:expr, $p_update:expr, $p_delete:expr
    ) => {
        pub mod $module_name {
            // ... 原 use 语句 ...

            pub async fn create(/* 原参数 */) -> Result<...> {
                if !$p_create.is_empty() {
                    svr_ctx.require_permission(concat!($p_create, ":create"))
                        .map_err($crate::Error::from)?;
                }
                $crate::rest::handler::create::<$bmc, $entity_create>(/* ... */).await
            }
            // create_many 同样用 $p_create

            pub async fn get(/* ... */) -> Result<...> {
                if !$p_read.is_empty() {
                    svr_ctx.require_permission(concat!($p_read, ":read"))
                        .map_err($crate::Error::from)?;
                }
                $crate::rest::handler::get_by_id::<$bmc>(/* ... */).await
            }
            // list / page 同样用 $p_read

            pub async fn update(/* ... */) -> Result<...> {
                if !$p_update.is_empty() {
                    svr_ctx.require_permission(concat!($p_update, ":update"))
                        .map_err($crate::Error::from)?;
                }
                $crate::rest::handler::update::<$bmc, $entity_update>(/* ... */).await
            }
            // update_many 同样用 $p_update

            pub async fn delete(/* ... */) -> Result<...> {
                if !$p_delete.is_empty() {
                    svr_ctx.require_permission(concat!($p_delete, ":delete"))
```

#### 权限映射(8 handler → 4 权限码)

| Handler | 权限码 | 对应 perms 配置项 |
|---|---|---|
| `create` / `create_many` | `{resource}:create` | `create = ...` |
| `get` / `list` / `page` | `{resource}:read` | `read = ...` |
| `update` / `update_many` | `{resource}:update` | `update = ...` |
| `delete` | `{resource}:delete` | `delete = ...` |

#### 关键设计点

1. **向后兼容**:无第 9 参数走模式二(全部不鉴权),现有代码不改也能编译,迁移渐进。
2. **`concat!` 编译期拼接**:`"module" + ":create"` = `"module:create"`,零运行时开销。
3. **空字符串判断**:运行时 `is_empty()` 布尔判断,开销极低。
4. **读操作共用资源名**:`get`/`list`/`page` 都用 `$p_read`,符合 RBAC 惯例。
5. **arms 匹配顺序**:`macro_rules!` 按声明顺序匹配,最具体的 `perms(...)` 放最前,避免被单字符串模式吞掉。

```rust
//! 代码声明权限 vs DB 存在性一致性校验
//!
//! 启动时比对 inventory 中声明的权限码 与 DB cmx_permission 表中的权限记录。
//! 缺失时按配置 panic/warn,提示开发者手动创建 DB 记录。
//! **不自动写 DB**。

use std::collections::HashSet;
use cmx_core::model::iam::registry::all_registered_permissions;
use cmx_iam::permission::PermissionFilter;
use cmx_traits::error::TraitError;

pub struct ConsistencyReport {
    /// 代码有、DB 无(会导致权限检查失效)
    pub missing_in_db: Vec<String>,
    /// DB 有、代码无(冗余,可清理)
    pub orphan_in_db: Vec<String>,
}

/// SQL 字符串转义(单引号替换为两个单引号)
///
/// 避免 display/description 含单引号时生成的 DDL 语法错误。
/// 这些值来自代码编译期常量(&'static str),安全性高于用户输入,
/// 但企业级框架不应示范不安全的 SQL 拼接模式(评审 v4-P0-2)。
fn escape_sql(s: &str) -> String {
    s.replace('\'', "''")
}

impl ConsistencyReport {
    /// 生成待执行的 INSERT SQL(评审 v3-P2-7 — 缓解"不写 DB"易用性问题)
    ///
    /// 将缺失的权限生成 DDL,开发者可复制执行(由人工 review 后执行)
    /// 字符串值经 escape_sql 转义,防止单引号破坏 SQL 语法(评审 v4-P0-2)
    pub fn to_insert_sql(&self) -> String {
        let mut sql = String::new();
        for code in &self.missing_in_db {
            // 从 inventory 查找元数据
            if let Some(p) = all_registered_permissions().iter().find(|p| p.key == code) {
                sql.push_str(&format!(
                    "INSERT INTO cmx_permission (code, name, description, status, archived) \
                     VALUES ('{}', '{}', '{}', 1, 0);\n",
                    escape_sql(p.key), escape_sql(p.display), escape_sql(p.description)
                ));
            }
        }
        sql
    }
}

/// 执行一致性校验
///
/// 使用 PermissionServiceImpl 获取 DB 权限列表(评审 v3-P0-2)
///
/// 注意:list_permissions 返回 Result<Vec<Permission>, TraitError>,
/// 需处理错误并返回 Result<ConsistencyReport, TraitError>(评审 v4-P0-3)
pub async fn ensure_db_permission_consistency(
    permission_service: &dyn cmx_iam::service_traits::PermissionService,
    mm: &cmx_database::DatabaseManager,
) -> Result<ConsistencyReport, TraitError> {
    // 1. 收集 inventory 声明的权限码集合
    let code_perms: HashSet<String> = all_registered_permissions()
        .iter().map(|p| p.key.to_string()).collect();

    // 2. 查询 DB 已有权限码
    //
    //    注意:PermissionServiceImpl::list_permissions 会默认追加 archived = 0 过滤,
    //    但一致性校验需要比对**所有**权限(包括已归档的),否则已归档权限会被误报为 orphan。
    //    因此这里直接执行 SQL 查询全部权限码,绕过 archived 过滤(评审 v4-P0-3)。
    let db_perms_raw = list_all_permission_codes(mm).await?;
    let db_perms: HashSet<String> = db_perms_raw.into_iter().collect();

    // 3. 比对
    let missing_in_db: Vec<_> = code_perms.difference(&db_perms).cloned().collect();
    let orphan_in_db: Vec<_> = db_perms.difference(&code_perms).cloned().collect();

    Ok(ConsistencyReport { missing_in_db, orphan_in_db })
}
```

## 四、关于"双保险"的说明(评审 v2-P1-5)

宏注入的 `require_*()`(handler 级)与现有 `mw_permission` 中间件(路由级)并存的说明:

**两条路径使用同一数据源** — 均基于 `AuthContext.permissions` 内存快照。

**双保险针对的是"漏配"而非"数据过期"**:
- handler 级检查防止"路由前缀匹配遗漏"
- 路由级中间件防止"handler 漏写权限检查代码"

**数据过期问题**由现有机制保障:权限变更时缓存失效 + token 刷新。

## 八、假设与决策

### 决策

1. **并存增强**:handler 级用宏注入检查(权限/角色注解),路由级用 TOML 中间件,职责分离。
2. **新建 cmx-macros crate**:proc-macro crate,仅依赖 syn/quote/proc-macro2,不依赖业务 crate。
3. **不做路由自动映射**(评审 v3-P0-1 方案 C):编译期无法可靠获取 route_path,删除"自动生成"能力,职责清晰分离。
4. **根用户短路**:`system:all` 权限或 `admin` 角色绕过所有权限/角色检查。
5. **CRUD 权限**:8 handler → 4 权限码映射(create/read/update/delete)。
6. **不自动写 DB**:启动时仅校验一致性,缺失时 warn 并输出 DDL,开发者手动执行。
7. **错误复用**:复用现有 `Forbidden`/`Unauthorized`,不新增错误变体,仅新增 `From` 转换。
8. **Spring Security 风格**:提供 6 个权限/角色注解宏 + 1 个公开标记,覆盖 hasAuthority/hasAnyAuthority/hasRole/hasAnyRole 语义。
9. **数据权限不在范围**:本方案仅覆盖功能权限(操作级)+ 角色检查,DataScope 后续单独设计。

### 假设

1. `inventory` 0.3 版本与 edition 2024 兼容(步骤 1 先验证,备选 `linkme` crate)。
2. 现有 4 处 `declare_crud_handlers!` 调用可逐一补充权限资源参数。
3. `PermissionServiceImpl::list_permissions()` 可获取全量权限码用于一致性比对。
4. 开发者新增 `#[has_permission]` 后会手动在 DB 创建对应权限记录(启动校验提示 + DDL 输出)。

### 风险

* **inventory 版本兼容**:edition 2024 较新,inventory 0.3 需实测。备选:改用 `linkme` crate。

* **宏注入参数定位**:通过**类型路径匹配** `CmxSvrContext`(非参数名)。找不到时编译期 error。

* **DB 一致性维护**:不自动写 DB,开发者需手动执行生成的 DDL。启动校验提示遗漏 + 输出 DDL 缓解。

* **跨服务权限检查**:`auth_context` 的 `#[serde(skip)]` 导致跨进程传递时权限丢失,宏注入的检查仅在 HTTP handler 同进程内有效。

* **OpenAPI 集成**(评审 v3-P2-6):首版不集成 Swagger security 注解,作为未来扩展项。

* **i18n**:`display`/`description` 为 `&'static str`,暂不支持多语言。
